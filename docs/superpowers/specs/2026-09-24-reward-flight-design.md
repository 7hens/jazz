## 1. 问题:四句产品原话逐句对账

| 产品说 | 实况(取证见括注) | 性质 |
|---|---|---|
| **没有声音** | 4 个撒花档**全静音**:`CONFIGS` 只挥 confetti,`celebrate` 无音频面(`celebrate.ts`)。`AudioCue` 里两个为此存在的档 —— `'streak'`(连击三音上行)与 `'correct'` —— **生产零调用点**(`celebrate.ts:9` + `dev-reference.md:108` 两处自陈登记) | **接线漏项**,非设计难 |

### 1.1 附带发现(盘点中挖出,须处置)

**① 星级 1–3 全仓零处显示。** `starsFor(missRef.current)` 在 `PinyinBlocksGame.tsx:151` 算完即交给 `onSolved`,此后**只进数据库**:`PinyinBlocksGame` 的渲染里没有它;`UnitMap` 那排 `★` 走 `cleared()`(= `>=1`)两态,表**通关与否**,不表 1/2/3;`ParentPanel.tsx` 全文不出现 `stars`。⇒ **孩子拿 3 星与拿 1 星看到的是同一屏**,大人也看不到。→ 想法池「关卡内星级即时反馈」行的**前半**,本设计收下(§3.2);该行的「『继续』按钮」半**不收**(§9)。

**② `audio.play` 用 `else` 兜底 —— 未知 cue 静默播成 `tap`。** `audio.ts:94-112` 是 `if / else if` 链,末支是无条件 `else`(440Hz 三角波,= `'tap'` 的音)。⇒ 往 `AudioCue` 加一个值而忘了实现分支:**编译通过、`tsc` 绿、`lint` 绿、运行静默播成「嗒」**。这与 2026-09-23 spec §1.1② 记的「四档撒花声明了没人调」是**同一族静默失效**。本设计新增两个 cue,故**先堵它**(§5.1④)。

**③ 徽章未得态的现行判据将被本设计撞上。** `UnitMap.test.tsx:196` 断言未得格 `textContent === ''`,其注释自陈用途:「只断 `data-*` 的话,把 emoji 改成无条件渲染(= 两态长得一样)照样全绿,而那正是 brief 的原始形态。」⇒ §3.4 要让未得态**也画那枚 emoji**,**正撞这条守卫**。**不能只把断言改松** —— 那会连同它守的那件事(两态可判)一起丢掉。替代判据见 §3.4 与 §5.1⑤,且**必须具名它比原判据弱**。

## 2. 本设计要立的那条不变量

> **§2 不变量**:孩子面上**每一笔奖励,当场看得见它去了哪** —— 要么看见它飞进一个**常驻的账本**,要么看见它落在一个**早就空在那儿、形状与自己相同**的位置上。
>
> **射程**:只管**奖励层**(星 / 星尘 / 连击 / 成就 / 幸运 / 撒花)。**不**覆盖关卡内积木交互、地图单元格本身、家长面板。
>
> **与 2026-09-23 不变量的关系**:那条是「不许出现**要读懂才明白**的文字」;本条是「不许出现**看不出归属**的图标」。**两条同时成立、互不替代** —— 本设计一个字不加。

## 3. 设计

### 3.1 声音:一档一音,且**绑定下沉**(不再靠「记得接线」)

**映射表**(新增到 `shared/`,因为 `LevelEntry` 要用;放 `features/combo` 会是跨 feature 编译期互引,`architecture.test.ts` 守的边界):

| 档 | 触发 | cue |
|---|---|---|
| `combo5` | 5 连 | `streak` |
| `combo10` | 10 连 | `streak` |
| `word` | 一关拼成、且无奖励弹层接手 | `correct` |
| `achievement` | 成就弹层弹出 | `achievement`(**新增 cue**) |
| `lucky` | 幸运弹层弹出 | `lucky`(**新增 cue**) |

- **`combo5` / `combo10` 共用 `streak`**:同一件事的两个量级,靠撒花规模(30 vs 150 粒)与圆点区分。不新增第三个连击 cue —— 理由同 2026-09-23 spec §3.3「不设第三连击档」。
- **不新增的**:`victory`(拼对那一瞬)、`tap`(落块)、`wrong`(放错)**零改**。
- 新增的两个 cue 与现有同族(正弦多音 / 单音),**不引依赖**。
- `'correct'` 原本就是「拼对」的意思,接到 `word` 档不是凑用。

**`Ruling:` 音效绑定下沉进 `celebrate` 实现,不在各调用点各自接。**

今天 `celebrate.play(tier)` 与 `audio.play(cue)` 分处两地 —— 这正是「四档全静音」的成因:没人接就没人响,而没有任何东西会发现。改法:`createCelebrateService(playConfetti, playCue)`(第二参可空,同第一参的既有形态),**`play(level)` 一个调用 = 撒花 + 声音**,从结构上不可能只做一半。

- `CelebrateService.play(level)` **契约零改**;改的只是实现签名(测试跟随)。
- 组装点 `bootstrap.ts:52-53`(`AudioService` 与 `CelebrateService` 注册相邻):把 audio 实例的 `play` 传进 `createCelebrateService`。传的是**函数**而非服务,保持 `celebrate.ts` 不 import 任何服务。
- **副作用(好的)**:`AchievementPopup` 已有的 `celebrate` 钩子(`App.tsx:95` 传的是 `celebrateService.play`)**自动获得声音**,弹层组件**零改**;`LuckyBonus` 加同一个钩子(§3.6)后同样自动获得。

**代价若判错**:若产品要「撒花与声音能分开开关」,需把 `playCue` 从构造参数改成运行时读取 —— 仍是 `celebrate.ts` 内部的事,不牵动调用点。

### 3.2 星级揭示(关卡页,新增)

**位置**:`PinyinRound` 的答案行(`PinyinBlocksGame.tsx:488-501`)那一块**下方**独立一行(不放右端 —— 答案行已有拼音 + 汉字,窄屏会挤)。

**形态**:三颗星,**拿到几颗亮几颗**。复用既有 `.pstar` / `.pstar--on`(地图单元格用的是同一对 class —— 一处概念一个形态)。逐颗 0.15s 依次亮起;`MotionConfig reducedMotion="user"`(`App.tsx:91`)下三颗同时亮。

**必须是填色,不能只靠动画** —— 同 2026-09-23 spec §3.3 的理由:纯动画表达对减动效用户等于不存在。

**时机**:`status === 'solved'` 期间渲染。`succeed()` 的窗口是 1.6s(焊接关 2.1s,`:157`),0.45s 弹完,余量充足。

**数据**:`starsFor(missRef.current)` 今天只活在 `succeed()` 的局部(`:151`),须提升为 state 才能进 render —— 这是本节的**唯一**实现改动点。

**加 `data-level-stars` 钩子**(今天无 `data-` 钩子,守卫无从下手)。

### 3.3 星尘归属(关卡页新增常驻计数器 + 一笔入账的可见动作)

**(a) 关卡页新增常驻星尘计数器** —— `LevelEntry` 顶部行左端(`←` 右侧),形如 `⭐ N`,加 `data-stardust` 锚点。

这是关卡页新增的**唯一常驻元素**。**为什么必须有**:没有它,`+N ⭐` 无处可飞,§2 的「飞进一个常驻的账本」不成立。

**(b) 一笔星尘 = 一次可见的入账**

- **旧值**:`handleSolved` 在 `await settleLevel(...)` **之前**记下当时的 `progressSnap.data.totalStars`(`LevelEntry` 已 `useServiceSnapshot(progress)`,无需新订阅)。这笔账的起点。
- **飞行**:结算返回后,从**视口中心**飞出一颗星,落在计数器上;落定 → 计数器脉冲 + 数字**从旧值滚到新值**(不是瞬跳)。
- **时长**:0.6s;若这笔里含**首次**成就则 1.8s(§3.5)。
- **无弹层时**:连击加成与 `word` 档那一笔**没有 `+N` 可飞**(屏幕上没有那个数字),此时**只滚数字**。即:计数器滚动**不依赖弹层是否存在**。
- **减动效**:跳过位移,只保留数字变化(滚或瞬变)。

**(c) 地图页计数器不滚动** —— 地图每次挂载拿到的就是最新值,没有「旧值」可比。归属动作发生在**关卡页**那一刻。→ §9 登记。

**技术约束(本设计最硬的一条)**:jsdom **无布局引擎**,`getBoundingClientRect()` 恒为 0。⇒ 飞行层必须:**坐标不可用就跳过位移、直接落定**。⇒ **守卫只断落定后的可判态**(数字变了 / 有落定标记),**不断位移**;位移归人眼走查(§6)。

**`Ruling:` 飞行层落在 `LevelEntry`,起点 = 视口中心,不读弹层 DOM。**

理由:弹层是 `App.tsx` 渲染的 `fixed inset-0` 覆盖层,恒在视口中心(`AchievementPopup.tsx:25` / `LuckyBonus.tsx:13`),故起点可直接取视口中心;**零跨 feature 耦合**(不需要从 features/achievements 把 rect 传出来,也不需要新增跨 feature 服务)。`LevelEntry` 同时握有 `result.starDust`(`settle.ts` 的 `LevelSettlement` 字段)与计数器 —— 起终点都在它手里。

**代价若判错**:若将来弹层不再居中,飞行起点会与弹层的 `+N ⭐` 错位 —— 那时需要一个共享锚点,属加法。

### 3.4 徽章剪影(地图页:未得态由「空圈」改「淡影」)

**未得态**:由「**不画图标**」改为「**画那枚 emoji 的淡影**」—— 描边保持 `border-ink-2` **实色**不变(2026-09-23 spec §3.5 的算术结论继续成立:整块压 opacity 会把描边合进天空,那是另一件事),**只给 emoji 元素压透明度**,取值 `opacity-45` —— 与 `ParentPanel.tsx:90` 的未得态**同一取值**(一处概念一个数)。

**为什么值得**:空圈不承诺任何身份;剪影承诺「这里将来是它」。剪影与成就弹层上那枚 emoji **同形** —— 这正是 §2 不变量里「形状与自己相同的位置」那条的实现。

**判据替换(具名削弱)**:`UnitMap.test.tsx:196` 的「未得格 `textContent` 为空」**形态**断言被替换为:

> 两态**都**渲染**同一枚** emoji(身份一致),且未得那格带 `data-badge-ghost`(态差可判)。

**这条比原判据弱**,必须写进测试注释与本节:原判据断**形态差异**,新判据只断**标记差异 + 身份一致**。「幽灵态在天空渐变上是否看得见」是**像素问题**,jsdom 判不了 ⇒ 人眼走查(§6 的 `W-V4` 改期望)。取值 `opacity-45` **同样未经像素裁定**(与 `ParentPanel` 的取值同待遇,`docs/PLAN.md` 想法池已有对应登记行)。

**`UnitMap` 的 props 零改** —— 剪影是内部形态,不新增输入。

### 3.5 首次慢放(只对成就)

- **「首次」的判据(无需新状态)**:`result.achievements[i].id` **不在** `settleLevel` **之前**的 `settingsSnap.data.earnedAchievements` 里。`LevelEntry` 已持有 `settingsSnap`(`:48`)。`settle.ts` 的写入路径本就是 union 去重追加,故「不在」⟺「这次刚拿到」。
- **表现**:那笔星尘的飞行时长 1.8s(否则 0.6s),落定后的脉冲与光环停留更久。
- **弹层的 2600ms 停留时间不改** —— 1.8s 飞行 + 0.8s 看落格,窗口够。不为了慢放拖慢每一关的节奏。
- 幸运 / `word` 档**不适用**(它们每关都可能出现,不是「第一次见到」)。

### 3.6 幸运:补上自己的撒花档(收法①)

- `CelebrateLevel` 加 `'lucky'`(4 → 5);`CONFIGS` 加一档 `{ particleCount: 60, spread: 70 }` —— 夹在 `combo5`(30 / 50)与 `word`(100 / 80)之间:幸运是**白捡的**,规模不该压过关卡本身,但也不该与连击小档同量级。(这是**配置值**,不是关于世界的事实断言,故写死;会静默变假的是「计数」那类,不是这层。)
- `LuckyBonus` 加 `celebrate?: (level: CelebrateLevel) => void`(`AchievementPopup` 同形,`:11`);`App.tsx:97` 传 `celebrateService.play`(今天**没传**)。
- **`LevelEntry.handleSolved` 的守卫不变**:`result.achievements.length === 0 && result.luckyReward <= 0` 才放 `word`。今天这条让幸运分支「一记都不出」;加了自己的档之后,让掉 `word` 是对的(一次成功只撒一次花),而**这一关不再静音**。⇒ 最小改。
- 这关掉想法池「幸运奖励无自己的撒花档」行(其**收法①**)。

## 5. 守卫

### 5.1 可机器判(进 `npm test`)

**① 星级揭示**:`miss = 0` → 亮 3 颗;`miss >= 3` → 亮 1 颗。断**填色**(class),不断动画。`data-level-stars="N"` 给一个可判钩子。

**② 关卡页星尘计数器**:结算前 `data-stardust` 文本 = 旧值,结算后 = 新值。**断落定终态**,不断滚动中间态(jsdom 无布局)。

**③ 撒花 ↔ 音效完备**:映射表键集 === `CelebrateLevel` 的值集。**用穷举断言,不写字面量条数**(条数会变,且本仓已具名「写死的计数会静默变假」)。—— 这条是本轮病灶(4 档全静音)的**根治守卫**。

**④ `AudioCue` 实现完备(§1.1② 的堵法)**:把 `audio.ts` 的分派从 `if/else` 链改成 `Record<AudioCue, …>` 或带 `never` 断言的穷举 `switch`,**取消无条件 `else` 兜底**。TS 在编译期守一半;运行期再断言一次「分派键集 === `AudioCue` 值集」,守 `as` 绕过。

**⑤ 徽章两态**:两态**都**渲染同一枚 emoji;未得格带 `data-badge-ghost`、已得格不带。**测试注释里必须写明此判据弱于它所替换的那条**(§3.4)。

**⑥ 幸运档**:`LuckyBonus` 收到 `celebrate` 时调 `play('lucky')`。

### 5.2 只能人眼的(进 `docs/walkthrough.md`)

见 §6。**所有位移 / 时长 / 对比度 / 「看不看得出」一律归此**,`jsdom` 无 CSS 引擎、无布局、无指针序列。

### 5.3 反例测试(必做,写进 spec 以便实现期执行)

每条新断言都要能被一次**具名注入**弄红,并**逐字节还原**(`/tmp` 快照 → `cp` 回 → `md5sum -c`)。**不许 `git checkout -- <file>` / `git restore`** —— 本仓已有实现者据此回滚掉自己未提交改动的先例。

## 9. 不做

- **「丑」的配色 / 布局重做** —— 那是**方案 C**(地图岛链化 / 关卡背景随单元换色 / 结算舞台),L 级、基本无自动化守卫。本设计只回应「一排空圈」与「形状语言不统一」这两处可判的丑。**产品若要继续,得先指认具体是哪一块**(本仓禁截图,控制器看不见)
