# 拼音积木脚手架遍(简单部分每题先跑一遍「固定非目标槽 · 只挖目标那一类块」)— 设计

> **日期** 2026-10-12(同日依产品追加口径「只挖声调也加进来吧」并入第二型,§2.2b / 裁定 D)
> **状态** 待评审
> **PLAN 行** `docs/PLAN.md` 想法池 `P1`「拼音积木新题型:脚手架遍」
> **口径来源** 2026-10-12 产品口径:「我们需要新设计一些题型,要丰富可玩性。我希望在简单(入门)级别的题目中,固定一些字母,只空出目标字母组合。如 a,题目可以使用 ba4,将 b 一开始就固定,只空出韵母部分,让玩家选。」/ 追加:「只挖声调也加进来吧」
> **性质** 引入**两型新的题型**(脚手架遍「挖本单元新教的那类块」+ 声调型「只挖声调」),不引新的失败态、不改判分、不改已有三段结构。本行是**把一种机制接回来** —— 被删的错题池机制曾有过 `prefill` + `locked` 集合 + 三处门禁,见 §3.2。

---

## 1. 问题与动机

今天的简单部分,孩子面对的是**一张全空的拼装台**:声母槽、韵母槽、声调槽一个都不填。他要同时做三件事 —— 认图、想音节、分配每一类块到对应的槽。`buildBlocks` 给的干扰块又刻意做成**最小对立对**(`b`/`p`、`n`/`l`、`an`/`ang`),这是 2026-09-27 难度改造定的难度来源。

**问题**:入门层的孩子还没有「声母 / 韵母」这套**位置意识**。`PinyinBlocksGame` 的槽位是按音节结构横向摊开的,孩子得先知道「哪个凹槽是给 b 的、哪个是给 a 的」。这个意识没建立之前,`b` 和 `p` 的最小对立对他没有意义 —— 他不是选错了,是**根本不知道自己在选什么**。

于是入门层的真实瓶颈不是「难度太高」,而是**认知负荷太高**:一题里同时压着三层判断,而入门期只需要一层。

**本设计**:同一道题**跑两遍**。第一遍是**脚手架遍** —— 非目标类型的槽**已经填好并锁定**,孩子只从托盘里挑目标那一类块。判据从「这是哪个音节」收窄成「这一类里是哪个」,最小对立对这时才真正开始起作用(他终于知道自己在比什么)。第二遍是**全拼遍** —— 今天的样子,一件不差。

## 2. 设计

### 2.1 一道题两遍

```
简单部分的一道题
  ├─ 遍 1:脚手架遍   非目标槽预填锁定,只挖「本单元新教的那一类块」
  └─ 遍 2:全拼遍     = 今天的玩法,一字不差
```

**两遍共用同一张图、同一个音节。** 差别只在「哪些槽是空的」。

`QuestionRun` 的 `items` 从「一道题一项」变成「一道题两项」:

```ts
export type QuestionItem =
  | Readonly<{ kind: 'level'; levelIndex: number }>          // 全拼遍(今天这一支)
  | Readonly<{ kind: 'scaffold'; levelIndex: number }>       // 脚手架遍(新增)
  | Readonly<{ kind: 'practice'; levelIndex: number; question: PracticeQuestion }>
```

`LessonEntry` 的 `items` 由 `flatMap` 展开成 `[scaffold, level]` 两项。`PinyinBlocksGame` 多一个 `scaffold` 入参(与 `practice` 同构),差异全部收敛在这一个入参上 —— **不写第二套拼装台**。

### 2.2 挖哪一类:本单元新教的那一类块,声调除外

产品裁定:「挖本单元正在教的那一类块」,**声调是唯一的例外**(裁定 F,§2.2b)。

口径是一条**纯派生**规则,不写第二份数据 —— 哪个单元教什么,`taughtBlocks(unitIndex)` 已经知道(`levels.ts:394`):

> **`focusTypeOf(unitIndex)` = 本单元 `Unit.badge` 里、在本单元之前**尚未出现过**的那些块,取它们的第一个 `type`。**

```ts
/**
 * 本单元新教的那一类块(脚手架遍只挖这一类)。**无解时返 null** —— 见 §2.3。
 *
 * 口径 = badge ∩ (本单元之前没教过的块)。用 badge 而不是「单元里出现最多的类型」:
 * badge 是**本单元新教块**的唯一事实源(levels.ts:79 写明「显式写死,不靠反推」),
 * 而「哪个类型出现最多」会把「本单元顺带复习了 5 个 a」误判成「本单元教 a」。
 *
 * **取第一个而非全部**:一个单元理论上可能新教两类块(今天的 12 个单元里没有),
 * 挖两类 = 预填只剩声调块,脚手架就退化成「选声调」—— 那正是 §2.2b 要单独做的那一型,
 * 与其让它意外地退化成那样,不如显式裁定。
 */
export function focusTypeOf(unitIndex: number): BlockType | null
```

**实测结果(逐单元跑 `taughtBlocks` 差集 + `slotsFor` 逐题查槽,不是推算):**

### 2.2b 声调遍:唯一被单独裁定的一类(`focusType = 'tone'`)

**声调在 `focusTypeOf` 之外,单独一型。** 它不是某个单元的新教块 —— 它**每个单元都有、每道题都必答,而 182 道题里从没被单独考过一次**。

**今天声调是怎么考的**:它是全拼遍里的一个槽,和声母、韵母**同屏竞争**。孩子放错声母会 `noteMiss`,放错声调也 `noteMiss`,两者混在一个 `missCount` 里。**没有任何一个观测点能区分「他不认识 b」和「他听不出第四声」。**

**声调遍的盘面**:字母块**全部预填锁定**,只留声调槽空:

```
         [ ? ]        ← 唯一可操作
[ zh ] [ i ]           ← 预填锁定
```

**这一屏考的是一件事,而且只有一件事:这个字的调是几。** 这是 182 道题里的**真空白** —— 声调是拼音四大要素之一,今天却从来没有被单独测过。

**它同时解决了 u10–u12 的空档**:那 23 道题不挖「新教块」(§2.2),改挖声调。**声调在每道题上都恒存在**(`slotsFor` 无条件为每个音节产一个 tone 槽,`rules.ts:42`),所以这三个单元**恒有脚手架遍可跑** —— 覆盖率从 **68/91 变成 91/91**。

> **这不是给 u10–u12 降难度,是给它们补上和其他单元同一个空白。** 整体认读(`zhī chǐ shī rì`)的调恰恰是最需要单独辨的地方 —— 声母韵母已经看得见,唯独调还是「搭车必答」。

**实测(逐题跑 `slotsFor` + `toneBlocks`)**:

| | 数量 | 说明 |
|---|---|---|
| 简单部分 tone 槽总数 | **97** | 91 道题 × 每题 1 个调,u12 的 6 道双音节题各 2 个(97 = 91 + 6) |
| 单音节题的声调托盘 | **恒 4 块** | `toneBlocks` 让四种走势恒全出(`rules.ts:118`),干扰恒 3 |
| u12 双音节题(**两音节同调**) | **恒 5 块** | `u7-0` `xī guā` → `1 1 2 3 4`;`u7-3` `hú dié` → `1 2 2 3 4`;`u12-50` `dà shù` → `1 2 3 4 4`。同调 ⇒ 需要**两块**那个调(`rules.ts:125` 的 `need` 计数) |
| u12 双音节题(**两音节异调**) | **恒 4 块**(`1 2 3 4`) | `u7-1` `xióng māo`(2·1)/ `u7-2` `niú nǎi`(2·3)/ `u7-4` `huā duǒ`(1·3) |

> ⚠ **实施中修正(2026-10-12,Lane A 实测推翻本 spec 早先的写法)**:本节初稿把 `u12-50` 归进「异调 ⇒ 4 块」那侧,**错了** —— `dà shù` 两个音节**都是第四声**,`toneBlocks` 出 `1 2 3 4 4` = **5 块**。若照初稿给 4 块,第二个音节永远填不满(不变量 6 被破)。**判据是「两音节调值是否相同」,不是音节本身。**

**双音节题挖声调 = 两个空槽**。同调时这两块同值(一一声两块)必须**各自可区分地落位**,不能合并成一个槽 —— 否则盘面就不是「双音节词的调」而是「两个调里选一个」。`toneBlocks` 的 `need` 计数已经保证正解块数,`SCAFFOLD_TRAY_CAP` 对声调**不适用**(它给的是「干扰块数上限」,而声调的干扰块恒为 4 减正解块数)。

**「唯独声调没有易混对」这件事要在注释里写死**:`CONFUSABLE.tone = {}`(`blocks.ts` 里那张表 tone 恒空)。所以声调遍**没有最小对立干扰** —— 四个调是四个完全不同的形状,孩子靠**认形状**就能选对,不需要辨相似。

> **这意味着声调遍是 91 道里最容易的一道。** 已裁定接受:它的目的不是难度,是**把这个一直存在却从未被单独观测的技能拉到台面上**。孩子在这一遍里做对了,说明他的调没问题;做错了,`missCount` 里这一条第一次**能被归因到调**。

**`listen` 关的交互(已核对,无冲突)**:`Level.listen` 是「进题自动念一遍」(`PinyinBlocksGame.tsx:181`)。声调遍**继承这个标志** —— 该念的题照念。`u10`/`u11` 的 8 + 9 道题 `listen` 恒为 `false`(实测),即「看图猜调」,不自动念;**念出来等于把答案告诉孩子**(调就在声音里)。这条纪律**一个字不变**。

**`weld` 的交互(已核对,无冲突)**:u10/u11 的整体认读题 `weld: true`,焊缝画在**两块之间**(`PinyinBlocksGame.tsx:685`,`colIdx === 1`)。声调遍里两个字母块都是预填的,焊缝照样画在它们之间 —— 视觉不变,`welded` 的触发条件是 `status === 'solved'`,与哪些块是预填无关。

### 2.3 降级:三条规则,都是纯函数

```
有 focus 类型 且 该题有该类型的槽  → 跑脚手架遍(focus 类)+ 全拼遍(2 遍)
无 focus 类型(u10–u12)且 该题有 tone 槽 → 跑声调遍 + 全拼遍(2 遍)
否则                              → 只跑全拼遍(1 遍,今天的样子)
```

**tone 槽恒存在**,所以第二条只在「`focusTypeOf` 返 `null`」时触发,不会因为「题里没调槽」而落空 —— `slotsFor` 对每个音节**无条件**产一个 tone 槽(`rules.ts:42`)。

**「该题无该类槽」的兜底仍然必要**:u6 的 5 道简单题全有 nasal 槽(实测 5/5),但这个 5/5 是**今天的数据碰巧**。将来加一关 `u6-60`(比如某个纯 `an` 的词)就没有 nasal 槽,那时它必须自动退成单遍,而不是渲染出一个「预填了 final 却没槽可挖」的怪盘面。

**u10–u12 走第二条,不是降级。**

### 2.4 脚手架遍的盘面

以 `u2-0`(👨 爸 `bà`,`initial: b` + `final: a` + `tone: 4`)为例,focus = `initial`:

```
        [ ˋ ]        ← 预填锁定(声调金)
[ b ] ← 挖空,唯一可操作
   [ a ]            ← 预填锁定(韵母绿)
```

**托盘**:只给 `initial` 类型的块。正解 `b` 必在,外加该类型的干扰块 —— 走 `taughtBlocks(unitIndex)` 里 `initial` 的池子 + `CONFUSABLE.initial.b = ['p']` 优先。可用干扰块见 §2.5。

**预填块不可拿回**:`placeBlock` / `takeBack` / 槽位 `onClick` 三处都要挡住。理由与被删的复习段一致 —— 能拿回的话孩子会把预填的正确块全掏出来重新摆一遍,「脚手架」就成了「可自由改写的提示」。

**门禁**:`canPlace` 不变。脚手架遍是**简单部分的一部分**,不引入任何新的判定函数(不像困难部分那样有 `sameTypeOnly`)。放错 = 弹回 + 抖动,与今天的简单部分完全一致。

**判错**:`wrongSlotIds` 那条路在脚手架遍**恒不可达**(同简单部分的既有性质 —— `canPlace` 在落位前就挡住了错的)。脚手架遍没有失败路径,与简单部分一致。

### 2.5 托盘算法:不碰 `buildBlocks`

`buildBlocks` 的干扰块总数 `cap = level.syl.length > 1 ? 2 : unit <= 1 ? 2 : 3`(`rules.ts:168`)是为**全槽拼装**调的 —— 它按「用到哪几类就摊给哪几类」分配名额。脚手架遍只用到**一类**,那个 cap 分配出来的托盘会有 2/3 的名额落在另外两类上,而盘面上**根本没有它们的槽** —— 那些块放不进去,孩子在托盘上点到一个无处可落的块,触发「miss + 闪红」。

**那是坏题**:它量的是手滑,不是理解(正是 2026-09-27 那份 spec §1 诊断的原始问题)。

> **裁定:脚手架遍走 `practice.ts` 那条「题源自带托盘」的路,`buildBlocks` 一个字不动。**

```ts
export function scaffoldQuestion(level: Level, unitIndex: number, rng: Rng = Math.random): ScaffoldQuestion
```

`ScaffoldQuestion` 与 `PracticeQuestion` 同构(都是 `{ slotIds, tray }`),但:

| | `PracticeQuestion` | `ScaffoldQuestion` |
|---|---|---|
| `slotIds` | **全部**槽(`practice.ts:25`) | **仅挖空类型**的槽(focus 或 `tone`) |
| `tray` | `buildBlocks(...)` 全类型 | 正解 + 该类型的干扰块 |
| 预填 | **无**(`practice.ts:9` 明写) | 非挖空类型的槽全部预填 |

**预填块怎么进盘面**:`placement` 的初值。把正确块贴上 id(`p{i}`)放进 `prefill`,同时**也放进 `tray`** —— 因为 `renderSlot` 与 `wrongSlotIds` 都靠 `tray.find(b => b.id === ...)` 反查块。被 `placement` 占用的块会自动从托盘的可视列表里滤掉(`PinyinBlocksGame.tsx:265` 的 `liveBlocks` 已经做了这件事),所以它们不会出现在托盘上。

> **这就是被删复习段用的手法**(`9c56f4b` 之前:`q{i}-p{j}` 两套 id 命名)。本行照抄,不发明新的。

**focus 型的干扰块取几个**:`SCAFFOLD_TRAY_CAP = 4`(4 块 = 1 正解 + 3 干扰,与 `CONFUSABLE` 的最小对立对密度相称)。取值从 `taughtBlocks(unitIndex)` 里 focus 类型的块按 `CONFUSABLE[focus][value]` 优先、同 `shuffle(…, rng)` 洗 —— 与 `buildBlocks` 的取块顺序**同一套形状**(`rules.ts:184-189`),但只跑一类。

> **不足时怎么办**:focus 类型的可用块不够 4 个就取几个。**恒 ≥1 个干扰块**(只有 1 个可取时给 2 块),除非该类型的池子本身只有 1 个值(u1 的 `final` 池在课程推进早期可能很浅)—— 那时**如实给 1 块**,不为凑数造一个未教过的块。

**声调型的托盘不走上面这套**,直接用 `toneBlocks(level)` —— 它已经是**四声恒全出 + 按需重复正解块**的现成纯函数(`rules.ts:118`):

- 单音节题 ⇒ 恒 **4 块**(`1 2 3 4`),干扰恒 3;
- 双音节题两个音节**同调**(如 `xī guā`)⇒ **5 块**(`1 1 2 3 4`),两块一声各落一个槽;
- 双音节题两个音节**异调** ⇒ **4 块**(`1 2 3 4`) —— `u7-1` / `u7-2` / `u7-4`。

**声调型不套用 `SCAFFOLD_TRAY_CAP`**:那个常量管的是「干扰块总数上限」,而声调的块数由**正解块数**决定(`toneBlocks` 里的 `need` 计数),两者是不同的旋钮,套用会把双音节同调题卡掉一块正解。**声调型的一条硬约束:托盘里的正解块数恒 ≥ 空槽数**(否则无解)—— 这是要测的(§5)。

### 2.6 落库:用独立键,不改 merge

**产品裁定:脚手架遍落库,全拼遍覆盖。**

直接实现「覆盖」需要改 merge 语义,而三层 merge **全是 `Math.max`**:

| 位置 | 代码 |
|---|---|
| worker | `worker/pinyin-progress.ts:65` `out[key] = Math.max(out[key] ?? 0, value)` |
| 前端写入 | `src/features/pinyin-progress/pinyin-progress.ts:44` `[clear.levelId]: Math.max(...)` |
| 前端合并 | 同文件 `:52` `stars[levelId] = Math.max(...)` |

**改它会撞「只升不降」这条铁律** —— 那条铁律正是 2026-09-27 进度全丢事故(`docs/PLAN.md` `P0` 「进度本地兜底」行)之后立起来的防线,而且它同时保护着「重玩拿一星不该把三星冲掉」这条正常语义。

> **裁定:「覆盖」用换键实现,零 merge 改动。**
> **脚手架遍落 `${levelId}s`(如 `u2-0s`),全拼遍照常落 `${levelId}`。**
> 效果与「同一键被覆盖」**完全等价**:正式那道题的星级只由全拼遍决定,脚手架遍的成绩写在另一个键上,不遮蔽任何东西。

**`s` 键对所有派生统计完全惰性** —— 实测核对过全部取数点:

| 取数点 | 怎么取数 | `s` 键的影响 |
|---|---|---|
| `completedLevelCount` | `unit.levels.filter(cleared)` | 遍历 `unit.levels`,`s` 键不在其中 |
| `perfectLevelCount` | 同上 + `=== 3` | 同上 |
| `perfectUnitCount` | `UNITS.filter(u => u.levels.every(...))` | 同上 |
| `lessonCleared` / `lessonClearedCount` | `lesson.levelIds.every/every` | `levelIds` 是正式 id |
| `practiceLevelsOf` | `unit.levels.filter(stars < 3)` | 遍历 `unit.levels` |
| `totalLevelCount` | `UNITS.reduce(Σ levels.length)` | 与星级表无关 |
| `unitClearedCount` / `lessonState` / `nextLessonOf` | 同上 | 同上 |

**零影响。** 唯一需要注意的是 `LEVEL_ID` 正则 —— 它现在认不下 `s` 后缀,而**认不下就会静默丢 key 或整包 400**(见 §3.3)。

### 2.7 星尘与连击

**星尘**:脚手架遍走**完整的 `settleLevel`** —— 连击加成、幸运骰、成就扫描全跑。它是一次真实的答题,该给的奖励要给。

> **副作用(要写进 spec 明处,不是缺陷)**:一节里同一道题跑两遍 ⇒ **星尘入账两次**。今天一节 5 题 = 5 笔,改后 5 题 = 10 笔。
> **已裁定接受。** 星尘今天**没有任何消费口**(「商店 / 徽章 / 宠物」在「坚决不做」里),它是纯累计计数器,倍增不改变任何可达状态。将来若开商店,按星尘总量调经济参数即可,不必回改本行。

**连击**:两遍都上报。脚手架遍里点错的块会打断连击 —— 这符合连击的既有语义(「连续答对」)。若某道题脚手架遍 3 星、全拼遍 2 星,连击不归零(它数的是块不是题)。

### 2.8 视觉:预填块怎么表示「这是给你的」

**零可见文字**(沿用 2026-09-23 立下的铁律)。预填块与孩子自己放上去的块必须**一眼可分**,否则孩子会试图拖动它、拖不动、以为是坏了。

**做法**:预填槽挂一个新类 `.pslot--given` —— **实线外框 + 略降不透明度**,块本身不降透明度(降块面就降了可读性)。与 `.pslot--filled`(孩子自己放的,无外框)的差别是**边框的实线/无**。

> **为什么不用现成的 `.pblock--placed`**:`placed` 是「孩子放的」这件事的标记,预填块**不是**孩子放的。复用它会让两件事在屏幕上同形,而那正是本行要解决的歧义。

**拖拽**:预填块**不接受** `onPointerDown`(`PinyinBlocksGame.tsx` 的 `trayBlock` 那层),所以拖它没有任何反馈。**拖不动的元素应该告诉孩子它不能动** —— 预填槽的实线外框 + `cursor: not-allowed` 承担这条。

### 2.9 无障碍

- 预填槽的 `aria-label` 从「已放 X」改成「已给 X」(`PinyinBlocksGame.tsx:551` 那行)—— 读屏用户能听到差别。
- 预填块不绑 `onKeyDown`(今天托盘块绑了 Enter/空格触发 `autoPlace`),所以它既不能点也不能键盘拖,与视觉一致。
- 预填块不绑 `onClick`(拿不回来),与视觉一致。

## 4. 不变量

1. **全拼遍一字不改** —— `canPlace` / `buildBlocks` / `autoTargetId` / `wrongSlotIds` / 提示档 / 干扰块算法,与本行无关。
2. **脚手架遍恒用 `canPlace` 门禁** —— 不引新判定函数,无失败路径,与简单部分同性质。**声调型同样如此**。
3. **脚手架遍的托盘里恒有正解**,且每一块都放得进盘面上**存在**的槽 —— 不得出现「点得到却无处可落」的块。
4. **预填块恒不可拿回**(`placeBlock` / `takeBack` / `onClick` 三处)。
5. **`slotIds ∪ prefill` 恒等于全部槽** —— 恒不多不少。少一个 = 一个空槽没挖(孩子无从下手);多一个 = 一个块无处可落。
6. **声调型的正解块数恒 ≥ 空槽数** —— 双音节同调题(`xī guā`)必须有两块一声。这是 §2.2b 那条硬约束。
7. **无解的题恒退成单遍全拼** —— 屏上不会出现「预填了却没有槽可挖」的盘面。
8. **`${id}s` 键对所有成就/解锁/练习口径零影响** —— 它们全都遍历 `unit.levels`。
9. **脚手架遍的星级不遮蔽正式那道题** —— 两者是两个键,且 `mergeStars` 仍是 MAX,全程只升不降。
10. **`Level.listen` 的纪律一字不变** —— 声调遍继承该标志;`listen: true` 的题照念,`false` 的绝不自动念(念出来等于把调告诉孩子)。
11. **后端零迁移** —— 只改三处 `LEVEL_ID` 正则,表结构、`readStars` 的值域、`mergeStars` 的算法全不动。
