# 拼音积木难度改造(一关三段 · 最小对立干扰块 · 困难段可失败 · 错块复习)— 设计

> **日期** 2026-09-27(2026-09-27 依产品三轮追加口径**整篇重写**,取代同日早先那版「一关一段 + 关末复习」的设计)
> **状态** 待评审
> **PLAN 行** `docs/PLAN.md` `0.3.0` feature 轨「拼音积木难度改造」(原落 `0.2.0` 轨,2026-09-27 依裁定 E1 挪出)
> **口径来源** 2026-09-27 产品口径:「游戏需要增加难度,增加关卡。目前没有错误的路径,玩家永远无法答错题」,及随后三轮追加:
> 1. 「每个关卡分 3 个部分:简单(现有关卡模式,没有失败路径)、困难(新模式,可能失败)、复习(复习错题)。简单级别部分中虽然没有失败路径,但是也要记录错题(多次选中错误的选项就会进入错题集)。三种题的 UI 要有明显的区别,且中间要有一个级别难度上升的提示。」
> 2. 「块只能拖进同颜色的槽位,声母只能拖进声母的槽位,韵母只能拖进韵母的槽位,可以使用错误的声母/韵母/声调,最后再判断是否失败。且要提到至少 2 个韵母和 2 个声母,增加干扰项。」
> 3. 「填满后判断出错,提示错误的槽位,让其重试,每道题可以重试 2 次,重试次数用完后,即判断失败,继续下一道题,失败的题进入后续的错题池复习」/「收「块」,复习段只考本关」/「存档不存,N=2」/「β + ②」
> **过程备注** 本行后续**采用 Sub-agent driven 的方式开发**(产品 2026-09-27 指定);分期与派工写在实现计划里,不在本 spec。
> **性质(B1 裁定的后果,全文口径)** 本设计只提供**辨认**难度 —— 三段的槽位门禁在最松的困难段也只放到「类型对、值可错」,**孩子永远拼不出一个音素层面非法、或跨类型错位的音节组合之外的东西**;简단段与复习段的门禁更是原样不动。任何「让孩子自由构造再看见它错」的机制都不在这里,入口见 §8 裁定 B 的 B2。

## 1. 问题

产品说「玩家永远无法答错题」。读源码实测之后,这句话**比它字面说的还要重** —— 判错的路径不是「很难走到」,是**结构上不可达**。

三条证据,按因果顺序:

1. **`placeBlock` 在块落位之前就把错的挡掉了**。`PinyinBlocksGame.tsx:167`:

   ```ts
   if (!canPlace(block, slot)) { noteMiss(); …; flashReject(slotId); return }
   ```

   `canPlace` 为假 → 块**不写进 `placement`** → 弹回托盘。

2. **`placement` 的唯一写入点就是上面那一句之后的第 178 行**,而托盘里的块在一轮之内身份不变。两条合起来:每个已填的槽**恒**满足 `canPlace`。

3. 于是 `rules.ts:182` 的 `wrongSlotIds(slots, next, tray)` **恒返回 `[]`**,`:188-201` 那一整段 —— 「全填 → `status='wrong'` → 抖 720ms → 撤掉错块」—— **永不执行**。

这段代码不是「很少触发」,是**死代码**:全仓没有任何一条测试覆盖它(`PinyinBlocksGame.test.tsx:596` 的一句注释里提到过它,仅此而已),`git log -S` 显示它从最初的提交 `1e22279` 就在那儿,所以这是**原设计如此**,不是回归。

第二层问题:**点击路径连「选块」这一步都省了**。`rules.ts:173` 的 `autoTargetId` 会替孩子找到那个**能放得进去的**空槽 —— 点托盘上的任何一块,它自己就飞到对的槽里。所以只要一路把托盘点空就能通关,托盘怎么打乱都不影响。

**结论**:今天孩子能犯的错只剩两种 —— 拖着块往不匹配的槽上怼(被弹回),或点到一块无处可落的块(被静默拒掉)。这两种量的是**手滑**,不是**理解**。三颗星的实际含义是「全程没被拒绝过」,而不是「拼对了」。

### 1.1 为什么「加关卡」治不了它

同一天落地的 PLAN 行「拼音课程全表扩充」(7 单元 37 关 → 12 单元 91 关)已经回答了「内容太少」,它当天的裁定④写的是:

> 难度手段 = **每单元末一个复习关**(弱档提示 + 干扰块拉满 + 池天然混入前面单元),**不引新机制**

复习关治的是**题量的分布**,不是「有没有判断」这件事本身 —— 91 关里每一关的胜利条件仍然是「把托盘点空」。题量翻一倍,通过率不变。

**本 spec 取代那条裁定④**;该行其余六条裁定与已交付的 91 关数据不动。产品在追加口径里提到的「增加关卡」,本次同样**不并进来**(§8 裁定 C)。

## 2. 本设计要立的那两条不变量

> **一、孩子做错的代价,必须落在「选错了块」上,而不是落在「没放对位置」上。**
> **二、难度必须是孩子能看见的。看不见的规则不是难度,是运气。**

第一条决定了后面所有的形态,包括那些看起来别扭的地方:

- 简단段与复习段的槽位门禁不设难点 —— 因为**位置**不是要教的东西,`canPlace` 是脚手架,拆了它只会让孩子把「拼不出来」误当成「手不稳」。
- 难度全压在**托盘**:托盘里同时摆着 `b` 和 `p`,孩子必须听/认得出区别才选得对。
- 「错」的计数与展示,记的是**点错了哪一块**,不是**放错了哪个槽**。

第二条是困难段那三条硬性约束的来源(§3.7):同类型才放得进、槽的类型色**恒亮**、判错后**指出是哪几个槽**。

第一条同时划出了本设计的**上限**:即使是门禁最松的困难段,孩子也只能把「类型对、值错」的块放进槽里,判错后撤块重来 —— 他**看不到一个拼错的音节被读出来**。这是一条**辨认**难度,不是**构造**难度。**这条上限已被产品确认接受**(裁定 B1)。入口见 §8。

## 3. 设计

### 3.0 一关 = 三段

```
简单段 ──[过场 A:难度上升]──→ 困难段 ──[过场 B:转入复习]──→ 复习段 ──→ 结算
(今天的玩法)                    (值可以错)                    (只考本关的错块)
```

| | 简单段 | 困难段 | 复习段 |
|---|---|---|---|
| **槽位门禁** | `canPlace`(值 + 类型都对) | **只对类型** —— 声母块只进声母槽、韵母进韵母槽、声调进声调槽;**值可以错** | `canPlace`(同简单段) |
| **失败** | 无(弹回 + 抖动) | 填满即判 → 指出错误槽 → 撤块重试;**每关 2 次**;用尽即本段失败,**不阻塞** | 无(弹回 + 抖动) |
| **记 miss** | 是 | 是(累加进同一个 `missCount`) | **否**(恒不增) |
| **进错题池** | 同一块点错 **2** 次 | 判错的每一块 | — |
| **托盘** | 现状 + 最小对立对优先(§3.3) | 每个用到的类型给足 ≥2 块(§3.7) | 该类型所有槽的正确块 + 该类型下点错过的块,上限 4 |
| **提示档** | `hintFor(unit.id, missCount, level.review)` 现状 | **不适用** —— 槽恒亮,不吃档位变量(§3.8) | 恒中档(`pslots--mid` 写死,不走 `hintFor`)(§3.8) |
| **上报连击** | 是 | 是 | **否** |
| **段标** | 台阶条第 1 格 | 台阶条第 1 + 2 格 | 台阶条第 1 + 2 格(橙)+ 第 3 格(灰蓝)+ 小题进度点 |

**一关一道题,三段共用同一张图、同一个音节。** 三段的差别是**门禁与托盘**,不是题面。

> **命名撞车,全文按下表用词。** 课程数据里已经有一个 `Level.review` 字段(每单元末那个复习关),它和这里的「复习段」是**两回事**:
>
> | 词 | 指什么 | 影响什么 |
> |---|---|---|
> | **复习关**(`level.review === true`) | 课程数据的一个字段,标在每单元最后一关上 | 只是 `hintFor` 的输入与 `buildBlocks` 的 `cap`(5),本设计不动它 |
> | **复习段**(本设计的第三段) | 每关都有的一段运行相位 | 门禁、托盘、记 miss 与否(§3.7) |
>
> 一个复习关里有三段;三段里的第三段叫复习段。实现时**不要**把两者混成同一个概念(`stage === 'review'` 与 `level.review` 是两个独立的东西)。

### 3.1 最小对立对数据表(`blocks.ts`)

新增一张纯语言学知识表,**不含任何课程/关卡耦合**:

```ts
/**
 * 易混伙伴:同一块在托盘里应该优先拿谁来当干扰块。
 * 只写「像」,不写「教没教」—— 后者由 taughtBlocks 在运行时过滤(见 buildBlocks)。
 */
export const CONFUSABLE: Readonly<Record<BlockType, Readonly<Record<string, readonly string[]>>>> = {
  initial: {
    b: ['p'], p: ['b'],
    d: ['t'], t: ['d'],
    g: ['k'], k: ['g'],
    j: ['q'], q: ['j'],
    zh: ['z', 'ch'], z: ['zh', 'c'], ch: ['c', 'zh'], c: ['ch', 'z'],
    sh: ['s'], s: ['sh'],
    n: ['l'], l: ['n'],
    m: ['n'],
    f: ['h'], h: ['f'],
  },
  medial: { u: ['ü'], ü: ['u'] },
  final: {
    u: ['ü'], ü: ['u'],
    ai: ['ei'], ei: ['ai'],
    ao: ['ou'], ou: ['ao'],
    iu: ['ui'], ui: ['iu'],
    ie: ['üe'], üe: ['ie'],
  },
  // 前/后鼻音只差一个鼻尾,所以「对」记在鼻尾上,而不在韵腹上 —— an/ang 的韵腹是同一个 a。
  nasal: { n: ['ng'], ng: ['n'] },
  // 四声恒全出(见 toneBlocks),声调不需要这张表。
  tone: {},
}
```

三条口径:

1. **表是不对称的**:`b: ['p']` 与 `p: ['b']` 各写一遍。不自动取反 —— 有些对本来就不对称(平翘舌里 `z` 的孩子更常误选 `zh`,反向少),今天虽然写成了对称的,但结构上留着不对称的余地。
2. **表只表达「像」,不表达「教过没有」**。哪些伙伴真的能进托盘由 `taughtBlocks(unit)` 在运行时过滤。于是**难度曲线是课程曲线自动派生的**,不需要第二份数据:u1(单韵母)一个伙伴都没教,关卡难度不变;u2 教齐 b/p/d/t/n/l/m 之后开始出对;u4 进来平翘舌整组;u5 进来复韵母对;u7 进来前后鼻尾。
3. **单韵母 a/o/e/i 与 er 不进表**。它们是入门内容,`u1` 面对的是刚认字母的孩子,那里不该有陷阱。

**实现时须有一条测试**:`CONFUSABLE` 里每一个键与每一个伙伴值,都必须是该 `type` 下真实存在的块值(键 ∈ `INITIALS_ALL` / `MEDIALS` / `FINAL_BASIC ∪ FINAL_COMPOUND` / `NASALS`,`tone` 恒空)。没有这条,表里写错一个字母不会有任何东西红 —— 而它错的方式恰好是**静默变简单**(伙伴查不到 → 池子里没有 → 退回随机干扰块)。

### 3.2 取块策略(`buildBlocks`,只改顺序)

`rules.ts:124-134` 现在给每一类建一个洗好的候选游标,`:143` 用 **`pop()`(取尾部)** 逐个取。所以只要把易混伙伴**放在数组尾部**,它们就会**先**被取走:

```ts
const friends = (CONFUSABLE[type]?.[value] ?? [])   // 对每个 required 块
const others  = taughtList.filter(v => !used.has(v) && !friends.includes(v))
cursors.set(type, [...shuffle(others, rng), ...shuffle(friends.filter(taught), rng)])
```

简单段与复习段的 `cap` **不动**(`level.review ? 5 : level.syl.length > 1 ? 2 : unit <= 1 ? 2 : 3`)。理由:干扰块**总数**是「题面有多挤」,易混对是「挤在里面的块有多像」—— 两个不同的旋钮,这里只拧后者。同时在 `cap` 小于伙伴数时,先取到的是最近的那几个(顺序由 `shuffle` 决定,仍受注入的 `rng` 控制,测试可复现)。困难段的托盘另有算法,见 §3.7。

### 3.3 顺带修的现存缺陷:i/u/ü 的双身份把干扰块废掉了

`rules.ts:72`:

```ts
const keyOf = (b: Block): string => `${b.type}:${b.value}`
```

`takenKeys`(`:111`)用它做「干扰块不得与正确块重名」的去重。但 `canPlace`(`:51-59`)对 `i/u/ü` 明确允许**介母 ↔ 韵母互换** —— 也就是说 `medial:u` 与 `final:u` 在孩子手里是**同一块积木**。现在它们被当成两块不同的块,后果有两层:

- **判对判错不一致**:答案是 `guā` 时 `medial:u` 是正确块;一个 `final:u` 干扰块被拖进介母槽,`canPlace` 判**通过** —— 它成了「货真价实的干扰块里唯一能放的」,孩子随手一拖就中。
- **屏幕上是两块一模一样的块**:托盘里并排两块「u」,孩子没有任何线索区分,而其中一块拖到某个槽上是「对」、另一块拖到同一个槽上也是「对」。这是纯粹的噪声。

**修法**:去重改用 family key —— `i/u/ü` 只按值去重,其余仍按「类型 + 值」。

```ts
const familyKey = (b: Block): string => (DUAL_VALUES.has(b.value) ? b.value : keyOf(b))
```

**为什么不能一律按值去重**:`initial:n`(声母 n,读「讷」)与 `nasal:n`(鼻尾 n,读「恩」)值相同,但 `canPlace` 判它们**不通用**,是两个真身份 —— 而它们同时出现在托盘里是**刻意设计**(`PinyinBlocksGame.test.tsx:185` 有一条断言专门钉住「按 `data-type` 认身份,不按字符」)。一律按值去重会把这一对合法干扰块删掉,等于把游戏改简单。

> **困难段是这条的例外,必须写清。** 困难段的门禁是「只对类型」,`medial:i`(青)与 `final:i`(绿)**在那一段里是两个真身份** —— 青色只能进介母槽,绿色只能进韵母槽。所以在困难段里:
> - family key **不参与**去重与错题池记账,一律按 `keyOf`;
> - 两块的**面颜色本来就不同**(介母青 / 韵母绿),孩子分得开,不需要靠去重保护。
>
> 简단段与复习段的门禁是 `canPlace`,family key 照用。

### 3.4 点错块的视觉反馈

`autoPlace`(`PinyinBlocksGame.tsx:227-240`)在块无处可落时:

```ts
else { noteMiss(); onBlock?.('wrong'); playSound?.('wrong') }
```

**只有声音**。静音环境(平板上很常见)里,孩子的体验是「点了它一下,什么都没发生」—— 而 `missCount` 已经在涨了。今天这只是小瑕疵;干扰块变成 `b`/`p` 这种高度相似的对手之后,它会直接变成挫败,而且简단段**要靠它**把错块收进错题池(§3.5),没有可见反馈的收集是孩子看不见的。

**做法**:托盘块复刻槽位的 `flashReject` 手法 —— 同一个自增序号 `n` 驱动,让**连续点同一块也能重放动画**(只切 class 的话第二次挂上去的类和第一次一样,CSS 动画不会重播)。

- 新增 state `rejectBlock: { id: string; n: number }`,与 `reject` 同构;
- 新增 CSS 类 `.pblock--reject`(抖动 + 短暂红描边,落在拼音积木材质段);
- 触发点是 `autoPlace` 的 `else` 分支,以及 `placeBlock` 里块不匹配时**同时**闪块与闪槽(现在是只闪槽)。

**零文本**:不出现任何文字或数字,只有形变与颜色。

### 3.5 简单段:错的记录(N = 2)

简单段**没有失败路径** —— 门禁与今天一字不差,块放不进就是弹回 + 抖动,**不阻塞、不扣星之外的东西**。

但它必须**记录**:

> **同一块在简单段里被点错 2 次 ⇒ 该块进本关错题池。**

**「点错」的两种形态都要算**(与 §3.4 的两个闪红触发点同源):

1. **点选无处可落** —— `autoPlace` 走到 `else` 分支(托盘里选错了块,它哪个空槽都进不去);
2. **拖到不匹配的槽** —— `placeBlock` 的 `!canPlace` 分支(把块往错的槽上怼,被弹回)。

两种都是「孩子选中了一块错的块」,产品口径说的是「多次**选中**错误的选项」,所以都进计数。

- **计数按 `block.id`**(托盘里那一块,一轮之内身份稳定),**入池按 family key 去重**。这样同一块被点两次才算数,而不是「同样点错两块不同的 p」凑数。
- **N = 2** 是产品裁定值,写成 `WRONG_PICK_THRESHOLD` 常量并注明来源,别散在代码里。
- 简单段点错的块必然是**干扰块或多余的声调块** —— 答案块永远点不错,它的槽总存在且此刻总空着,`autoTargetId` 总能给它找到落点。所以错题池的候选集天然干净。
- **池是关内状态,不持久化、不跨关。** 产品裁定「复习段只考本关」。

### 3.6 困难段:值可以错

**门禁**:`canPlace` 在困难段**不适用**。替换为一个更松但独立的判据 ——

> **`sameTypeOnly(block, slot)`:`block.type === slot.type`。**
> 声母块只能进声母槽,韵母块只能进韵母槽,声调块只能进声调槽。**值不对也放得进去。**

- 这是**第三个判定函数**,不是修改 `canPlace`。`canPlace` 一个字不动(§5)。
- **`medial` 与 `final` 在困难段不通用**,尽管 `canPlace` 允许互换 —— 困难段按 `type` 严格比。介母块是青色、韵母块是绿色,孩子看得见这个区别(见 §3.8 关于类型色恒亮)。
- **点击一键落位(`autoTargetId`)保留**,但目标槽改为「同类型的第一个空槽」。产品在早期裁定里明确保留一键落位;在困难段它退化成「把块放进它那一类的槽里」,选哪一块、选得对不对仍由孩子负责,考点没有绕过去。
- **拖拽**照旧只接受同类型的槽;拖到别的类型的槽上 = 弹回 + 抖动。

**判定时机**:填满后判(与今天同)。

**判错后的处置**(这是今天那段死代码第一次真正跑起来的地方,`PinyinBlocksGame.tsx:188-201`):

1. `wrongSlotIds(slots, placement, tray)` 返回所有值不对的已填槽;
2. 非空 ⇒ `noteMiss()` + `onBlock('wrong')` + `playSound('wrong')`;
3. `status = 'wrong'`,那些槽挂 `.pslot--wrong`(红描边 + 抖动,已有 CSS);
4. 停 **720ms**(沿用现状),撤掉错槽里的块回托盘,`status = 'playing'`,重试;
5. **每次判错计 1 次 miss**(累加进同一个 `missCount`,与简单段的点错同源)。

**重试上限**:每关 **2 次**(产品裁定值,写成常量)。

**用尽之后** —— 第 3 次判错时:

- 不再撤块重试;
- 把**正确块自动落进各自的槽**(一次可见的「演示」),答案行亮起(显示 `pinyin` + `read`);
- 停约 1.2s,进过场 B;
- **本段标记为失败,但继续往下走,不阻塞**(产品裁定)。星级已由 `starsFor(missCount)` 决定,2 次重试用尽 ⇒ `missCount ≥ 2` ⇒ 最高 2 星。**「1 星即通关」的既有铁律不变**,失败不会是死路。
- 判错的块**全部进错题池**(每次判错的都进,不只是最后一次)。

> 「演示正确答案」这一步是本 spec 对「重试次数用完后,即判断失败,继续下一道题」这条口径的**具体化建议**。理由:一关只有一道题,「继续下一道题」在一关内无从落实;而直接跳过会让孩子不知道正确答案是什么,复习段又会拿同样的块来考他 —— 那会把一次失败放大成两次。若产品要的是「什么都不给,直接走」,改这一处即可,不影响其余设计。

**托盘**:困难段的 `cap` 算法与简单段不同 —— 干扰不够就不构成难度。

> 对**本关真实用到的每一个类型**,从该类型已教过的块里取足至少 **2** 块(即:正确块 + ≥1 个易混干扰块,伙伴优先,见 §3.2 的排序)。声调块照旧四声全出。

`u2-0`(爸 `bà`,声母 + 韵母 + 声调)在困难段因此是:`b p` / `a o` / `ˉ ˊ ˇ ˋ` = 8 块 —— 与简单段**同为 8 块**(简单段的 `cap` 是**全局**名额,困难段是**逐类型**取足,两者不走同一套算法,谁多谁少随关卡而定:全 91 关里困难段更多的只有 7 关、持平的 23 关、更少的 61 关)。**两段的难度差不在块数,在门禁**:简单段多出来的块**值不对就放不进去**(`canPlace` 拦在落位之前),困难段给每一类都配了一块**值不对却放得进去**的对手块 —— 值对不对由孩子自己负责。

### 3.7 复习段:只考本关的错块

**触发**:错题池非空。**池空时照样进复习段**,只是考的题不同(见下)。

**题量**:**每个错块一道小题,最多 3 道。**

- 错块按 **family key 去重**(§3.3);同一类型的错块合成一道小题。
- 超过 3 个类型时,取**最近点错的**前 3 个。
- 每道小题:挖空本关中**该类型的所有槽**(双音节有两个声母槽就都空出来,这时考的是「哪个音节用哪个」,反而更好),其余槽用正确块**预填**,复用本关的图与音节。
  > **预填的块必须不可拿回。** 今天已填的槽点一下就 `takeBack` 回托盘 —— 复习段照搬的话,孩子能把预填的正确块全掏出来重新摆一遍,考点就没了。预填槽在复习段不绑 `onClick`,孩子唯一能操作的是挖空的那几个槽。
- 小题的托盘 = 这些槽的正确块(全部给,**少一块就无解**)+ 该类型下点错过的块(family key 去重,最近的优先),**总数上限 4**;若正确块已达上限,则这道小题**只留正解、不加错块(上限优先)** —— 与同一句里的总数上限是**同一条口径**:上限管的是屏上看得见的那几块,名额不够时先保「题面不超编」,不为凑一块错解而破例(正解少一块就无解,错解少一块只是这道题变简单)。课程数据保证这一支今天打不到:每关同一类型的槽最多 3 个,`名额 = 4 − 空槽数 ≥ 1` 恒成立(守卫在 `levels.test.ts`);这条是防御,不是常规路径。
- 某错块的 family key 与某个复习槽的正确块相同时,该错块**不进复习托盘**。否则会出现两块**完全一样**的块,孩子只能瞎猜 —— 那不是难度,是坏题。

**池空时**:照考 —— 把本关**整题重做一遍**(所有槽挖空,托盘同简单段),小题进度点只有一颗。产品裁定「三段结构恒定」,不做「跳过复习段」那条分支。

**判定与代价**:

- 复习段沿用 `canPlace` 门禁与点击自动落位 —— 与简单段完全一致,这是产品「不在槽位设置难度」这条裁定的直接后果,复习不例外;
- 因此复习里的「错」表现为**被弹回 + 抖动**,而不是「拼出一个错的音节」;
- **不记 miss、不影响星级、不产星、不上报连击**。星在进复习段**之前**就已经落库了。

**题面复用本关的图**:这一条同时解决了一个否则无解的障碍 —— `SPEAK_OF.tone` 是**空表**(声调没有可念的音,`blocks.ts:57-58`),所以「听音选块」这种题面对**声调块根本不成立**;而图不依赖发音,声调块也考得了。

### 3.8 三段的 UI

**总原则:零可见文字。** 游戏区今天就没有一个可见汉字(所有中文都在 `aria-label` 与注释里),三段靠**形状、颜色、材质**区分。判据只有一条 —— **孩子一眼知道自己在哪一段**。

#### 段标:台阶条

三轮候选(A 台阶条 / B 场地色 / C 数字印章 / D 进度环)中产品选定 **A**。

- 三个竖条并排,**越右越高**,亮到第几格就是第几段;
- 位置钉在**题面图上方**,与拼装台同列,不占新位置;
- 颜色语言与**连击圆点**同源(一排东西、亮/暗两态),孩子在这个游戏里已经学过这个读法,不需要重新教;
- **两态必须可读**:未亮 = 中性暗色,亮 = `accent` 橙。减动效用户看到的是一样的两个状态,动效只是加成。

三段的取值:

| 段 | 台阶条 |
|---|---|
| 简单 | 第 1 格橙,第 2、3 格暗 |
| 困难 | 第 1、2 格橙,第 3 格暗 |
| 复习 | 第 1、2 格橙(保持),**第 3 格灰蓝** |

**第 3 格为什么换色**(候选 α 同色 / β 冷色 / γ 虚框,产品选 **β**):台阶「越右越高」说的是难度,而复习不是第三级难度,是回炉。第三格变成灰蓝,颜色断掉,不会被读成「三级台阶的顶」。

灰蓝这一个色号在复习段承担两个角色(段标第 3 格、小题进度点),是**同一条颜色语言**,不算新增。

#### 槽的类型色

| 段 | 槽 |
|---|---|
| 简单 | 照现有提示档淡出(强 `--slot-line: 55%` / 中 30% / 弱 0%),**不动** |
| 困难 | **恒亮 100% + 实线边**(不吃提示档变量) |
| 复习 | 中档约 40%,虚线边 |

**困难段必须恒亮,这不是审美选择,是正确性要求。** 困难段的规则是「同色才能放」,而槽类型色在弱档单元(`--slot-line: 0%`)被彻底淡光 —— `u9`–`u12` 全是弱档,在那里「同颜色的槽位」这条规则**在屏幕上是不可见的**,孩子只能靠猜。所以困难段把类型色从**提示**升格成**硬规则的载体**,恒亮且换实线边(实线 = 规则,虚线 = 提示)。

#### 积木盘底

| 段 | 托盘 |
|---|---|
| 简单 | 亮玻璃(现状 `glass-strong`),不挂额外类 |
| 困难 | 底色**压暗一档** + `accent` 橙**实线环** + 内阴影 |
| 复习 | 底色**去饱和灰** + 中性**虚线环** |

积木盘是屏幕下半部最大的一块面,底色是**最不占位置的段信号**。困难段压暗之后五类块面反而更跳 —— 这与「困难 = 沉下去」一致。压暗后需复核块面墨色的对比度(块面本身是实体、三主题恒定,不会随底盘变色;要核的是**块压在暗底上的边界是否还分得清**)。

#### 过场

两处,都在段落切换时发生,**共用同一个遮罩组件,画法不同**:

**过场 A(简单 → 困难)—— 全屏抬升**。产品在「原地升级① / 全屏抬升②」中选 **②**。压一层暗遮罩,台阶条放大到屏幕中央、两格**逐格点亮**,再缩回原位,约 **1.2s**,配一声上冲音。理由:这是唯一能保证孩子注意到「换段了」的画法,而换段正是要他意识到自己进了新规则。

**过场 B(困难 → 复习)—— 同一遮罩**,台阶条画成「前两格保持橙 + 第三格点亮成灰蓝」。产品选的是「重:复用同一遮罩,画法不同」,所以两处都是全屏打断,但第二处的**颜色语言**告诉孩子这不是升级。

**减动效**(`MotionConfig reducedMotion="user"`):两者都退化成**同一个静态帧** —— 暗遮罩 + 台阶条全部点亮到目标态,停 1.2s,然后消散。**不靠位移,两态可读**,与连击圆点那条既有纪律一致。

#### 复习段的小题进度点

**本轮唯一新增的控件。** 复习段最多 3 道小题,需要知道还剩几道:

- 位置钉在**台阶条正下方**,与段标同层,不占新地方;
- 最多 3 个点,做完几道亮几颗,颜色用**复习段那支灰蓝**(与第 3 格同色);
- 放错只抖,不动它。

### 3.9 星级与结算

**星级输入口径(产品裁定:困难段的错也累加 miss)**:

```
starsFor(简单段点错次数 + 困难段判错次数)
```

- `starsFor` 的**取值一个字不改**(`0 错 → 3 星 / ≤2 错 → 2 星 / ≥3 错 → 1 星`,1 星即通关);
- 困难段 2 次重试用尽 ⇒ `missCount ≥ 2` ⇒ 该关**最高 2 星**;
- **复习段恒不增 `missCount`**(§3.7),要有一条注释写死这件事,否则后来者会把复习的错合并进去,造成「复习没做好 → 主关掉星」的反噬。

**相位与落库顺序(硬要求)**:

```
简单段拼对
  → [过场 A]
  → 困难段(拼对,或 2 次用尽失败后演示正解)
  → settleLevel(落库:星级归一 / 首通 / 连续天数 / 成就扫描 / 星尘)   ← 星在这里就安全了
  → [过场 B]
  → 复习段(N 道小题,或池空时本关整题)
  → onSettle(result) + 撒花 + 推进下一关
```

- **星必须在这里落库**:复习段中途孩子按「回地图」就走(那个按钮在 `LevelEntry` 头部,一直可见),此时这一关必须已经记上。今天「拼对 = 立刻记上」,这条不能因为插了两段而退化。
- **星级在困难段结束时就已经定死** —— 因为复习段不产生 miss。这是「星先落库」能成立的前提。
- **`onSettle(result)` 与撒花推迟到复习段之后**:`result` 里的成就 / 幸运奖励弹层由 `App` 渲染,压在复习台上就没法玩了。`settleLevel` 与 `onSettle` 本来就是两件事,这里只是把它们**拆到复习段的两侧**。
  > 这正是本行与「奖励层『归属动作』重做」期 2 的**串行红线**所在:期 2 要在同一条路径上插星级揭示与星尘飞行,两批改动落在同几个函数上,禁止并行。顺序由裁定 E1 定死:期 2 先落,本行随后。
- 复习段跑完,或孩子按「回地图」离开复习段 ⇒ 发 `onSettle` + 撒花,再推进 / 回地图。
- **连击不参与复习**:复习段不上报 `onBlock`,免得「复习」变成刷连击的通道。

**存档:后端零改动、零迁移。** 产品裁定「存档不存」—— 困难段与复习段的成绩**不单独落库**,没有新字段、没有新契约。三段对存档的唯一影响是**间接的**:它们影响 `missCount`,而 `missCount` 决定星级。星级与星尘的入库形状与今天完全一致(`readStars` 只收 1..3、`parseStars` 丢 0、`mergeStars` 取 MAX、`local-store.ts` 的校验一字不差地镜像 worker)。

### 3.10 复用哪段代码 —— 不新写平行组件

给 `PinyinBlocksGame` 加两个可选入参:一个 `stage`(`'easy' | 'hard'`),一个 `review`(`{ slotIds, wrongBlocks }`)。差异全部收敛在这两个入参上:

| 面 | 简单段 | 困难段 | 复习段 |
|---|---|---|---|
| 门禁 | `canPlace` | `sameTypeOnly` | `canPlace` |
| `autoTargetId` 目标 | 现状 | 同类型的第一个空槽 | 现状 |
| 初始 `placement` | 全空 | 全空 | `slotIds` 之外的槽用正确块预填 |
| `takeBack` | 已填槽可点回 | 同左 | **预填槽不绑 `onClick`**(§3.7) |
| 托盘 | `buildBlocks(level, unit, rng)` | 同函数,`cap` 走困难段算法 | `slotIds` 各槽的正确块 + `wrongBlocks` |
| `missCount` | 累计 | 累计 | 恒不增 |
| 判错处置 | 弹回 | 撤块重试 → 用尽演示正解 | 弹回 |
| 完成回调 | 进困难段 | 进复习段(先 `settleLevel`) | `onReviewDone()` —— **绝不再触发 `onSolved`** |

理由是那份拼装台里 590 行有相当一部分是拖拽命中、点选路由、幽灵块、槽位渲染 —— 抄一遍必然两份实现各自漂移,而三段要的恰恰是**同一套手感**。

**相位机在 `LevelEntry`**:`LevelEntry` 多一个相位状态(`'easy' | 'hard' | 'review'`)。`PinyinBlocksGame` 已经由 `key={level.id}` 挂载,换段只是换入参,**不刷新关卡数据、不重置已落库的星**。复习段完成后 `setLevelIndex(+1)` 或 `onExitToMap()` —— 与今天 `handleSolved` 末尾那两行同源。

## 4. 不变量的汇总

1. **简단段与复习段**的已填槽恒满足 `canPlace`。
2. **困难段**的已填槽恒满足 `sameTypeOnly`,但**可以**不满足 `canPlace` —— 这正是它的全部考点。
3. 答案块永远点不错 ⇒ 错题池的候选集只含干扰块与多余声调块。
4. 复习托盘里**必有**至少一块错块与全部正解,且**不会**出现两块无法区分的同形块。
5. **困难段的类型色恒亮** ⇒ 「同色才能放」这条规则在包括弱档单元在内的所有单元都看得见。
6. 关星在复习段之前落库;复习段无论做得多差,星级不变。
7. 复习段不产生星、不进连击、不再触发 `onSolved` —— 不可能递归。
8. 干扰块永远来自**已教过的块**(`taughtBlocks` 过滤),易混对不例外。
9. 三段共用一张图、一个音节;换段不换题面。
10. 后端与存档形状零改动。

- `sameTypeOnly` 纯逻辑测试 —— 值错但类型对:可放;类型不对:不可放;`medial` ↔ `final` 不通用。
- 困难段重试计数与用尽后的行为(撤块 → 演示正解 → 进下一段)。
- 错题池的收集(简单段 N=2 计数按 `block.id`、入池按 family key;困难段每次判错全进)与复习小题推导(去重、上限 3、最近优先)。
- 复习托盘的两条边界(同 family key 的错块被过滤;池空时走整题重做)。
- `PinyinBlocksGame.test.tsx` 增加:三段各自渲染、复习相位预填槽、复习托盘内容、复习不涨 `miss`、困难段判错走的是原来那段死代码。
- `LevelEntry` 的落库顺序 —— 断言「进复习段之前 `recordClear` 已被调用」(这条要挡住的行为是:孩子复习到一半退出,星没了)。
- `LevelEntry` 的相位机 —— 简单 → 困难 → 复习 → 推进;困难段失败**不阻塞**。

## 8. 裁定记录

### ✅ A —— `starsFor` 的分档 → **不动**(按推荐)

上限即现状 3 次(≥3 错 → 1 星,1 星仍通关)。诚实地说,「错误次数上限」这个需求在这一档下**没有新增任何东西** —— 它今天就是这个值。真正的牙在困难段(2 次重试用尽)与复习段。
A2(收紧成 `1 错 → 2 星 / ≥2 错 → 1 星`)未选:三星比例会明显下降,而三颗星对孩子是可见的目标;在干扰块已经变狠的前提下可能过头。

### ✅ B —— 复习阶段要不要放开 `canPlace` 门禁 → **B1:不放开**

复习里选错 = 被弹回 + 抖动,必须重选。复习的强度是「**逼他在正解与错解之间再选一次**」,而不是「看他会不会拼出一个错的音节」。
**B2(未选)** 保留在此备查:拼装台接受任何块,填满后由 `wrongSlotIds` 判,错了闪红 + 撤块重试。代价是复习与简单段的手感不同,且 `autoTargetId` 得在复习里关掉。

> **B1 与困难段的关系要说清**:困难段的「类型门禁」**不是** B2。B2 放开的是**全部**约束(块可以落到任何槽),困难段只是把「值必须对」这一条松开、**类型**仍然锁死。所以本设计整体仍然是辨认难度 —— 孩子能把 `p` 放进声母槽而答案是 `b`,但他拼不出一个跨类型的、结构上非法的东西。**「错的音节」始终没有被读出来过。**

### ✅ C —— 增关 → **后置**(按推荐)

产品在开头提到「增加关卡」,但当天已落地的课程扩充行刚把 37 关扩到 91 关,且本 spec 认为那样治的是题量分布。**推荐后置**:先落本设计、在现有 91 关上重估难度分布,再决定加多少、加在哪(否则会同时在改「有没有判断」和「判断多少次」两个变量,无法归因)。若产品坚持扩,另起一行,不并入本行。

### ✅ D —— `wrongSlotIds` / `status='wrong'` 的去留 → **留着**(按推荐)

**留着,而且要接线。** 早先的推荐理由是「删除会把本设计的上限从代码里抹掉」,现在这个理由升级了:**困难段正是这段代码的入口**。今天那段 720ms 的撤块重试逻辑、`status='wrong'` 状态、`.pslot--wrong` 的 CSS,全部在困难段第一次真正跑起来。需要新增的只是**重试计数**与**用尽后的正解演示**。只改注释:`PinyinBlocksGame.tsx:188-201` 上那句「今天从没跑过」要改成「困难段的入口」。

### ✅ E —— 本行与 `0.2.0` 的先后 → **E1:先发 `0.2.0`**

本行随其后的下一个 minor 发。两处落实:

1. **本行从 `0.2.0` 轨挪到 `0.3.0` 轨**(`docs/PLAN.md`)。该轨自 2026-09-21 起挂着「整轨失效」横幅 —— 那条说的是**它的旧条目**(千字谷 / 词课 / 糖果材质等,随「拼音积木取代全游戏」删除),不是这个轨位本身不能再用;已在横幅下加一行注明本轨自 2026-09-27 重新启用承接新能力。
2. **与「奖励层『归属动作』重做」期 2 的串行红线,顺序由本条定死:期 2 先落,本行随后。** 红线本身不撤 —— 两批改动仍然落在关卡页同几个函数上(期 2 插星级揭示与星尘计数器,本行插两段相位与复习段),只是不再有争抢先后的余地。

### ✅ F —— 一关分三段的结构 → **简单 / 困难 / 复习**(产品 2026-09-27 追加口径)

取代本 spec 早先那版「一关一段 + 关末复习」的结构。整篇已按三段重写。

### ✅ G —— 困难段的门禁与失败 → **同类型即可放,2 次重试用尽即失败但不阻塞**

产品口径:「块只能拖进同颜色的槽位,声母只能拖进声母的槽位,韵母只能拖进韵母的槽位,可以使用错误的声母/韵母/声调,最后再判断是否失败。且要提到至少 2 个韵母和 2 个声母,增加干扰项。」/「填满后判断出错,提示错误的槽位,让其重试,每道题可以重试 2 次,重试次数用完后,即判断失败,继续下一道题,失败的题进入后续的错题池复习」。

产品口径:「收「块」,复习段只考本关」。⇒ 池是关内状态,不持久化、不跨关。
