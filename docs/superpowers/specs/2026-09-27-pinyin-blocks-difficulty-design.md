# 拼音积木难度改造(最小对立干扰块 · 点错反馈 · 关末错题复习)— 设计

> **日期** 2026-09-27 · **状态** 待评审
> **PLAN 行** `docs/PLAN.md` 0.2.0 feature 轨「拼音积木难度改造」
> **口径来源** 2026-09-27 产品口径:「游戏需要增加难度,增加关卡。目前没有错误的路径,玩家永远无法答错题」
> **产品已选**(2026-09-27,六轮问答逐条选定):槽位机制不动 / 难度落点在积木盘 / 干扰块做狠(最小对立对)/ 错误次数不失败只封星级 / 每关满星恒 3 颗 / 关末新增错题复习且题干复用本关的图
> **本 spec 标 `待裁` 的五条未获产品裁定**,逐条列在 §8,是本次评审的主要对象(其中 B 与 E 是写 spec 过程中新发现的,产品此前未见过)

## 1. 问题

产品说「玩家永远无法答错题」。读源码实测之后,这句话**比它字面说的还要重** —— 判错的路径不是「很难走到」,是**结构上不可达**。

三条证据,按因果顺序:

1. **`placeBlock` 在块落位之前就把错的挡掉了**。`PinyinBlocksGame.tsx:167`:

   ```ts
   if (!canPlace(block, slot)) { noteMiss(); …; flashReject(slotId); return }
   ```

   `canPlace` 为假 → 块**不写进 `placement`** → 弹回托盘。

2. **`placement` 的唯一写入点就是上面这一句之后的第 178 行**,而托盘里的块在一轮之内身份不变。两条合起来:每个已填的槽**恒**满足 `canPlace`。

3. 于是 `rules.ts:182` 的 `wrongSlotIds(slots, next, tray)` **恒返回 `[]`**,`:188-201` 那一整段 —— 「全填 → `status='wrong'` → 抖 720ms → 撤掉错块」—— **永不执行**。

这段代码不是「很少触发」,是**死代码**:全仓没有任何一条测试覆盖它(`PinyinBlocksGame.test.tsx:596` 的一句注释里提到过它,仅此而已),`git log -S` 显示它从最初的提交 `1e22279` 就在那儿,所以这是**原设计如此**,不是回归。

第四代之后的第二层问题:**点击路径连「选块」这一步都省了**。`rules.ts:173` 的 `autoTargetId` 会替孩子找到那个**能放得进去的**空槽 —— 点托盘上的任何一块,它自己就飞到对的槽里。所以只要一路把托盘点空就能通关,托盘怎么打乱都不影响。

**结论**:今天孩子能犯的错只剩两种 —— 拖着块往不匹配的槽上怼(被弹回),或点到一块无处可落的块(被静默拒掉)。这两种量的是**手滑**,不是**理解**。三颗星的实际含义是「全程没被拒绝过」,而不是「拼对了」。

### 1.1 为什么「加关卡」治不了它

同一天落地的 PLAN 行「拼音课程全表扩充」(7 单元 37 关 → 12 单元 91 关)已经回答了「内容太少」,它当天的裁定④写的是:

> 难度手段 = **每单元末一个复习关**(弱档提示 + 干扰块拉满 + 池天然混入前面单元),**不引新机制**

复习关治的是**题量的分布**,不是「有没有判断」这件事本身 —— 91 关里每一关的胜利条件仍然是「把托盘点空」。题量翻一倍,通过率不变。

**本 spec 取代那条裁定④**。该行其余六条裁定与已交付的 91 关数据不动。

## 2. 本设计要立的那条不变量

> **孩子做错的代价,必须落在「选错了块」上,而不是落在「没放对位置」上。**

这句话决定了后面所有的形态,包括那些看起来别扭的地方:

- 槽位不设难点 —— 因为**位置**不是要教的东西,`canPlace` 是脚手架,拆了它只会让孩子把「拼不出来」误当成「手不稳」。
- 难度全压在**托盘**:托盘里同时摆着 `b` 和 `p`,孩子必须听/认得出区别才选得对。
- 「错」的计数与展示,记的是**点错了哪一块**,不是**放错了哪个槽**。

它同时也划出了本设计的**上限**:在不放开槽位门禁的前提下,**孩子永远拼不出一个错的音节**。他能做的只是「在一堆像的里面挑对」。这是一条**辨认**难度,不是**构造**难度。§8 待裁 B 请产品确认这是否是想要的那件事。

## 3. 设计

### 3.1 最小对立对数据表(`blocks.ts`)

新增一张纯语言学知识表,**不含任何课程/关卡耦合**:

```ts
/**
 * 易混伙伴:同一块在托盘里应该优先拿谁来当干扰块。
 * 只写「像」,不写「教没教」—— 后者由 taughtBlocks 在运行时过滤(见 buildBlocks)。
 */
export const CONFUSABLE: Readonly<Record<BlockType, Readonly<Record<string, readonly string[]>>>> = {
  initial: {
    b: ['p'], p: ['b'],
    d: ['t'], t: ['d'],
    g: ['k'], k: ['g'],
    j: ['q'], q: ['j'],
    zh: ['z', 'ch'], z: ['zh', 'c'], ch: ['c', 'zh'], c: ['ch', 'z'],
    sh: ['s'], s: ['sh'],
    n: ['l'], l: ['n'],
    m: ['n'],
    f: ['h'], h: ['f'],
  },
  medial: { u: ['ü'], ü: ['u'] },
  final: {
    u: ['ü'], ü: ['u'],
    ai: ['ei'], ei: ['ai'],
    ao: ['ou'], ou: ['ao'],
    iu: ['ui'], ui: ['iu'],
    ie: ['üe'], üe: ['ie'],
  },
  // 前/后鼻音只差一个鼻尾,所以「对」记在鼻尾上,而不在韵腹上 —— an/ang 的韵腹是同一个 a。
  nasal: { n: ['ng'], ng: ['n'] },
  // 四声恒全出(见 toneBlocks),声调不需要这张表。
  tone: {},
}
```

三条口径:

1. **表是不对称的**:`b: ['p']` 与 `p: ['b']` 各写一遍。不自动取反 —— 有些对本来就不对称(平翘舌里 `z` 的孩子更常误选 `zh`,反向少),今天虽然写成了对称的,但结构上留着不对称的余地。
2. **表只表达「像」,不表达「教过没有」**。哪些伙伴真的能进托盘由 `taughtBlocks(unit)` 在运行时过滤。于是**难度曲线是课程曲线自动派生的**,不需要第二份数据:u1(单韵母)一个伙伴都没教,关卡难度不变;u2 教齐 b/p/d/t/n/l/m 之后开始出对;u4 进来平翘舌整组;u5 进来复韵母对;u7 进来前后鼻尾。
3. **单韵母 a/o/e/i 与 er 不进表**。它们是入门内容,`u1` 面对的是刚认字母的孩子,那里不该有陷阱。

**实现时须有一条测试**:`CONFUSABLE` 里每一个键与每一个伙伴值,都必须是该 `type` 下真实存在的块值(键 ∈ `INITIALS_ALL` / `MEDIALS` / `FINAL_BASIC ∪ FINAL_COMPOUND` / `NASALS`,`tone` 恒空)。没有这条,表里写错一个字母不会有任何东西红 —— 而它错的方式恰好是**静默变简单**(伙伴查不到 → 池子里没有 → 退回随机干扰块)。

### 3.2 取块策略(`buildBlocks`,只改顺序)

`rules.ts:124-134` 现在给每一类建一个洗好的候选游标,`:143` 用 **`pop()`(取尾部)** 逐个取。所以只要把易混伙伴**放在数组尾部**,它们就会**先**被取走:

```ts
const friends = (CONFUSABLE[type]?.[value] ?? [])   // 对每个 required 块
const others  = taughtList.filter(v => !used.has(v) && !friends.includes(v))
cursors.set(type, [...shuffle(others, rng), ...shuffle(friends.filter(taught), rng)])
```

`cap` **不动**(`level.review ? 5 : level.syl.length > 1 ? 2 : unit <= 1 ? 2 : 3`)。理由:干扰块**总数**是「题面有多挤」,易混对是「挤在里面的块有多像」—— 两个不同的旋钮,这次只拧后者。同时在 `cap` 小于伙伴数时,先取到的是最近的那几个(顺序由 `shuffle` 决定,仍受注入的 `rng` 控制,测试可复现)。

### 3.3 顺带修的现存缺陷:i/u/ü 的双身份把干扰块废掉了

`rules.ts:72`:

```ts
const keyOf = (b: Block): string => `${b.type}:${b.value}`
```

`takenKeys`(`:111`)用它做「干扰块不得与正确块重名」的去重。但 `canPlace`(`:51-59`)对 `i/u/ü` 明确允许**介母 ↔ 韵母互换** —— 也就是说 `medial:u` 与 `final:u` 在孩子手里是**同一块积木**。现在它们被当成两块不同的块,后果有两层:

- **判对判错不一致**:答案是 `guā` 时 `medial:u` 是正确块;一个 `final:u` 干扰块被拖进介母槽,`canPlace` 判**通过** —— 它成了「货真价实的干扰块里唯一能放的」,孩子随手一拖就中。
- **屏幕上是两块一模一样的块**:托盘里并排两块「u」,孩子没有任何线索区分,而其中一块拖到某个槽上是「对」、另一块拖到同一个槽上也是「对」。这是纯粹的噪声。

**修法**:去重改用 family key —— `i/u/ü` 只按值去重,其余仍按「类型 + 值」。

```ts
const familyKey = (b: Block): string => (DUAL_VALUES.has(b.value) ? b.value : keyOf(b))
```

**为什么不能一律按值去重**:`initial:n`(声母 n,读「讷」)与 `nasal:n`(鼻尾 n,读「恩」)值相同,但 `canPlace` 判它们**不通用**,是两个真身份 —— 而它们同时出现在托盘里是**刻意设计**(`PinyinBlocksGame.test.tsx:185` 有一条断言专门钉住「按 `data-type` 认身份,不按字符」)。一律按值去重会把这一对合法干扰块删掉,等于把游戏改简单。

### 3.4 点错块的视觉反馈

`autoPlace`(`PinyinBlocksGame.tsx:227-240`)在块无处可落时:

```ts
else { noteMiss(); onBlock?.('wrong'); playSound?.('wrong') }
```

**只有声音**。静音环境(平板上很常见)里,孩子的体验是「点了它一下,什么都没发生」—— 而 `missCount` 已经在涨了。今天这只是小瑕疵;干扰块变成 `b`/`p` 这种高度相似的对手之后,它会直接变成挫败。

**做法**:托盘块复刻槽位的 `flashReject` 手法 —— 同一个自增序号 `n` 驱动,让**连续点同一块也能重放动画**(只切 class 的话第二次挂上去的类和第一次一样,CSS 动画不会重播)。

- 新增 state `rejectBlock: { id: string; n: number }`,与 `reject` 同构;
- 新增 CSS 类 `.pblock--reject`(抖动 + 短暂红描边,落在 `pinyin-blocks.css`);
- 触发点是 `autoPlace` 的 `else` 分支,以及 `placeBlock` 里块不匹配时**同时**闪块与闪槽(现在是只闪槽)。

**零文本**:不出现任何文字或数字,只有形变与颜色。

### 3.5 星级与「错误次数上限」

产品的两条原话:「不能随便乱点,每道题目要有错误次数上线」「不失败,只封星级,建议在每个关卡后面再新增一个错题复习环节。每个关卡固定是3颗星」。

**现状盘点(这条要说清,否则会做出一个空改动)**:

- `starsFor`(`rules.ts:186-190`)已经是 `0 错 → 3 星 / ≤2 错 → 2 星 / ≥3 错 → 1 星`;
- 「1 星即通关」是写死的铁律(`rules.ts:180-185` 的注释:判定的下限必须是 1,否则星级会变成一道否决题);
- ⇒ **「错误次数上限」其实已经存在,它的值就是 3**,而且任何设在 3 以上的上限都是**无效果的**(第 4 次错不会让星级再降)。

所以按默认口径**不改 `starsFor` 的数值**(要不要收紧见 §8 待裁 A),「上限」这条的兑现方式是把它**显式化**:每关满星恒 3 颗不变,≥3 次错封顶 1 星不变,而**真正的牙长在 §3.6** —— 只要本关错过一次,关末就必须再考一遍。

**`starsFor` 的输入口径要收紧一处**:今天 `missCount` 的三种来源是「放错槽」「点选无槽可落」「全填后判出错块」(后一种已死)。本次**新增一种不计入的来源**(§3.6 复习阶段的判错),`starsFor` 的**取值**不变,但要有一条注释写清「复习的错不进这个数」,否则后来者会把复习的 miss 合并进去,造成「复习没做好 → 主关掉星」的反噬。

### 3.6 关末错题复习

**触发**:本关发生过「点错块」(即 `autoPlace` 走到过 `else` 分支)—— 也就是 §3.4 里闪红的那些块。按 §3.3 修完之后,这些块必然是**干扰块**或**多余的声调块**。

> **不变量(已验)**:答案块永远点不错 —— 它的槽总存在、且此刻总空着,所以 `autoTargetId` 总能给它找到落点。⇒ **「点错的块」永远不是正确块**,复习的候选集天然干净。

**题面**:复用本关的图(产品选定)。这一条同时解决了一个否则无解的障碍 —— `SPEAK_OF.tone` 是**空表**(声调没有可念的音,`blocks.ts:57-58`),所以「听音选块」这种题面对**声调块根本不成立**;而图不依赖发音,声调块也考得了。

**复习范围 —— 空哪些槽**:

1. 取孩子点错过的块的**类型**集合 `T`(去重);
2. 复习槽 = 本关中**类型属于 `T` 的所有槽**(同类型有多槽就全空 —— 双音节两个声母槽都空出来,这时考的是「哪个音节用哪个」,反而更好);
3. 其余槽用正确块**预填**;
4. 每个错块的类型都必然在本关有对应槽 —— 干扰块的类型取自 `requiredBlocks` 的类型,声调块来自 `toneBlocks`,两者都只产出本关真实用到的类型。

**复习托盘**:

- **复习槽的正确块,全部给**(少一块就无解);
- **孩子点错过的那些块**(按 family key 去重,最近的优先);
- 总数上限 4;若正确块本身已经 ≥4,则只再加 **1 块**错块(优先最近点错的那块)—— 这一条是为了保证「复习里一定有正解与错解并排」,而不是退化成把正确操作再做一遍。

**两条必要的边界**:

- 若某个错块的 family key 与某个复习槽的正确块相同,则该错块**不进复习托盘**。否则会出现两块**完全一样**的块(例如 `initial:n` 是正确块、`nasal:n` 是干扰块,而某关的鼻尾槽值恰好是 `n`),孩子只能瞎猜 —— 那不是难度,是坏题。
- 过滤之后**错块为空** ⇒ **不进复习相位**,照旧结算推进。没有错解并排的复习没有考点。

**判定与代价**:

- 复习阶段沿用同一套槽位机制(`canPlace` 门禁、点击自动落位)—— 与主关完全一致,这是产品「不在槽位设置难度」这条裁定的直接后果,复习不例外;
- 因此复习里的「错」表现为**被弹回 + 抖动**,而不是「拼出一个错的音节」;
- **不记 miss、不影响星级、不产星**。关星在进复习**之前**就已经落库了。

**相位与落库顺序(重要)**:

```
拼对 → onSolved(stars, wrongPicks)
     → settleLevel(落库:星级 + 星尘 + 连续天数 + 成就扫描)   ← 星在这里就安全了
     → 有错块? ── 否 ─→ onSettle(result) + celebrate + 推进下一关(今天的路径,一字不动)
                └─ 是 ─→ 复习相位 ──(完成或孩子按「回地图」离开)──→ onSettle(result) + celebrate + 推进
```

- **星先落库**是硬要求:复习中途孩子按「回地图」按钮就走(那个按钮在 `LevelEntry` 的头部,一直可见),此时这一关必须已经记上。今天「拼对 = 立刻记上」,这条不能因为插了复习而退化。
- **`onSettle(result)` 与撒花推迟到复习之后**:`result` 里的成就 / 幸运奖励弹层由 App 渲染,压在复习台上就没法玩了。`settleLevel` 与 `onSettle` 本来就是两件事,这里只是把它们**拆到复习的两侧**。
  > 这正是本行与「奖励层『归属动作』重做」期 2 的**串行红线**所在:期 2 要在同一条路径上插星级揭示与星尘飞行,两批改动落在同几个函数上,禁止并行。
- **连击不参与复习**:复习阶段不上报 `onBlock`,复习做得再好也不进连击,免得「复习」变成刷连击的通道。

**复用哪段代码 —— 不新写平行组件**:给 `PinyinBlocksGame` 加一个可选的 `review` 入参(`{ slotIds, wrongBlocks }`),差异全部收敛在这一个入参上:

| 面 | 主关 | 复习 |
|---|---|---|
| 初始 `placement` | 全空 | `slotIds` 之外的槽用正确块预填 |
| 托盘 | `buildBlocks(level, unit, rng)` | `slotIds` 各槽的正确块 + `wrongBlocks`(见上) |
| `missCount` | 累计,进 `starsFor` | 恒不增 |
| `hint` | `hintFor(unit.id, missCount, level.review)` | `hintFor(unit.id, 0, true)` → 恒弱档 |
| `onBlock` | 上报(连击) | 不上报 |
| 完成回调 | `onSolved(stars, wrongPicks)` | `onReviewDone()` —— **绝不**再触发 `onSolved` |

理由是那份拼装台里 590 行有相当一部分是拖拽命中、点选路由、幽灵块、槽位渲染 —— 抄一遍必然两份实现各自漂移,而复习要的恰恰是**同一套手感**。

**复习从哪进**:`LevelEntry` 多一个相位状态(`'level' | 'review'`)。`PinyinBlocksGame` 已经由 `key={level.id}` 挂载,复习相位换成同一个组件带 `review` 入参即可,不刷新关卡数据。复习完成后 `setLevelIndex(+1)` 或 `onExitToMap()` —— 与今天 `handleSolved` 末尾那两行同源。

## 4. 不变量的汇总

1. 已填槽恒满足 `canPlace` —— **主关与复习都成立**,`wrongSlotIds` 因此继续是死代码(§5)。
2. 答案块永远点不错 ⇒ 复习候选集只含干扰块与多余声调块。
3. 复习托盘里**必有**至少一块错块与全部正解,且**不会**出现两块无法区分的同形块。
4. 关星在复习之前落库;复习无论做得多差,星级不变。
5. 复习不产生星、不进连击、不再触发 `onSolved` —— 不可能递归。
6. 干扰块永远来自**已教过的块**(`taughtBlocks` 过滤),易混对不例外。

## 5. 明确不改

## 8. 待裁(四条,交产品)

### 待裁 A —— `starsFor` 的分档要不要收紧

- **A1(推荐):不动。** 上限即现状 3 次(≥3 错 → 1 星,1 星仍通关)。诚实地说,「错误次数上限」这个需求在这一档下**没有新增任何东西** —— 它今天就是这个值。真正的牙在复习环节(≥1 次错就必须再考一遍)。
- **A2:收紧成 `0 错 → 3 星 / 1~2 错 → 2 星 / ≥3 错 → 1 星` 之外的更严分档**(例如 `1 错 → 2 星 / ≥2 错 → 1 星`)。代价是三星比例明显下降,而三颗星对孩子是可见的目标;在干扰块已经变狠的前提下,可能过头。

### 待裁 B —— 复习阶段要不要放开 `canPlace` 门禁

- **B1(推荐,= 产品已选的「交互一致性」):不放开。** 复习里选错 = 被弹回 + 抖动,必须重选。复习的强度是「**逼他在正解与错解之间再选一次**」,而不是「看他会不会拼出一个错的音节」。
- **B2:只在复习阶段放开**(拼装台接受任何块,填满后由 `wrongSlotIds` 判,错了闪红 + 撤块重试 —— **那样就正好激活了 `PinyinBlocksGame.tsx:188-201` 那段今天从没跑过的代码**)。代价是复习与主关的手感不同,且点击路径的 `autoTargetId` 得在复习里关掉,否则一键落位又把考点绕过去了 —— 那等于在复习里同时推翻了「拖动/点击一致」这条裁定。

**这一条直接定义本设计的性质**:B1 下这是**辨认**难度(在一堆像的里面挑对),B2 下才第一次出现**构造**难度(能拼出错的音节)。如果产品要的是后者,B1 的复习环节价值有限,应该选 B2 并接受它带来的交互不一致。

### 待裁 C —— 增关

产品在开头提到「增加关卡」,但当天已落地的课程扩充行刚把 37 关扩到 91 关,且本 spec 认为那样治的是题量分布。**推荐后置**:先落本设计、在现有 91 关上重估难度分布,再决定加多少、加在哪(否则会同时在改「有没有判断」和「判断多少次」两个变量,无法归因)。若产品坚持扩,建议另起一行,不并入本行。

### 待裁 D —— `wrongSlotIds` / `status='wrong'` 死代码的去留

- **D1(推荐):留着**,并在注释里写明「本设计下不可达,保留是为了标记上限」。
- **D2:删掉**,连同 `rules.ts` 的 `wrongSlotIds` 与它的导出。收益是少一段骗人的代码;代价是若将来选 B2,这段要重写。

### 待裁 E(实现面,可以后定) —— 本行与 0.2.0 的先后

`0.2.0` 轨今天卡在两件事上:`docs/walkthrough.md` 的人眼走查还没跑、远程 D1 迁移的裁定还没下(PLAN 行「远程 D1 迁移」)。本行按本文件开头的「不新开轨」规则落在 0.2.0 轨,但落进来就意味着 **0.2.0 要继续等本行做完**。两条路:

- **E1:先发 0.2.0**(跑完走查、裁定迁移),本行随下一个 minor 发 —— 走查清单不被本行撑大。
- **E2:本行并进 0.2.0**,一次发 —— 孩子少等一轮,但走查清单要在没跑之前再扩一截。

推荐 E1,除非产品认为「不能答错」这个缺陷不该再多活一个版本。
