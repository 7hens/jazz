# 拼音积木「学习路径」设计(Section / Unit / Lesson 三层)

> 本文**取代** `2026-09-28-pinyin-blocks-chapters-design.md` 的**结构部分**(「单元三部分」→「三层学习路径」),
> 也取代 `2026-09-29` 那批「单入口收敛」的导航部分。
> 那两份 spec 里 **门禁语义、常量、`starsFor` 取值、材质与题面视觉** 全部继续有效 —— 本文只改「这一切挂在什么之上」。

## 0. 一句话

课程不再是一张 12 格网格。它变成**一条竖向的蛇形路径**:最上面按教学点分成 **7 个 Section**,每个 Section 里是一个或多个 **Unit**,每个 Unit 拆成若干个 **Lesson**(一个节点 ≈ 3~5 题)。孩子点一个节点 → 走完那一节 → 回路径。原来的「复习部分」降级成**每单元一个独立的「练习」入口**。

## 1. 动机

2026-09-30 产品口径:「重构一下游戏规则,采用类似多邻国的学习路径的方式,分为 Section / Unit / Lesson 的层级来组织。」追问后锁定的痛点只有两条,都在**地图层**:

1. **地图太扁平,看不出阶段** —— 12 个格子平铺在一屏,孩子看不出「我现在在第一大阶段」;
2. **一次看到 12 格有压力** —— 整条课程一次全摊开,后面十格全是锁。

改成路径之后:

- **Section 是可见的大阶段**(7 个),每个段头用**本段新教的积木名片**自表意;
- **节点小、数目多**(46 个),一屏只看得见当前那一段的一小截 —— 这正是多邻国的「一次只看一小段路」;
- **节的粒度变小**(3~5 题),节点成了天然的一次坐下就做得完的单位。

**没有改的**:一题一星、`starsFor` 三档、`1 星即通关`、简单/困难两部分的音节气设计、零可见文字的题面。这些是「规则」,本文说的「重构游戏规则」只落在**课程的层次组织与推进方式**上。

## 2. 结构

```
学习路径(一条竖向蛇形节点路,46 个节点)
└── Section ×7            ← 按教学点分段,段头零文本(本段新教块的积木名片 + 段完成计数)
    └── Unit ×12          ← 一字不动:仍是 UNITS 里那 12 个,仍是 levels 扁平数组
        ├── Lesson ×3~5   ← 新增层。一个节点的题 = 本单元某一部分里连续的 3~5 题
        └── 练习入口 ×1    ← 原「复习部分」降级而来,独立于线性链(§8)
```

## 3. 切分规则

```ts
export const LESSON_MAX = 5

/** 一个单元的全部节,顺序 = easy 各节 → hard 各节。 */
export function lessonsOf(unit: Unit): readonly Lesson[]
```

对 `easyLevelsOf(unit)` 与 `hardLevelsOf(unit)` **各切一次**,互不混:

```
n = 该部分的题数
k = ceil(n / LESSON_MAX)          // 节数
base = floor(n / k), rem = n % k
第 i 节的题数 = base + (i < rem ? 1 : 0)
```

**为什么是均分而不是「每 5 题一刀」**:n = 6 时后者切出 `5 + 1`,末节一道题不成课。均分给的是 `3 + 3`。实测各档:`10→5+5`、`9→5+4`、`8→4+4`、`7→4+3`、`6→3+3`、`5→5`(单节)。⇒ **今天全表每一节恒 3~5 题**。守卫按 `3 ≤ len ≤ LESSON_MAX` 断言;`n < 3` 的将来情形会产出一道不足 3 题的节,那时这条守卫会红 —— 那是**故意留的**,提示「要么合并要么补题」,不许静默放过。

**为什么切分尊重简单/困难的分界**(2026-09-30 产品选定):困难部分「另一批音节 + 门禁只比类型」是一整套设计,节内混难易会让一节课中途突然换规则、换难度。所以**一节恒是纯简单题或纯困难题**。

### 3.1 `Lesson` 是派生视图,不是课程数据

节**不写进 `levels.ts`**。理由是 `levels.ts:76-82` 那条既有教训:`progress-stats` / `achievements` / worker / 存档格式遍历的都是 `unit.levels`,换形状要同时改五处;`easyLevelsOf` / `hardLevelsOf` 两个派生取值函数就是为躲开这件事而生的,`lessonsOf` 走同一条路。

节的身份:

```ts
export type Lesson = {
  /** 形如 'u2#easy-1'。**不是存档键** —— 切分线挪动不碰任何已存的星。 */
  readonly id: string
  readonly unitId: string
  readonly part: 'easy' | 'hard'
  readonly levelIds: readonly string[]
}
```

> **这是本设计唯一一处「派生而非写死」的数据。** 本仓的相反惯例(「块显式写死,不由拼音串反推」)针对的是**内容**(哪个块、哪个音节 —— 反推必错);节的**边界**是纯粹的排版决定,由一条纯函数从题数算出,加一条守卫测试钉住结果(§10)。产品 2026-09-30 选定「按题数重切」而非「手写边界」。

## 4. 数据模型

```ts
/** 新增,显式写死 7 条。段内 unitIds 的顺序即路径顺序。 */
export type Section = {
  readonly id: string
  /** 仅用于家长/试玩者的选择器,游戏内不出现(与 `Unit.name` 同一口径)。 */
  readonly name: string
  readonly unitIds: readonly string[]
}
export const SECTIONS: readonly Section[] = [
  { id: 's1', name: '单韵母',      unitIds: ['u1'] },
  { id: 's2', name: '声母',        unitIds: ['u2', 'u3', 'u4'] },
  { id: 's3', name: '复韵母',      unitIds: ['u5'] },
  { id: 's4', name: '鼻韵母',      unitIds: ['u6', 'u7'] },
  { id: 's5', name: '三拼与 ü',    unitIds: ['u8', 'u9'] },
  { id: 's6', name: '整体认读',    unitIds: ['u10', 'u11'] },
  { id: 's7', name: '双音节词',    unitIds: ['u12'] },
]
```

- `Unit` / `Level` **一字不动**。`Level` 仍是 `{ id, emoji, pinyin, read, syl, stage?, listen? }`。
- `Section` **只有分组,没有新数据** —— 段头要展示的东西全部从段内单元的 `badge` 派生。
- **零迁移、零后端改动**:`LevelStars` 仍是 `Record<string, number>`,键仍是 182 个题 id。

## 5. 解锁与进度

### 5.1 严格逐节线性(2026-09-30 产品选定)

```
nextLessonOf(stars): Lesson | null     // 路径顺序上第一个「未全通」的节;全部通过 ⇒ null
```

- **只有 `nextLessonOf` 那一个节点可进**;它**前面**已通的节点随时可重玩;它**后面**的全是锁。
- 节全通 = `lesson.levelIds` 里**每一题**都 ≥1 星(`every`,1 星即通关 —— 与今天 `partCleared` 同义)。
- 段全通 = 段内每一节全通。
- 全部现算,不落库。

> ⚠ **`isUnitUnlocked` 那条门禁死了**。今天「前一单元简单部分全通 ⇒ 解锁下一单元」在严格线性下被「前一节全通」**蕴含**,再写一遍就是第二套口径、两套必然漂移。所以它连同 `part.ts` 的 `PARTS` / `firstIncompletePart` / `nextPartOf` 一起删(§9)。

### 5.2 地图上的计数

| 位置 | 数什么 | 口径 |
|---|---|---|
| 段头 | 已通节数 / 总节数 | `sectionClearedCount` / `sectionTotal` |
| 单元簇头 | 已通题数 / 总题数 | 沿用今天的 `unitClearedCount` / `unitTotal` |
| 节点 | 无数字 | 只有三态图标 |

节点上**不显示星级**(沿用「题级星位不进地图」的既有裁定 —— 放不下)。

## 6. 地图与导航

`UnitMap.tsx` 退休,新文件 `LearningPath.tsx`(名字必须换:它不再是单元地图)。三层可见结构,**全部零可见文字**:

```
层        画什么                                    零文本手段
──────────────────────────────────────────────────────────────────────
Section   段头一行                                  本段新教块的积木名片行 + 段完成计数
Unit      段内的一簇节,簇头一行                      本单元 badge 名片行 + 单元完成计数
Lesson    圆形节点,蛇形排布                          三态图标,无字
```

- **节点三态**:已通(✓)/ 当前(亮,可点)/ 未解锁(灰 + 锁)。当前节点**恒唯一** = `nextLessonOf`。
- **已通的节点可重玩**(点了重跑那一节,存档只升不降)。
- **段头名片 = 段内各单元 `badge` 的并集**(按 `type:value` 去重,顺序 = 单元顺序)。S2 → `b / a / g / zh`。
- **单单元段不画簇头**(S1 / S3 / S7)—— 簇头与段头是同一套名片,画两遍是纯冗余。**簇头只在段内单元数 > 1 时出现**。
- 46 个节点是长滚动。这是多邻国的形态本身,**不做折叠**(2026-09-30 产品选定「全部展开」)。
- 顶栏(星尘 / 家长入口)原样保留。
- `App.tsx` 的视图状态:`{ map }` | `{ lesson, lessonId }` | `{ practice, unitId }`。
- **节与节之间回路径**,没有自动过场(§9)。

## 7. 节律与结算

- **节内**:一题接一题**自动推进**(沿用今天「拼对 → 自动下一题」的节律),**没有**换节过场。
- **节末**:回路径。今天那 1.2s 的遮罩过场没了(`StageTransition` 整组件删,§9)。
- **落库**:每题结束即落库(`settleLevel` 口径一字不改),累积结果**在节末或退出到路径时交一次账** —— 与今天「部分末交账」是同一条口径,只是交账单位从「部分」变成「节」。
- **撒花一档一次,一节一次**(不是一题一次):沿用今天的判据(这一批里既没出新成就、也没有幸运奖励 ⇒ 撒小档),但**一节只撒一次** —— 逐题撒花会把「拼对了」这件小事淹掉。
- **进节从哪起**:该节第一道未通的题;节内可中断,刷新 / 退出后从同一处接着来(逐题落库保证)。
- **练习**:全程不落库,每题结算整段跳过(不记 miss、不上报连击,§8)。
- **题面的难度壳**仍由 `mode` 决定:`'easy'` / `'hard'` / `'practice'` —— 困难节压暗盘面 + 橙环那套视觉不变,练习走灰盘。`StageBar` 的三格台阶条改成「本节的 n 个题位」(§9)。


## 8. 练习入口(原「复习部分」)

「复习部分」不再是流程的一环,降级成**每个单元一个独立的练习入口**,挂在路径上该单元簇的末尾。

- **解锁**:该单元已解锁即可用,**不参与逐节线性** —— 它不是课,是回炉。
- **题目** = 该单元里**「<3 星」的题**,按 `unit.levels` 顺序,**封顶 5 道**(≈ 一节长度)。
- **每题 = 全槽挖空**,复用现成的 `wholeReviewQuestion`(它已经会从 `taughtBlocks` 配干扰块)。
- **不落库、不记 miss、不上报连击** —— 沿用今天「复习做得再差也不掉星」的裁定。

### 8.1 「由星级反推」的接缝(必须写死)

`MistakePool` 存的是**块**(`mistakes.ts:19`,`readonly Block[]`),而星级只记得**哪道题**错过 —— **推不出「他错的是声母还是韵母」**。所以 2026-09-30 产品裁定:**练习重考错题的整题**(`wholeReviewQuestion` 那条路),不再按类型挖空。连带整个错题池机制死掉(§9)。

> 代价写在明处:练习**不再是「只挖他错的那一类块」**。换来的是零新表、零迁移,且练习的题源能跨设备跨会话活着(星级本来就在库里)。

### 8.2 空池口径(产品裁定,破今日一条旧裁定)

**该单元一道 <3 星的题都没有时,入口不亮。**

今天「复习部分恒存在」那条裁定是为「一个单元的流程必须有个终点」立的 —— 有 `wholeReviewQuestion` 兜底照考第一道整题。练习独立成入口之后,这个理由没了:全 3 星 = 没什么可练的,**伪造一道题是往屏幕上放假话**。

> 这是本设计唯一一处**推翻已发布裁定**的地方,单独标出以便复审时推翻回来。

## 10. 不变量(实现时必须守住)

1. **182 道题的 id 一字不动** —— `content-constants.test.ts:31` 已有守卫(12 单元 / 182 关 / 91+91),它**不许被改弱**。这是「老存档每颗星都落回原题」的全部保障。

## 11. 明确不做

- 不做**地图内联星级**(想法池既有行,独立于本设计)。
- 不做**折叠式段**(「只展开当前段」是落选方案;已选「全部展开」)。
- 不做**练习的错块粒化**(要新表 + 迁移 + worker + 本地副本同步面,本轮范围翻倍)。
- 不改**成就口径**(`collector` 仍「一个单元全三星」、`grand_master` 仍「全通关」,由 `progress-stats` 派生、自动跟随)。
- 不做皮肤 / 动效重做;不碰家长面板;不碰题面材质。
- 不引入「失败」概念(重试用尽仍照常通关,只是星少)。

## 13. 待实测的开放项

- **46 个节点的长滚动**:手机上从 u1 滚到 u12 要滑很久。本设计的裁定是**不做折叠**(产品选定「全部展开」),理由是折叠会让「后面还有什么」变得不可见。**发布前走查时用真手机看一遍**;若确实过长,杠杆是「段内已全通的节点折叠成一条」——单开一行,不在本设计里预支。
- **严格逐节线性的挫败感**:节点粒度小,孩子卡在一节就完全推不动。缓解是「1 星即通关」+「不能失败」本来就守着,且已通的节点可重玩。**若实测孩子反复卡在同一节**:杠杆是「已通节点之后**再**放行一个」,同样是单开一行。
- **练习不落库的「练了不涨星」**:练习做对了不改变星级 ⇒ 题目永远留在自己的池子里,下次练还是这几道。这是沿用既有裁定(「复习做得再差也不掉星」)的直接后果。**若实测觉得别扭**(明明练会了还是 2 星):杠杆是让练习也落库(它是逐题 MAX,只升不降,不会掉星)。**不在本设计里预支。**
- **段头 / 簇头两排名片的视觉冗余**:S2 段头是 `b a g zh`,簇头是 `b a` / `g a` / `zh a` —— 有重复。单单元段已靠「不画簇头」躲开。**多单元段是否仍显挤,只能真机上判。**
- **切分线挪动的连带**:未来给某单元加一道题,该单元的节边界会整体平移(节是派生的)。星的键是题 id,**一颗都不会丢**;但地图上「做到哪一节了」会跳一下。可接受,记在这里。
