# 拼音积木「单元三章」设计(简单章 / 困难章 / 复习章)

> 本文取代 `2026-09-27-pinyin-blocks-difficulty-design.md` 的**结构部分**(「关内三段」→「单元三章」)。
> 那份 spec 里**门禁语义、常量、错题池口径、段标 / 材质 / 过场的视觉**全部继续有效 —— 本文只改「这三段挂在什么之上」。

## 0. 一句话

一关不再自己走「简单 → 困难 → 复习」。现在**一个单元 = 三章**,每章是一个连续的题池:先把本单元所有题在**简单章**里走完,再在**困难章**里用**另一批音节**走一遍(门禁更狠),最后进**复习章**重考本单元错过的块。

## 1. 动机

现在的「关内三段」让孩子在**同一道题**上被连考三次(同一张图、同一个音节),而简单段拼对时已经把答案亮出来并朗读过 —— 于是困难段实际是「照着刚看到的答案按类型塞」。难度没上去,节律还碎(每道题都要吃两次过场)。

改成章之后:

- **困难章换一批音节** ⇒ 孩子确实在考没见过的东西,不能靠背上一段的答案;
- **节的粒度变大** ⇒ 过场只在章与章之间出现(一个单元两次),不再每题都打断;
- **错题池的视野变大** ⇒ 复习章收的是**整个单元**的错,不是一道题的错。

## 2. 结构

```
地图(12 个单元格)
└── 单元(如 u2:声母 b p m f)
    ├── 简单章  —— 本单元全部「简单题」(今天的普通关,复习关的题并入)
    ├── 困难章  —— 本单元全部「困难题」(手写的新音节,简单章没考过)
    └── 复习章  —— 本单元错块重考(不是固定题目,见 §5)
```

题仍是**每道题一个星位**(0~3 星),存档键仍是每道题一个 id(§3.3)。

### 2.2 顺序锁

- **章依次锁**:简单章做完 → 开困难章;困难章做完 → 开复习章。
- **「做完」= 该章全部题都 ≥1 星**(沿用「1 星即通关」,不要求满星)。
- **单元之间的锁放宽**:前一单元**简单章全通**即解锁下一单元。困难章与复习章不参与解锁 —— 孩子不该因为卡在困难章而看不到新单元。这条**取代**今天「前一单元全关通关」的口径(题量翻倍后旧口径会让第二单元起几乎推不动)。
- 已解锁的章**可重复进**(复习章天然要能重进;简单/困难章重进即重刷星,存档只升不降)。

## 3. 数据模型

### 3.1 `Level` 增一个字段、删一个字段

```ts
export type Level = {
  readonly id: string
  readonly emoji: string
  readonly pinyin: string
  readonly read: string
  readonly syl: readonly Syllable[]
  /** 困难题。不写 = 简单题。 */
  readonly stage?: 'hard'
}
```

- **删 `review?: boolean`** —— 它描述的「单元末综合复习关」这一关**不存在了**,它的题并进简单章。读它的地方**穷举如下**,一处都不许留成「永远为假」的死分支:

  | 位置 | 现在拿它做什么 | 章化后 |
  |---|---|---|
  | `rules.ts:167` | 复习关的干扰块 cap 抬到 `5` | 由「当前是复习章」决定 |
  | `blocks.ts:152` `hintFor(unitId, missCount, review)` | 复习关恒弱提示 | 形参语义换成「章的类别」或改传 `chapter` |
  | `PinyinBlocksGame.tsx:192` | 上面那个第三参的**唯一**调用点 | 跟着改 |
  | `levels.test.ts:357-359` | 断言每单元**恰好一个**复习关且在末位 | 改成断言简单章 / 困难章的划分 |
  | `rules.test.ts:228 / 240 / 249-260` | 用 `level.review` 当 cap 与被试的开关 | 改成用章 |

  另有一处**名字像但不相关**:`mistakes.ts` 的 `reviewQuestions(...)` 是复习章的出题函数,**不读 `level.review`**,保留。
- **新增 `stage: 'hard'`** —— 只标困难题,简单题不写(默认即简单)。

### 3.2 数组顺序即推进顺序

`Unit.levels` 保持**扁平单数组**,顺序 = **简单章全部题在前、困难章全部题在后**。派生两个只读视图给 UI 与规则用:

```ts
export function easyLevelsOf(unit: Unit): readonly Level[]   // stage !== 'hard'
export function hardLevelsOf(unit: Unit): readonly Level[]   // stage === 'hard'
```

这样 `progress-stats.ts`(`totalLevelCount` / `completedLevelCount` / `perfectUnitCount`)、`achievements`、后端、存档格式**全部零改动**就能跟上 158 道题 —— 它们遍历的都是 `unit.levels`。

### 3.3 题 id 约定

- 简单章题:**沿用现有 id 一字不改**(`u2-3` 等)⇒ 旧存档的星原样保留,孩子不用重打。
- 困难章题:**拿对应简单题的完整 id 加 `h` 后缀**(`u2-4` → `u2-4h`)。`h` = hard,一眼看出它属于哪一章。

  > **注意:现有 id 不是按单元顺序编的** —— id 记的是「这道题出自哪一课的题组」,和它今天落在哪个单元**无关**。u3 单元里有 `u2-4`,u5 单元里有 `u3-0`~`u3-5` 和 `u6-5`,u12 单元的六道题**全部**是 `u7-*`。所以新 id 只能**照抄对应简单题的 id**,不许自己按位置编序号 —— 编了就是新 key,老存档全断。
- id 仍是**存档键**:与显示顺序解耦,挪题不改 id。

### 3.4 存档

沿用「每 user 一行 + 逐 key 取 `MAX` 只升不降」。**零后端改动、零迁移**:
- 困难章题是新 key,旧存档里没有 ⇒ 取 `MAX` 后自然为「未通」;
- 复习章不落库(沿用今天「存档不存」);
- `LevelStars` 是 `Record<string, number>`,加 79 个 key 不需要 schema 变化。

**唯一要处理的**:被删掉的 12 个旧复习关 id(`u1-52` 等)在**老存档里可能已经有星**。它们不再出现在课程数据里 ⇒ 统计函数遍历 `unit.levels` 时天然忽略它们(死 key 停留在 JSON 里,不影响任何计算)。**不做数据清理**(清理要动后端,收益为零)。

## 4. 三章各自的门禁与托盘

| | 门禁 | 放错时 | 托盘 | 失败路径 |
|---|---|---|---|---|
| **简单章** | `canPlace`(类型 + 值都要对) | 弹回、槽红一下、记 miss;**同一块错 2 次入错题池** | 沿用现有 `cap` 规则 | **没有** |
| **困难章** | `sameTypeOnly`(只比类型,值可以错) | 落地不拦;盘面**填满才判** ⇒ 指出错槽 → 撤块 → 重试 | 每类至少 2 块(现有 `HARD_TRAY_PER_TYPE = 2`) | 有:重试用尽 ⇒ 演示正解、该题记失败,**不阻塞**,失败的块进池 |
| **复习章** | `canPlace`(同简单章) | 只抖,**不记 miss**、**不上报连击** | 该题的正解块 + 每个类型 ≥1 个错解(上限 4) | 没有 |

常量沿用,不重新发明:`WRONG_PICK_THRESHOLD = 2` / `HARD_RETRIES = 2` / `HARD_TRAY_PER_TYPE = 2` / `MAX_REVIEW_QUESTIONS = 3` / `REVIEW_TRAY_CAP = 4`。

### 4.1 星级

每道题各自结算:`starsFor(该题 missCount)` —— `0 错 = 3 星`、`≤2 错 = 2 星`、其余 `1 星`(1 星即通关)。**`starsFor` 的取值一字不动。**

- 简单题:miss 只来自简单章那一次;
- 困难题:miss 只来自困难章那一次(判错一次记一次);
- **落库时机**:该题结束(拼对 / 重试用尽后演示完)即落库,**不等整章走完** ⇒ 中途退出不丢(§7)。

今天那套「简单段 miss + 困难段 miss 相加后落库」的口径**作废** —— 章的边界把两段的 miss 分开了。

## 5. 复习章

- **池的范围 = 本单元**:孩子在**简单章 + 困难章**里点错过的块(两块来源合并进同一个池)。
- **入池门槛**沿用:同一块错 `2` 次(困难章的判错一次算一次)。
- **一次最多 3 道小题**(`MAX_REVIEW_QUESTIONS`),每道小题 = 挖空**一个类型**、复用**那道题自己**的图 + 音节(题面照旧,只是某些槽预填锁死)。
- **池空** ⇒ 照考本单元一道整题(沿用今天的兜底口径)。
- 做完把已考的类移出池;复习章**可重复进**(又攒出错题就能再刷)。
- 复习章**不落库、不记 miss、不上报连击** —— 它做得再差也不影响任何星。

## 6. 地图与导航

今天一个单元格里直接排「每关一颗星」+ `n/6`。题量翻倍后格子里放不下,改成**一行一章**:

```
┌─────────────────────────────┐
│ [b][p][m][f]   ← 单元徽章    │
│ 简单章   ★★★☆☆  5/5  ✔     │   ← 可点
│ 困难章   ★★☆☆☆  3/5        │   ← 可点(做完简单章才开)
│ 复习章   ⭐ 2 道待重考       │   ← 可点(做完困难章才开)
└─────────────────────────────┘
```

- 每行显示该章的**已通题数 / 总题数**(复习章显示「N 道待重考」,池空显示「暂无错题」)。
- 锁着的章:灰掉 + 🔒,点了不响应(沿用 `W-M1` 的判据:不进章、不抖、不响、外观不变)。
- **题级星位不进地图**(放不下),进章之后再看 —— 章内每题仍记 0~3 星,星尘照旧。
- 单元之间的锁沿用今天的视觉(灰掉 + 🔒)。

**导航**:地图 → 点单元格 → 单元内展开(或进单元页)→ 点某一章 → 进该章第一道未通的题 → 章内自动推进 → 章末过场 → 下一章(已解锁时)或回地图。

## 7. 节律与落库

- **章内**:一道接一道**自动推进**(沿用今天「拼对 → 自动下一题」的节律),**没有**换段过场。
- **章间**:章末走过场(复用今天的 1.2s 遮罩 + 台阶条素材),然后进下一章。
- **换章不改题面以外的任何东西**:同一单元三章共用本单元的难度阶梯。
- **落库**:每道题结束即落库(§4.1)。退出到地图 / 刷新 / 切后台都从「该章第一道未通的题」接着来。
- 一个单元一趟 = 简单章 5~9 题 + 困难章 5~9 题 + 复习章 ≤3 ⇒ **13~21 道**。因为是逐题落库、章内可中断,**不强制一口气做完** —— 章末是天然的休息点。

## 8. 视觉(沿用,不重做)

- **台阶条**:三格从「一关的三段」变成「一个单元的三章」,亮格 = 当前章(第 1/2/3 格)。**位置与画法不变**(题面图正上方)。
- **换章过场**:复用今天过场 A / B 的素材(暗遮罩 + 放大的台阶条,约 1.2s);减动效下退化成静态帧。
- **困难章**:盘面压暗 + 橙环、槽实线且类型色恒亮(弱档单元 u9~u12 也必须看得见)。
- **复习章**:灰盘、预填槽锁死、槽恒中档。
- **游戏区零可见文字**不变(唯一例外仍是拼对后答案行亮出的同音汉字)。

## 9. 课程数据:困难章的 79 道新题

### 9.1 选题规则

1. **块全部落在本单元已教范围内**(到该单元为止课程里出现过的块),否则孩子拼不出来。这条由 `taughtBlocks` 的既有护栏测试兜住。
2. **尽量与简单章构成最小对立**:与简单章某道题只差**一个特征**(换声调 / 换送气声母 / 换介母 / 换韵腹),例:简单章考 `bà`(爸),困难章考 `pà`(怕)或 `bá`(拔)。这样困难章难在「辨音」,不是难在「不认识」。
3. **不与简单章重音节**(`pinyin` 不重复);同单元内困难题之间也不重。
4. **一题一张 emoji 图 + 一个同音汉字 `read`**(不是拼音串 —— TTS 拿到拉丁串会逐字母念)。

### 9.2 规模

每单元手写题数 = 该单元的简单章题数(见 §2.1),共 **79 道**。**这是本设计最大的一块工作量**,且每道都要配图与同音汉字 —— 估算时按此计。

## 10. 不变量(实现时必须守住)

1. `starsFor` / `canPlace` / `autoTargetId` 的**判定与取值**一字不改。
2. 关卡数据完整性护栏(每题的块都显式写死、`read` 是汉字、块在已教范围内)**继续有效**,并扩到新题。
3. **每关同一类型的槽 ≤ 3**(复习小题恒有 ≥1 个错解名额)—— 新题也必须满足。
4. 旧存档**只增不改**:简单章 id 不变 ⇒ 老存档的星原样亮着。
5. 后端零改动、零迁移;存档仍「每 user 一行、只升不降」。

## 11. 明确不做

- 不做「同一批音节换题面」的困难章(已改为另一批音节)。
- 不做题级星位的**地图内联展示**(放不下)。
- 不清理由删掉的 12 个旧复习关在**老存档**里留下的死 key。
- 不改 `starsFor` 的三档阈值;不引入「失败」概念(困难章重试用尽仍照常通关,只是星少)。

## 13. 待实测的开放项

- **成就难度漂移**:`collector`(「一个单元全部拿到三颗星」)现在要一个单元 10~18 道题**全三星**,比今天难得多;`grand_master`(「全部关卡通关」)要 158 道。本设计的裁定是**成就判定表达式一字不动**(它由 `progress-stats` 派生,自动跟随新题量),理由是成就本就是隐藏的长线目标,先让孩子玩到再谈数值。**若实测确实过难,单开一行改口径,不在本设计里预支。**
- **困难章的真实难度**:困难题是孩子没见过的音节,且门禁只在填满后才判错 —— 可能错得比预期多(错题池被塞爆 ⇒ 复习章变长)。缓解手段已内置(复习章上限 3 道小题、池空照考整题)。**发布前靠人眼走查判断,不预先加提示。**
