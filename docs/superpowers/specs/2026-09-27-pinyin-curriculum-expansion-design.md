# 拼音课程全表扩充 — 设计

> 目标:`0.2.0` 轨,新能力、兼容新增 → **minor**。
> 上游:[拼音积木取代全游戏](2026-09-21-pinyin-blocks-full-game-design.md) §13.1 登记的四条内容缺口即本 spec 的起点。

## 1. 背景

产品口径(2026-09-27):「游戏太简单了,内容太少了,需要扩充内容,将学习的内容尽可能的覆盖到所有知识点」。

现状 `src/features/pinyin-blocks/levels.ts` = **7 单元 / 37 关**。逐条实测(非眼看)后的覆盖缺口:

| 知识点 | 应有 | 已用 | 缺口 |
|---|---|---|---|
| 声母 | 23 | 18 | `p k q r s` |
| 单韵母 | 6 | 5 | `ü` 从未单独教过 |
| 复韵母 | 8 | 6 有效 | `iu` / `üe` 只借整体认读关露过脸 |
| 特殊韵母 | 1(`er`) | 0 | `er` 在 `FINAL_COMPOUND` 里有定义、有读音,**0 关使用** |
| 前鼻韵母 | 5 | 2 | `in un ün` |
| 后鼻韵母 | 4 | 3 | `ing` |
| 整体认读 | 16 | 7 | `ri zi si yi wu ye yuan yin yun` |
| ü 去点规则 | — | 仅 `yu` / `yue` | `ju qu xu` / `jue que xue` / ü 介母 |
| 三拼 ü 介母 | — | 0 | `juan quan xuan` |

复现命令:

```bash
node -e "const s=require('fs').readFileSync('src/features/pinyin-blocks/levels.ts','utf8');console.log([...new Set([...s.matchAll(/initial: '([^']+)'/g)].map(x=>x[1]))].join(' '))"
```

**「覆盖」在本 spec 中的定义**:该知识点在**全课程至少一关**的 `Level.syl` 里以正确结构出现过(§7.2 有机器判据)。不要求「在某个特定单元里」。这条口径让排布有回旋余地 —— 例如 `yuè`(月)同时是复韵母 `üe` 和整体认读 `yue`,它放在 u5 就同时覆盖两项。

### 2.1 D5 的后果(产品已明示接受)

「全通才解锁」在单元变长后必然造成**解锁倒退**:

> 孩子今天 u1 三关全亮 → u2 解锁。扩表后 u1 变 6 关,i / u / 复习三关未通 → **u2 重新锁上**,连锁下去 u2..u12 全灰。

这是本 spec 中**唯一会让孩子当场察觉的倒退**。已裁定接受:孩子重玩新关即恢复。**代价是:此后的每一次内容扩充都会重演一次** —— 这是「全通解锁」口径的固有性质,不是本 spec 引入的。若某天要做「加内容不倒退」,改 `progress-stats.ts` 的 `isUnitUnlocked` 一处即可。

### 3.1 u1 为什么只有 5 个韵母

**`ü` 不能放在 u1**。汉语拼音方案里 ü 自成音节时写作 `yu`(它本身就是 16 个整体认读之一),`ü` 只在与声母相拼时保留两点、且在 `j q x y` 后去点。**在去点规则讲清楚之前,`ü` 没有独立面目可教** —— 硬塞进 u1 会得到一关「块面写 ü、屏幕显示 yu」而没有任何解释的题面。

故 u1 = `a o e i u` 五个,u 最后;`ü` 首现落在 u9(§3.2)。

> **同一条原则的第二个后果**:`ün` **不能放在 u6(前鼻韵母)**。ü 行韵母里 `ün` 是唯一一个**只与 `j q x y` 相拼**的(`jun qun xun yun`)—— 也就是说 `ün` **在普通话里永远是去点形态**,`qún`(裙)的块面写 `ü`、屏幕显示 `u`,同样是无解释的题面。故 `ün` 一并移入 u9。

### 3.2 u9 = ü 行韵母 · 两点去留

u9 收 **ü 行四个韵母**(ü / üe / ün / üan)加上两点去留两面:

- `j q x y` 之后**去点**(ü 行全部四个韵母都能凑出来:`ju` `xue` `qun` `quan`);
- `n l` 之后**保两点**(`nǚ` `lǜ`)。

| # | 音节 | 结构 | 教学点 |
|---|---|---|---|
| 1 | `jú` 橘 🍊 | `{initial:'j', final:'ü'}` | j + ü → 去点 |
| 2 | `qù` 去 | `{initial:'q', final:'ü'}` | q + ü → 去点 |
| 3 | `xuě` 雪 ❄️ | `{initial:'x', final:'üe'}` | x + üe → 去点 |
| 4 | `qún` 裙 👗 | `{initial:'q', final:'ü', nasal:'n'}` | **前鼻 ün** → 去点(替 u6 兜住 `ün` 的覆盖) |
| 5 | `quān` 圈 ⭕ | `{initial:'q', medial:'ü', final:'a', nasal:'n'}` | **ü 介母** + 去点(三拼) |
| 6 | `nǚ` 女 👧 | `{initial:'n', final:'ü'}` | n + ü → **两点保留** |
| 7 | `lǜ` 绿 🟩 | `{initial:'l', final:'ü'}` | l + ü → **两点保留** |

第 5 关同时兑现 D1 里的「三拼 ü 介母」缺口 —— **不需要单独开一个单元**。第 3–5 关则顺带把 `üe` / `ün` / `üan` 三个 ü 行韵母在同一单元里讲完。

> 注:`ün` 沿用既有的「鼻尾拆块」约定,写作 `{ final: 'ü', nasal: 'n' }`(与 `mén` 写作 `{ final: 'e', nasal: 'n' }` 同形)。**不新增块值** —— `ü` 与 `n` 都已在目录里。

### 3.3 u2–u4 的例字约束(**硬约束,不得留给实现时临场决定**)

u2–u4 在课程最前,此时**只解锁了 a o e i u 五个单韵母**(复韵母要 u5、鼻尾要 u6/u7)。所以这 23 关的例字**只能用「声母 + a/o/e/i/u」**。

这条约束有代价:`c` `s` `r` `k` 等声母在这个约束下找不到特别好的儿童例字。候选(实现时逐个定稿,但**必须落在此约束内**):

```

t tù 兔    n ní 泥    l lí 梨
g gǔ 鼓    k kū 哭    h hǔ 虎    j jī 鸡    q qī 七    x xī 西
zh zhū 猪  ch chē 车  sh shū 书  r rè 热    z zú 足
c cā 擦    s sè 色    y yā 鸭    w wǒ 我
```

> **为什么这条不能松**:干扰块池按「该单元及之前出现过的块」派生(§6)。若 u2–u4 的例字用到了尚未出现的韵母,`levels.test.ts` 的池位守卫会红 —— 而那时改起来要动课程顺序。
>
> **`wáng`(王)不在这批里**:它带鼻尾 `ng`,必须落在 u7(u6 教 `n`、u7 教 `ng`)。

## 6. 块目录、解锁池、复习关

### 6.1 解锁池改为派生(替代 `poolFor`)

**现状**:`blocks.ts:75` 的 `poolFor(type, unit)` 按**单元序号**硬编码阈值 —— `unit >= 1` 给全部声母、`>= 2` 给全部韵母、`>= 3` 给鼻尾、`>= 4` 给介母。

**问题**:12 个单元下这张阈值表会烂成一串 if-else;而且「哪个单元教什么」在 `levels.ts`,「池子给什么」在 `blocks.ts`,**两处各写一份必漂移**。

**改**:池 = **该单元及之前所有单元里出现过的块**。从课程数据派生,零硬编码,语义正好是「只出孩子见过的块」。

```ts
// levels.ts(已持有 UNITS 与 Block 类型,放这里不需要新文件)
/** 到第 unitIndex 单元(含)为止,课程里出现过的全部块(不含声调块)。干扰块的唯一来源。 */
export function taughtBlocks(unitIndex: number): readonly Block[]
```

`blocks.ts` 的 `poolFor` **删除**;`rules.ts:121` 的 `poolFor(type, unit).filter(...)` 换成对 `taughtBlocks(unit)` 的同类筛选。

> **`buildBlocks` 的签名不动** —— 仍是 `buildBlocks(level, unit: number, rng)`,`PinyinBlocksGame.tsx:91` 一处调用点**零改动**。我原先想把 `unit` 换成调用方传池,那是多余的:`unit` 在 `cap` 里仍要用(见 6.2),而且 `rules.ts` 早已按 `unit` 索引取数据,多传一个池只是把同一个数算两遍。

> **副作用(须知悉,非 bug)**:派生池与现阈值表**不同宽** —— 今天 u2 的韵母池是「基础 + 复韵母」全体,派生后 u2 的池只有 u1+u2 出现过的块,反而更窄;到 u5 时池里已含前面全部单元的块,比今天更宽。**现有 37 关的干扰块题面会变**。干扰块本就随机,不构成行为破坏,但 `rules.test.ts` 里钉死具体干扰块的断言要重写。

### 6.2 复习关的派生

```ts

  if (missCount >= 2) return 'strong'   // 救急垫脚石优先于一切
  return review ? 'weak' : (HINT_BY_UNIT[unitId] ?? 'strong')

```

```ts
// rules.ts —— 只动 cap 一行
const cap = level.review ? 5 : level.syl.length > 1 ? 2 : unit <= 1 ? 2 : 3
```

`unit <= 1 ? 2 : 3` 那档**保留**:12 单元下它仍指 u1(单韵母),u1 是孩子第一次看积木盘的地方,干扰块少一点是对的。复习关的 5 覆盖它。

调用点两处跟着改:
- `PinyinBlocksGame.tsx:91` — `buildBlocks(...)` 签名不变,无需改;

## 7. `spell()`:把「显示串」与「结构」对起来

### 7.1 今天有一个真空洞

`Level.pinyin`(屏幕上显示的拼音串)与 `Level.syl`(槽位数据)是**两份手写数据,没有任何东西保证一致**。`pinyin: 'māo'` 配 `syl: [{final:'ao', tone:1}]` 能通过今天的全部 308 条测试 —— 孩子看到的拼音和积木拼出来的可以不是一回事。37 关时是隐患,**91 关手写数据下它会变成必然**。

### 7.2 `spell()` 契约

```ts
// levels.ts(新)
/** 把一个音节拼成带调拼音串。纯函数,不引任何服务。 */
export function spellSyllable(syl: Syllable): string
/** 一关的完整显示串:各音节空格分隔,与 Level.pinyin 同形。 */
export function spell(level: Level): string
```

规则按序:

1. **拼底串** `initial + medial + final + nasal`。
2. **零声母的 y/w 改写**:
   - 韵母以 `i` 起头 → `i` 改 `y`(`ie` → `ye`);`i` 单独 → `yi`
   - 韵母以 `u` 起头 → `u` 改 `w`(`uo` → `wo`);`u` 单独 → `wu`
   - 韵母以 `ü` 起头 → 前加 `y` 且 `ü` 去点(`üe` → `yue`、`üan` → `yuan`、`ün` → `yun`)
3. **ü 去点**:`initial ∈ {j, q, x, y}` 时 `ü` → `u`。
4. **标调位置**(这条本身是知识点,故写进纯函数并有测试):
   - 有 `a` → 标 `a`
   - 无 `a` 而有 `o` / `e` → 标 `o` / `e`
   - 无 `a o e` 且 `i`/`u` 并列 → **标后一个**(`iu` 标 `u`:`niú`;`ui` 标 `i`:`guī`)
   - 单个 `i` / `u` / `ü` → 标自身
5. **带调字符表**:`ā á ǎ à` / `ē é ě è` / `ī í ǐ ì` / `ō ó ǒ ò` / `ū ú ǔ ù` / `ǖ ǘ ǚ ǜ`(ü 带调时两点保留)。

> **两种表示都能拼对**:整体认读既可以写成零声母(`{final:'ü', tone:2}` → `yú`),也可以写成两块(`{initial:'y', final:'ü', weld:true}` → `yú`)。现有 37 关里的 `yú` / `yuè` / `yīng` 是**两块**写法,u11 新增的 `yi` / `wu` / `yuan` 等沿用同一写法(有 `initial`,块面上看得见 `y`/`w`),与 u5 的 `yuè` 一致。**`spell()` 必须两种都能处理** —— 这也是它值得有独立测试的原因。

### 7.3 守卫

```ts
// levels.test.ts
it('每关的 pinyin 与 syl 拼出来的一致', () => {
  for (const e of allLevels) expect(spell(e.level), where(e)).toBe(e.level.pinyin)
})
```

这一条把「91 关 × 手写数据」的一致性变成机器可判。**它同时也守住了标调位置规则** —— `niú` 若被标成 `níu`,`spell` 会产出 `níu` 而 `pinyin` 写 `niú`,当场红。

## 8. ü 的两点飞走

### 8.1 触发

**判据是结构,不是单元**:某个音节里 `initial ∈ {j, q, x, y}` 且韵母以 `ü` 起头时,孩子把 `ü` 拖进槽里即触发:

- 块面上的两点**淡出并向上飘走**(约 300ms),块面由 `ü` 变成 `u`;
- 答案行同时显示去点后的拼写。

**不去点的关(`nǚ` `lǜ`)不触发** —— 同样由结构决定(`initial ∈ {n, l}`)。这条判据与 §7.2 的第 3 条规则**同源**,实现时复用同一个纯函数,不在渲染层再写一遍。

> **它首次出现的地方不是 u9,而是 u5 的 `yuè`**(月,`y` + `üe`)。这没关系 —— 去点本就该在「孩子第一次看见 `y` 和 `ü` 拼在一起」时发生,飞走的动画本身就是那句解释。u9(§3.2)是把它**集中成课**,不是它的首演。全课程会触发它的关:`yuè`(u5)、`jú` `qù` `xuě` `qún` `quān`(u9)、`yú` `yuán` `yún`(u11)。

### 8.2 实现落点

- `BlockChip` 新增一个可选态(如 `dropped`),由拼合判定后置位;
- 两点不是独立元素 —— `ü` 是**一个字符**。做法:块面同时渲染「`ü`」与叠在其上的「`u`」两层,或用一个伪元素画两点。**具体手段留给实现**,但必须满足:
  - 块面尺寸不变(不能因为换字导致块跳动);
  - 尊重 `MotionConfig reducedMotion="user"`(全仓既有约定):减弱动效时**直接显示结果**,不做飞走。

### 8.3 已知边界

动画只在**本关内**本次拼合时播一次。重玩该关会再播(与 `makeRng(round)` 的重玩语义一致,不额外存状态)。

### 9.1 新关的 id 规则

**新关序号一律从 50 起**(`u1-50`、`u2-50`、…、`u12-50`、`u12-51` …)。

理由:旧键全部落在 0–6 段,且**旧键的前缀与它在新课程里的单元号已经脱钩**(例如 `u2-4`(jī)现在住在 u3 里)。若新关沿用「该前缀下下一个空闲序号」,`u2` 的新关就要跳过被 u3/u4 占着的 `u2-4` / `u2-5` 去用 `u2-6`,而 `u3` 的新关又要跳过被 u5 占着的 `u3-0`..`u3-5` —— 规则依赖「别处现在占着什么」,极其脆弱。**50 段一次性把两代键隔开,永不可能相撞。**

id 的格式(`/^u\d+-\d+$/`)不变 → `worker/pinyin-progress.ts` 的 `readStars` 与本仓 `local-store.ts` 的副本校验**都不用改**。全局唯一性由既有的 `levels.test.ts` 守卫兜底。

> 「id 前缀 ≠ 所属单元」在本版起成为**常态**。`levels.ts` 顶部注释要改写这条,别再写「形如 u2-3(单元 id + 建关时的序号)」而不加限定。

## 13. 不做(本 spec 射程外)

- **词语 / 短句扩展**(三音节、词组)—— 会破「每单元音节数一致」的分组渲染前提(D2 里选定的口径不含此项)。
- **复习单元的独立机制**(错题回炉 / 限时 / 听音选块)—— 只做 D4 的复习关。
- **`grand_master` 重触发** —— 见 §10。
- **解锁口径放宽** —— D5 已裁定不改。
- **`spell()` 反向解析**(拼音串 → 结构)—— 数据是手写的,不需要反向。
- **每关星级即时反馈 / 关内星级揭晓** —— 与 PLAN 想法池既有条目同在,不并入本 spec。
