# 需求版本管理规范(词库学习岛)

> **版本**:1.0(2026-09-04,自通用模板裁剪为项目专属;模板原文见 git 历史 `docs/features/feature-management.md`)
> **适用**:单人开发 · 家庭自托管单机 · 需求驱动(无固定双周节奏)
> **事实源分工**:铁律/事实 = `CLAUDE.md`;发布执行 = `/release` skill(`.claude/skills/release/SKILL.md`);详设/计划 = `docs/superpowers/`。**本文件 = 流转与版本映射视图,不重复任何命令**(重复即漂移源)。

## 1. 核心理念

需求管理的本质不是"管住需求",而是**管住自己**。每个新需求都是一次"诱惑";规范目的是在诱惑前保持清醒,聚焦最重要的事。

**核心公式**:版本号变更幅度 = 需求的**影响面**,而非工作量。

**真实用户**:孩子(端上玩家)+ 家长(开关设置/重置)。需求判断一律问这两类人,没有"用户群反馈 ≥2 人"这类多用户标准。

## 2. 生命周期流转(真实目录)

```
一行想法    docs/IDEAS.md                     ← 💡 停车场,先入池不承诺
   │ 值得写一页
一页提案    docs/ideas/<YYYY-MM-DD>-<topic>.md  ← 规范/候选/远期(本文件在此)
   │ 评估通过,立项
立项详设    docs/superpowers/specs/<date>-<topic>-design.md  ← 需求详档唯一位置
   │ 拆任务执行
当前迭代    docs/superpowers/plans/<...>.md + .superpowers/sdd/<...>/  ← 一次一个
   │ 完成 → /release(双闸门)
上线归档    根 CHANGELOG.md                    ← 只追加,不修改
```

等车棚与拒绝 = `CLAUDE.md`「二期 backlog」(确认要做待排期)/「真不做」(非目标,留痕防反复)。超 ~10 条或含拆解时,拆出 `docs/BACKLOG.md`。

## 3. 池与看板职责

### 3.1 `docs/IDEAS.md`(停车场,单文件行级)

- 规则:任何想法先占一行,**禁止直接开工**;不承诺、不限量。新增前瞄一眼,重复则弃旧。
- 已拒绝留痕:`CLAUDE.md`「真不做」即长期拒绝记录;临时否决可写回 IDEAS 待观察。
- 准入(从"一行"升级为提案/立项)满足其一:孩子实际使用受阻 / 家长明确诉求 / 技术债阻塞后续 / 有明确复玩价值。

### 3.2 等车棚 = `CLAUDE.md` 二期 backlog

- 现状条目:绘画题型(题干大图 `promptEmoji` 现仅 Choice 用)、填空题型、复习/错词重练排程、离线可用。
- 真不做(拒绝记录):语音识别、汉字书写笔顺、多孩子档案、家长看板、商店/徽章/宠物/每日挑战、PWA、多人在线。

### 3.3 立项与当前迭代 = superpowers 流

- 详设:`docs/superpowers/specs/`(每 feature 一份 `*-design.md`,含背景/规则/验收,需求详档**唯一位置**,不另建 features 库)。
- 计划与执行:`docs/superpowers/plans/` + `.superpowers/sdd/<feature>/`;当前在跑的 plan 即"发车台",**一次只跑一个**。
- 完成即发版(走 `/release`),无攒版压力。

### 3.4 `CHANGELOG.md`(历史,根目录)

- 发版**前**手写并 commit(preflight 要求);只追加,不改已发布条目;格式 Keep a Changelog。

## 4. 分级与版本映射

### 4.1 估算分级

| 级 | 工作量 | 例 | 处理 |
| :--- | :--- | :--- | :--- |
| S | ≤ 2 小时 | 文案、样式、配置 | 随最近一次发版或直接 commit,不独立版本 |
| M | 1~2 天 | 新题型/新页面/新接口 | 独立迭代,随 **minor** 发布 |
| L | ≥ 3 天 | 改库、重构、新子系统 | **强制拆**为多个独立 spec+commit 分批 |

**50% 边界**:M/L 实际耗时到上限且完成度 < 50% → 收尾滚入下版,本版只发已完成。

### 4.2 版本号决策(与 `CLAUDE.md`「版本语义」同源,不另定)

| 版本 | 触发 | 判别例 |
| :--- | :--- | :--- |
| patch | 修复 Bug / 文案 / 样式 | 修结算并发 bug |
| minor | 向下兼容新能力 | 新增题型、新增表/新字段(带 `DEFAULT` 或可 `NULL`)、新增 API 路由 |
| major | 破坏性变更(1.0.0 起;0.x 阶段不触发) | 删/重命名字段·表·API 路由、改字段类型不可自动转换 |

Major 与工作量无关:花 5 天加大功能(非破坏)→ minor;1 小时删个旧接口 → major。

## 5. 发版与回滚(只指向,不重复)

- 顺序/闸门/回滚/secret 全部见 `/release` skill + `CLAUDE.md`「部署与版本发布」。**本文件不抄任何 wrangler 命令、不建 `docs/RELEASE.md`**。
- 要点(指向性):tag 仅在 部署 + 双闸门(预览冒烟 + 生产读写)通过后;失败绝不 `npm version`;禁 `[env.production]`;禁 Dashboard 手改 env。
- 紧急线上故障:仍走 `/release` 快速路径出 patch,**不折叠生产读写闸门**,绝不 Dashboard 手改/覆盖 secret。
- 迁移:表结构变更 = 新增数字前缀迁移,不改 `0001` 基线;新字段带 `DEFAULT`/可 `NULL`;绝不回滚迁移文件。

## 6. 自检与复盘

**发版前两问**:

1. 这版做完,孩子/家长真的感知到吗?(纯内部优化无感 → 并入下版减少发版)
2. 今天不上线会死人吗?(不会 → 按序走;会 → 快速 patch 仍过闸门)

**发版后三问**(追加至 `docs/IDEAS.md` 复盘节):

- 本版新东西孩子真的玩到了吗?
- backlog 增了几条、拒/删了几条?(拒绝越多 = 越聚焦)
- 最后悔做的是哪个?为什么?(识别冲动模式)

## 7. 速查表

| 情境 | 动作 |
| :--- | :--- |
| 有个新想法 | 加一行 `docs/IDEAS.md`,冷静 |
| 要不要做? | 孩子受阻 / 家长诉求 / 技术债 / 复玩价值 |
| 确认要做 | 写 `docs/superpowers/specs/<date>-design.md` 立项 |
| 怎么执行 | specs → plans → /sdd,一次一个,完成即发 |
| 做一半超时 | 收尾滚下版,只发已完成(50% 规则) |
| 升什么号 | patch(bug)/ minor(新能力)/ major(破坏,1.0.0 起) |
| 发版 | 走 `/release`(命令全在那,不在此查) |
| 紧急线上故障 | /release 快速 patch,闸门不折叠 |
