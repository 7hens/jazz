# 手工走查清单(walkthrough)

> **这是「人眼验收」的唯一清单** —— 本仓没有 headless 浏览器、且**禁止截图**(见 `CLAUDE.md` 红线),所以**布局 / 手势 / 动画 / 持久化**这类只能由人在浏览器里判。
> **单一事实源**:`.claude/skills/release/SKILL.md` 的闸门①**只指向本文件**,不再内嵌条目 —— 两处写一份必漂移。
> **每次发布前必走**;日常改功能按 §D 的规则**在同一个提交里**维护它。

---

## A. 条目写法(四条硬要求,改本文件时逐条对照)

1. **必须是人眼可判定的现象**。「应该没问题」「正常显示」等于没写;要写成「松手落在放不下的槽上 → **该槽红一下**,积木**不回槽也不落位**」。
2. **必须写清前提**:哪台设备、什么宽度、要不要先刷新。**做不到前提的人不算通过,只算「未验」**(见 §D 第 4 条)。
3. **不许依赖截图**:本仓禁止截图/读图检查 UI。判据要能用**看一眼、听一声、点一下**得出。
4. **一条只判一件事**;两件事写两条(这样红了才知道红在哪)。

**代码侧已守、此处只判其人的后果**(别去读断言来推断视觉结果):`src/features/pinyin-blocks/PinyinBlocksGame.tsx` 的拖拽(含 `pointercancel`、二指同按)、结算 260ms 窗口;`src/features/pinyin-blocks/rules.ts` 的槽位/干扰块/星级;`worker/pinyin-progress.ts` 的 MAX 合并。

### 一个单元三章(简单 / 困难 / 复习)

> **本组(`W-T*`)是「单元三章」条目。** 一个单元 = 三章,每章是一个连续的题池:
> 先把本单元所有题在**简单章**里走完,再用**另一批音节**在**困难章**里走一遍,最后进**复习章**重考本单元错过的块。
> 章与章之间有 1.2s 过场,**章内的题与题之间没有过场**。

| # | 前提 | 操作 | 期望 |
|---|---|---|---|
| **W-T1** 台阶条三章形态 | 任意设备,进任一单元的任一章 | 依次走过三章,每次看题面图上方的台阶条(三根竖条并排、**越右越高**) | **简单章亮第 1 格**;**困难章亮第 1 + 2 格**(都橙);**复习章第 1 + 2 格保持橙、第 3 格转灰蓝** —— 第 3 格**不是橙** |
| **W-T2** 台阶条与连击圆点不混 | 任意设备 | 一眼扫过屏幕:题面图上方的台阶条(竖条)与右上角那排连击圆点 | 两组同时在场、**一眼分得开** —— 台阶条是**三根高矮不一的竖条**、连击圆点是**一排等大的小圆点** |
| **W-T3** 章间过场,章内不过场 | 任意设备,进任一单元的简单章 | 走完**一道题**盯住屏幕;再走完**整章**盯住屏幕 | **题与题之间没有遮罩** —— 拼对后约 1.6s 直接换下一道题面;**章末**压一层暗遮罩、屏幕中央出现**放大的台阶条**,约 **1.2s** 后散去进下一章。简单→困难亮到第 2 格(橙),困难→复习亮到第 3 格(**灰蓝**) |

| **W-T6** 困难章每类都有能落位的对手块 | 任意设备,进任一单元的困难章 | 把一块**类型对、值不对**的块拖到它那一类的空槽上;再回同一单元的**简单章**做同一件事。**注意:困难章的托盘块数不一定比简单章多**,别去数块数 | **困难章放得进去**(槽吃下它、块**留在槽里**也不弹回);**简单章同一块被弹回**(该槽红一下、块不落位)。困难章里**每一类槽都至少有一块这样的对手块**;声调那一行照旧四声全出,同样放得进 |
| **W-T7** 困难章判错与重试 | 任意设备,进任一单元的困难章 | 只按**类型**放对、故意让**值**错,把槽填满 | 填满当场判错:**错槽红描边并抖动**;约 **720ms** 后**错块被撤回托盘**、槽空出,可以重放 |
| **W-T8** 困难章重试用尽 | 任意设备,进任一单元的困难章 | 连续三次把值放错、每次都等判错走完 | 前两次判错都**撤块可重试**;第 **3** 次判错后**自动把正解一块块落进槽**(演示),**答案行亮起拼音 + 汉字**并朗读,随后照常**进下一题**、这一单元照常通关 |
| **W-T9** 复习章预填槽锁死 | 任意设备,走到复习章 | 点那些**已经填好**的槽(挖空的那几个之外) | **点不动** —— 不响、不弹回、槽里的块**拿不回来**;只有挖空的那几个槽能操作 |
| **W-T10** 复习章小题进度点 | 任意设备,走到复习章(本单元错过若干块时最多 3 道小题) | 看台阶条第 3 格**正下方**,做完一道小题再看一眼 | 有 **1~3 颗灰蓝小点**、**做完一道亮一颗**;错题池空时只有 **1 颗**(整题重做),同样做完亮起 |
| **W-T11** 复习章不记 miss、不动连击 | 任意设备,走到复习章。**先记下右上角连击圆点亮着几颗** | 复习小题里**故意把块放错**,做完这道小题再**故意把块放对**(两边都试);每次都看一眼右上角连击圆点 | 放错**只抖一下、块弹回**;**放错或放对都不动连击圆点** —— 亮着的颗数**不变**(不点亮、也不清零);这一章做得再差也**不掉星** |
| **W-T12** 章内中途退出,已过的题落库了 | 任意设备,先让简单章走到**第 2 道题**(不要走完) | 点单元页左上 **←** 回地图,**再进同一单元的简单章** | 该章**从第 2 道题接着来**(不是从头);地图上简单章那行的 `n/m` **已经加过第 1 道** —— 星是**逐题落库**的 |
| **W-T13** 托盘两端各走一章 | 任意设备 | 分别走 **u1 的单音节章**与 **`xī guā` 的双音节三拼章**(托盘最小与最大的两头) | 两端都能把三章走完;u1 每道题 **2 个槽**(韵母 + 声调)在三章里都**填得进、盘面不溢出**;`xī guā` 的两组槽在三章里都**分得开、不被压扁** |
| **W-T14** 困难章第一轮是不是在「猜」(**人眼判断**) | 任意设备,进任一单元的困难章(**首推 u5 / u6 / u7 这类带真对手块的单元**) | 盯住困难章的**第一轮** —— 这时的题面是孩子**没见过的音节**,没有「刚亮过的答案」可抄 | 看孩子(或你自己**装作 4~8 岁的孩子**)是不是**只按类型**挑块 —— 那类槽空着就随手拿同类里任意一块塞进去,值的对错根本没过脑子。**记录「是 / 否」**。**若判「是」= 太难或太易**(两种读法都要记):这是**设计问题,不是代码问题** —— 回去改 spec 里困难题的选题规则(§9.1),走一次 spec 修订;**不许**在现场悄悄改代码。这一条 `npm test` 判不了,只有人眼能判 |

### 结算与奖励
| # | 前提 | 操作 | 期望 |
|---|---|---|---|
| **W-S1** 星级口径 | 任意设备 | 在第 1 单元分别以 **0 错 / 1-2 错 / ≥3 错** 各做通**一道题**(简单章点错与**困难章判错**都计入 miss)—— 章内一道接一道**自动**往下走,想看地图就点单元页左上角 **←**(整章走完也会自动进下一章 / 回地图) | 三次都**照常通关** —— **≥3 错也不出现「失败」**(地图上没有失败标记);回地图后**该章那行的 `n/m` 加一**(地图上只有每章那行的一个 `n/m` 计数,不再逐题画星位) |

> **W-S1 的注(为什么期望里没有「0 错 = 3 星」)**:地图上**每道题只有「通了 / 没通」两态**(每章那行只有一个 `n/总数` 计数,不再逐题画星位),**看不出某道题是几星**;题内也没有星级揭晓(T15 勘误:spec §7.4 的「星级揭晓 + 继续按钮」本版未实现)。所以「0 错 = 3 星 / ≤2 错 = 2 星 / 其余 1 星」这条口径**今天没有逐题读数** —— 题内不显示,地图上也只有每章那行的一个 `n/总数`。唯一沾过它的人眼出口是**一次性、间接**的:首次拿三星时隐藏成就 `perfect_level` 的文案(「一关一块不错,拿到三颗星」—— **原样引用成就目录里的文案**,`src/features/achievements/achievements.ts`)**过去**会经成就弹层露出**一次**,说不出是哪一道题;1 星 / 2 星零出口。**本次「特效零文本化」把这一处文案出口也收掉了** —— 成就弹层不再渲染 `perfect_level` 的文案(只剩图标 + `+N ⭐`,说不出是哪一道题、也说不出几星),故这条口径**今天零人眼出口**。**主守卫是 `npm test` 的 `rules.ts` 星级纯逻辑(`starsFor`)**,不属本文件射程。本条目只判人眼能判的那一半:**三档错数都照常通关,不出现「失败」**。缺口登记见本节末「尚未纳入」。
>
> **W-S2 的注(同理)**:「该题**星级**不被降」与 W-S1 同一个原因 —— **没有逐题读数**(地图上每章那行只有一个 `n/总数` 计数,看不出 1–3 星;由 `npm test` 的 `starsFor` + worker MAX 合并守)。本条目只判**星尘数字**那一半。

## D. 维护规则(让这份文件活下来的机制)

1. **谁改功能谁改文档,同一个提交。** 提交里凡触碰**用户可见行为**(样式 / 布局 / 手势 / 动画 / 文案 / 持久化 / 发音),`git diff` 里**必须同时出现本文件**。
2. **触发条件表**:
   | 发生了什么 | 本文件要做什么 |
   |---|---|
   | 新增用户可见功能 | **加条目**(进对应分区;若属最小闭环,进 §B) |
   | 改用户可见行为 | **改条目**(把期望改成新事实 —— 旧的期望**今天就假**了) |
   | 删功能 | **删条目**(留着就是僵尸条目) |
   | 改设备/宽度/前置条件 | **改「前提」列** |
   | 只想「顺手优化几句措辞」 | **不动** —— 本文件不是散文 |
3. **走哪一档(可判定,不靠自觉)**:
   | 时机 | 走多少 |
   |---|---|
   | **每次发布前**(`preview` 冒烟,闸门①) | **§B 核心回归**(11 条) |
   | **合并进 `main` 之前** | **§B + §C 全量** |
   | 日常改动(不发布) | 本次**碰到的那个分区**必走 |
4. **闸门口径**:条目只有三种结果 —— **通过 / 未通过 / 未验**(做不到前提)。**「未验」不能记成「通过」**;`W-C3/W-C4` 缺设备时按此记。**判定人 = 走查的人;发布人负责把结论记下来。**
5. **结论记在哪**:每次发布的走查结果写进根 `CHANGELOG.md` 对应发布条目(复盘三问已在那里),**不写进本文件** —— 本文件只放**当前**该走的清单,历史不进正文(否则会被历史撑爆、条目失焦)。
6. **发布流水线引用**:`.claude/skills/release/SKILL.md` 的闸门① = 「给用户 preview URL + 本文件 §B 的核心回归」;**等用户明确「通过」**;不因 `preview == prod`、时间紧、用户催而跳过。
7. **复审红线**:整支终审 / 复审把「改了用户可见行为却没动本文件」当**一条要报的项** —— 这是本文件不被时间磨掉的唯一保障。

## E. 为什么这些必须人走

`npm test` 跑在 **jsdom** 上:**没有 CSS/布局引擎,没有指针事件序列**,所以
- 「块被 flex 压扁」「格子里那排积木名片溢出」 → **jsdom 里根本不可断言**;
- 「幽灵块跟手」「第二指按下时第一指消失」 → **DOM 结构可断言,视觉后果不可**;
- 「刷新后仍是登录态」 → 涉及真 cookie 与真 worker,**只有真浏览器**。

代码侧能守的部分(结构、类名、变量、MAX 合并)已经在 `npm test` 里,**别在这里重复它们** —— 本文件只放**机器判不了**的那些。
