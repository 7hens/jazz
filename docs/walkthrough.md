# 手工走查清单(walkthrough)

> **这是「人眼验收」的唯一清单** —— 本仓没有 headless 浏览器、且**禁止截图**(见 `CLAUDE.md` 红线),所以**布局 / 手势 / 动画 / 持久化**这类只能由人在浏览器里判。
> **单一事实源**:`.claude/skills/release/SKILL.md` 的闸门①**只指向本文件**,不再内嵌条目 —— 两处写一份必漂移。
> **每次发布前必走**;日常改功能按 §D 的规则**在同一个提交里**维护它。

---

## A. 条目写法(四条硬要求,改本文件时逐条对照)

1. **必须是人眼可判定的现象**。「应该没问题」「正常显示」等于没写;要写成「松手落在放不下的槽上 → **该槽红一下**,积木**不回槽也不落位**」。
2. **必须写清前提**:哪台设备、什么宽度、要不要先刷新。**做不到前提的人不算通过,只算「未验」**(见 §D 第 4 条)。
3. **不许依赖截图**:本仓禁止截图/读图检查 UI。判据要能用**看一眼、听一声、点一下**得出。
4. **一条只判一件事**;两件事写两条(这样红了才知道红在哪)。

**代码侧已守、此处只判其人的后果**(别去读断言来推断视觉结果):`src/features/pinyin-blocks/PinyinBlocksGame.tsx` 的拖拽(含 `pointercancel`、二指同按)、结算 260ms 窗口;`src/features/pinyin-blocks/rules.ts` 的槽位/干扰块/星级;`worker/pinyin-progress.ts` 的 MAX 合并。

> **同上改造 · 第二次(整格可点)**:产品口径「应该是**整个卡片可以点击**,而不是只有下面一小块」。格子的 DOM 从「`<div>` 容器 + 里面一个小 `[data-unit-start]` 按钮」收成**一个 `<button>`** —— 名片行与进度条都降级成按钮里的 `<span>`。**命中区**从「只有底下那条进度条」变成**整格**(含按在积木名片上)。`data-unit-id` / `data-unit-start` / `data-locked` 三件套现在落在**同一个元素**上(不再是父子两层),地图测试与上面几条走查条目都按这个取。锁定态仍是 `if (locked) return` —— 变的是**哪里算点到了**,不是**点到之后做什么**。
>
> 顺带纠正一处旧版的重叠压暗:旧 DOM 里 `<div>` 与内层 `<button>` **各压一次** `opacity-45`(合成 ≈0.20),所以锁定格上那条进度条比名片暗得多。收成一个元素后只剩**一层** 0.45 —— 锁定格的进度条会比改版前**亮一点**。这是预期,不是掉了样式。
>
> **同上改造 · 第三次(Material 3 改版,2026-09-29)**:产品口径「卡片的样式不好看,重新设计,要符合 material-3 风格」。定的三件:**卡片走 M3 的 elevated 变体**、**范围 = 地图整页**、**圆角按 M3 规范档**。落下来的样子:
>
> - **卡片**:填充 `surface-container-low`(#f4f9ff,sky 调)+ 一层 M3 规范 elevation-1 的影,**描边整条删掉**(原来那圈 `border-2 border-hairline` 没了 —— 卡片变宽了 4px,布局预算的算术同步改过);圆角从 32px 收到 **16px**(`rounded-m3-lg`)。
> - **悬停 / 按下 = 状态层**(叠 8% / 12% 的 `ink`,**不换底色**)+ 影在 elevation-1 ↔ 2 之间抬一下。原来那套「悬停换底色 + `active:scale-[0.98]` 缩一下」撤了。
> - **底部那圈胶囊删掉**(口径:「整个卡片都可以点击,就不需要胶囊来表示点击范围了」)。原先试过一版 M3 tonal chip(`primary-container` 底 + `rounded-full`),同一会话内被这条口径推翻 —— 整格可点之后,那一圈底只会读成「只有这一小条能点」,正好跟事实相反。现在底下就是**一行裸内容**:▶/🔒 图标 + `n/m` 数字,无底、无描边、无圆角。
> - **锁定态**(**观感差别最大**的一处,`W-M1` / `W-M3` 要重判):不再是「整格压 `opacity-45`」。改成 M3 的 disabled 口径 —— **撤影**(`shadow-none`)、**图标转灰蓝**(`ink-2`,压卡片面 4.2:1,「不能点」这条形状线索得读得出)、**数字退一档**(`ink-3`),只有**名片行**压到 40%。两态因此差**三条**:有影/无影、橙 ▶ / 灰 🔒、数字深/浅。
> - **可玩的 ▶ 用 `--color-accent-ink`(深橙),不是 `--color-accent`**:后者压浅底只有 **2.2:1**,连图形对象那条 3:1 都不到。这是本次顺带修掉的一处旧对比度问题。
> - **顶栏**:星尘胶囊与家长按钮从「玻璃 + 描边圆」换成 M3 的 **tonal chip / tonal 图标按钮**(`surface-container-low` 实底 + full 圆角 + 状态层)。两个都**不挂影** —— M3 里浮起来的只有卡片,那层影是「这一格可以进去」的信号,洒到顶栏上就把它稀释成装饰了。
> - **徽章空位**:未得那格从「半透明白、直落天空」换成实打实的一档色阶 `surface-container-high`(#dbe9f7)。描边的**分母因此从天空换成色阶** —— `W-V4` 的判据跟着改(见下),`UnitMap.tsx` 里那段对比度算术已按新分母重算(亮 3.6:1 / 暗 5.7:1)。
> - **天空渐变背景保留**:M3 不要求底色中性,而这片天空是游戏的世界本身。卡片与天空只有 1.27:1 的色差,分开靠的是那层影 —— 觉得卡片「飘不起来」时,先看影还在不在,别去加描边。
>
> jsdom 判不出好看与否,只钉得住「这几件还在不在」(圆角 / 色阶填充 / 无描边 / 状态层 / 进度行**没有**胶囊 / 两态的颜色分岔),那是 `UnitMap.test.tsx` 里四条 M3 用例;**影够不够、色阶分不分得开、状态层按下去明不明显,只有本文件这几条人眼条目能判**。

### 一个单元的多节课(简单节 / 困难节 / 练习)

> **本组(`W-T*`)是「单元多节课」条目。** 一个单元 = 一条**节链**(简单节若干 → 困难节若干),外加一个**练习入口**:
> 先把本单元所有题在**简单节**里逐节走完,再用**另一批音节**在**困难节**里走一遍;练习入口重考本单元「<3 星」的题(整题挖空)。
> **读法**:本组写于「地图 12 格 + 单元内三部分」时代,凡「部分」按**节**读、「三部分」按**多条节**读、「台阶条」按**题位条**读、「练习」按**练习入口**读 —— 逐条对应的新条目见上面 **W-C** 组。
> 部分与部分之间有 1.2s 过场,**部分内的题与题之间没有过场**。

### 进度持久化与兜底(浏览器本地副本)

> 进度现在有**两份**:服务端 D1 那份 + 浏览器 `localStorage` 里的兜底副本(键 `jazz.pinyin-progress.v1`)。
> 打开页面时两份**逐题取 max**,谁丢了另一份都能把它捞回来;发现服务端落后会自动补写回去。
> DevTools 路径:Application → Local Storage → 选本站源 → 找 `jazz.pinyin-progress.v1`。

| # | 前提 | 操作 | 期望 |
|---|---|---|---|
| **W-B1** 副本确实在写 | 已登录,**先通掉任意一题** | 刷新页面 → 开 DevTools 看该键 | 键**存在**且是 JSON,`stars` 里能对上刚过的题、`totalStars` 是地图上那个星尘数 |
| **W-B2** 服务端丢数据后自愈 | 同上,**记下地图上各单元入口的 `n/m` 计数** | 删掉服务端那条记录(本地开发:`npx wrangler d1 execute --config wrangler.toml jazz-life-tracker --local --command "DELETE FROM pinyin_progress"`)→ **刷新页面** | 那些入口的 `n/m` **没归零**、星尘**没归零**;**不等任何操作**,几秒内服务端那条记录**自己长回来了**(再查一次表:行存在,`stars` 与屏幕上一致) |

> **W-B2 的注**:本地开发删表前**先确认 `--config wrangler.toml` 在命令里**(红线:漏了它 wrangler 会读构建产物里的 `wrangler.json`,打到生产库上)。
> **已知局限(不是 bug,是记录)**:`localStorage` 是**每台设备一份**。在 A 设备重置后,B 设备上残留的旧副本仍可能在它下次通关时把进度写回来 —— 家长看到的是「重置没生效」,**再点一次即可**。要根治得给重置加一个服务端版本号,本版没做。
> **同样窄的一条**:打开页面时若正好在补写、且家长同时点重置,补写可能落在 DELETE 之后,进度会复活一次;同上,**再点一次**。

## D. 维护规则(让这份文件活下来的机制)

1. **谁改功能谁改文档,同一个提交。** 提交里凡触碰**用户可见行为**(样式 / 布局 / 手势 / 动画 / 文案 / 持久化 / 发音),`git diff` 里**必须同时出现本文件**。
2. **触发条件表**:
   | 发生了什么 | 本文件要做什么 |
   |---|---|
   | 新增用户可见功能 | **加条目**(进对应分区;若属最小闭环,进 §B) |
   | 改用户可见行为 | **改条目**(把期望改成新事实 —— 旧的期望**今天就假**了) |
   | 删功能 | **删条目**(留着就是僵尸条目) |
   | 改设备/宽度/前置条件 | **改「前提」列** |
   | 只想「顺手优化几句措辞」 | **不动** —— 本文件不是散文 |
3. **走哪一档(可判定,不靠自觉)**:
   | 时机 | 走多少 |
   |---|---|
   | **每次发布前**(`preview` 冒烟,闸门①) | **§B 核心回归**(11 条) |
   | **合并进 `main` 之前** | **§B + §C 全量** |
   | 日常改动(不发布) | 本次**碰到的那个分区**必走 |
4. **闸门口径**:条目只有三种结果 —— **通过 / 未通过 / 未验**(做不到前提)。**「未验」不能记成「通过」**;`W-C3/W-C4` 缺设备时按此记。**判定人 = 走查的人;发布人负责把结论记下来。**
5. **结论记在哪**:每次发布的走查结果写进根 `CHANGELOG.md` 对应发布条目(复盘三问已在那里),**不写进本文件** —— 本文件只放**当前**该走的清单,历史不进正文(否则会被历史撑爆、条目失焦)。
6. **发布流水线引用**:`.claude/skills/release/SKILL.md` 的闸门① = 「给用户 preview URL + 本文件 §B 的核心回归」;**等用户明确「通过」**;不因 `preview == prod`、时间紧、用户催而跳过。
7. **复审红线**:整支终审 / 复审把「改了用户可见行为却没动本文件」当**一条要报的项** —— 这是本文件不被时间磨掉的唯一保障。

## E. 为什么这些必须人走

`npm test` 跑在 **jsdom** 上:**没有 CSS/布局引擎,没有指针事件序列**,所以
- 「块被 flex 压扁」「格子里那排积木名片溢出」 → **jsdom 里根本不可断言**;
- 「幽灵块跟手」「第二指按下时第一指消失」 → **DOM 结构可断言,视觉后果不可**;
- 「刷新后仍是登录态」 → 涉及真 cookie 与真 worker,**只有真浏览器**。

代码侧能守的部分(结构、类名、变量、MAX 合并)已经在 `npm test` 里,**别在这里重复它们** —— 本文件只放**机器判不了**的那些。
