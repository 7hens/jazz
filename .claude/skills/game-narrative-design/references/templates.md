# 叙事结构模板骨架(game-narrative-design)

> **结构模板 ≠ 填空处**:台词、选项文本、题量**一律不抄进这里**(见 SKILL「台词权威只存一处」)。
> 台词写法与分镜行的交付格式 = `game-story-writing/references/script-and-craft.md` §三·§四;本文件只给**结构列**的骨架。

## 一、分支树骨架(三幕式)

```text
[起点]
  ├─ 强制节点(必经) ──→ [第一幕末:跨门槛选择]
  ├─ 可选节点(可跳过,不影响主线可达性)
  └─ QTE 节点(时限 / 条件触发)
        ↓
[中点反转]
  ├─ 分支 A ──→ 结局 1(条件:变量 X ≥ 60)
  ├─ 分支 B ──→ 结局 2
  └─ 隐藏分支 ──→ 结局 3(解锁:道具标记 / 前章状态)
```

**线性章(无分支)照此输出**:节点列全填「强制」,差异点列写「无(无兄弟节点)」,末端指向唯一出口;**不为了让表格好看而虚构分支或结局**。闸门第 2、3 项按下方 §六 的线性填法处理。

节点列定义(每个节点一行):

| 列 | 填什么 |
| --- | --- |
| 节点 id | 稳定标识;增删改须留 `removedId → replacementId` 映射(见 SKILL 存档节) |
| 类型 | 强制 / 可选 / QTE |
| 入场条件 | 变量阈值、道具标记、前章状态;无条件则写「恒真」 |
| 差异点 | 与兄弟节点**至少一处**不同:文案 / 状态 / 结局。三处全同 = 伪分支 |
| 去向 | 下一节点 id 列表(≥1)。**去向为空 = 死胡同**,闸门必拦 |

## 二、分镜脚本表(只补结构列)

台词、画面焦点、选项文本照 `game-story-writing/references/script-and-craft.md` §四 写;结构侧**只增这三列**:

| 增补列 | 填什么 |
| --- | --- |
| 分支差异点 | 本行选项与其它选项差在哪(文案 / 状态 / 结局) |
| 状态挂钩 | 读哪些变量、写哪些变量(与状态变量表逐行对账) |
| 演出钩子 | 本行要砸实的一件事(下游 `game-visual-design` 据此排镜头) |

## 三、逐幕演出表骨架(逐幕,设计层)

```text
幕 id | 功能(本幕在结构里干什么) | 舞台/氛围数据 | 玩家交互(点什么、几选、几次机会)
      | 转场(入场/出场承接谁) | 演出钩子(本幕要砸实的一件事)
```

> **逐行 vs 逐幕**:分镜表 = 玩家**说什么**;演出表 = 这一幕**怎么演**。二者都要,别用一份顶两份 —— 只写台词会漏交互与转场,只写演出会不知道说什么。

## 四、状态变量表

| 变量 | 类型 | 初始 | 读写点(哪几幕) | 结局落点 | 玩家可感知 |
| --- | --- | --- | --- | --- | --- |
| 信任 Trust | 连续 0–100 | 0 | S3 读 / S7 写 | 结局 1 阈值 60 | 是(角色态度变化) |
| Has_Scroll | 布尔标记 | false | S5 写 / S9 读 | 结局 3 解锁 | 是(道具在库) |
| 连续答对 | 计数 | 0 | 每屏写 | — | 是(进度条) |

变量宁少勿多;**每行必须有读有写、有结局落点**。空列 = 悬空变量,删掉或补戏,别留作装饰。

## 六、逻辑校验闸门(进视觉前,逐项打勾)

| # | 检查 | 标准 | 不过 = |
| --- | --- | --- | --- |
| 1 | 不可达死胡同 | 每个分支末端都能到某个结局 | 死路 |
| 2 | 伪分支 | 选 A/B 至少一处差异(文案 / 状态 / 结局) | 有选 = 没选 |
| 3 | 结局多样性 | **≥ 3 条截然不同的结局路径可达** | 单线伪装成多线 |
| 4 | 结局覆盖率 | 每个预设结局均可被实际触发(开发末实测) | 死循环 / 摆设结局 |
| 5 | 变量闭环 | 每个变量有读有写有结局落点 | 悬空变量 |
| 6 | 存档兼容 | 新增节点留 `removedId → replacementId`;`schemaVersion` 已升 | 加一章崩老档 |

> **线性章(无分支)的填法**:第 2、3 项**标「不适用」并写明理由**(本章为线性单出口,不存在兄弟节点可比 / 不预设多结局),**不虚构分支或结局来凑格式**;第 1、4 项按唯一出口核对(全链可达 + 实测可触发);第 5、6 项照常适用 —— 线性章反而更容易做到迁移零风险。
> **结局/分支是被设计出来的,不是被表格要求的**:项目不需要多结局时,老实写线性,比造三个殊途同归的假结局强。
