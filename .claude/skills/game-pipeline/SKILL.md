# 全屏漫画式交互游戏全流程(game-pipeline)

## 定位与原则

本技能 = 全链路**执行手册/导航总纲**,把「漫画的翻页悬念 × 游戏的交互选择」从概念推到上线的骨架:串阶段 0→8(含 1b 叙事结构 / 3b 灰盒纵切片两个**先验环**)、5 个质量闸门,回答「先后顺序、谁产出什么、过什么质检、出问题找谁」。**不重复领域技能细节** —— 叙事(创作与结构:故事/角色/对白/伏笔 + 分支/状态/结局校验/存档兼容)进 `game-story-design`,视觉/AI 素材配方进 `game-visual-design`,听觉进 `game-audio-design`;总纲只给流程骨架 + 验收红线 + 风险归属,本身**不拥有任何领域**。

## 技能间交棒约定

本技能只排程;三份领域技能各管一域(叙事 / 视觉 / 听觉)。跨域一律用**显式标记**,不靠散文描述:

- **前置 → `game-xxx`**:本域动工前**必须先消费**对方的产出(如排视觉前,故事侧的外貌锚必须已定稿)。
- **交棒 → `game-xxx`**:本域产出交给对方接手(如创作定稿 → 结构侧排分支)。

判据:同一件事**只在一个域里拥有事实源**,其他域只放指针;交接处写清「交出什么、对方拿什么开始」。中途冒出的新创意 → 回**阶段 0 变更闸门**重锚,不走交棒。

## 全链路阶段速览(主线串行;标注 `[并行]` 可同步)

```text
阶段0 概念锚定(类型/平台/风格锚,变更唯一入口;产出一页定位)
   ↓
阶段1 叙事创作:世界观圣经·角色台账·节拍·分镜脚本·伏笔台账
   ↓ 【闸门】故事层对账(主题可陈述/规则自洽/弧光/伏笔回收/遮名测试)
   ↓ 【闸门】叙事逻辑校验(无死胡同/伪分支;≥3 条结局可达)
阶段1b 叙事结构:分支树 + 逐幕演出表(交互/转场/演出钩子)
   ↓
阶段2 交互:分支树的交互节点细化(强制/可选/QTE)· 节奏控制表 · 状态变量表
   ↓
阶段3 视觉:情绪色盘→全屏构图→UI→材质滤镜  +  [并行] 听觉(闸门见 `game-audio-design`)
   ↓ 产出【素材 prompt 档】+【角色设定表】(锚点块/布景/氛围/符号/3/4 侧视/表情集 = 设计前置定稿)
阶段3b 灰盒排演 → 纵切片:占位图先排全篇验交互与节奏 → 挑 1 幕做成**成品级**(全通道 + 启动/重开/失败恢复/存档)
   ↓ 【闸门】纵切片验收(一幕达成品级且全循环跑通;**未过禁批量产素材**)
阶段4 AI 资产:角色池/场景/4s 循环视频(按纵切片定稿的锚点**批量执行**,非逐幕发明)
   ↓ 【闸门】AI 质检:三无 + 风格一致(畸形/溢色/穿帮/跨图漂移;废片丢弃重绘禁 PS 补)
阶段5 合成与开发:素材校验→分层叠加→脚本/变量挂接→[并行] 性能实测
   ↓ 回填后回归:素材替换完 → 重跑纵切片那一幕
阶段6 测试打磨:自检·节奏实测·结局覆盖率·A/B·**儿童试玩**(读不出提示 / 不懂重试 / 不懂存档)
   ↓
阶段7 发布上线:构建→迁移(先升库后升代码,含**存档版本**)→部署→浏览器冒烟→打 tag→回滚预案
   ↓ 【闸门】冒烟通过才打 tag(失败绝不 version,孤儿 tag = 回滚失锚)
阶段8 运营连载:章节结算页(下回预告钩子)·分支数据回灌剧本·**埋点先过隐私门**
```

## 阶段依赖与派活(该调谁)

| 阶段 | 主产出 | 主责技能 / 参考 |
| --- | --- | --- |
| 0 概念锚定 | 一页定位(类型/平台/风格);后续一切变更先回此步 | 本技能(变更闸门守则) |
| 1 叙事创作 + 闸门 | 前提与主题命题 / 《世界观圣经》《**角色台账**》《节拍表》《分镜脚本》《伏笔台账》《**术语表**》 | `game-story-design`(故事层闸门) |
| 1b 叙事结构 | 《逐幕演出表》(交互/转场/演出钩子)+ 脚本行结构 +《分支树》 | `game-story-design`(结构侧) |
| 2 交互状态 | 分支树的交互节点细化(强制/可选/QTE)· 节奏控制表 · 状态变量表 | `game-story-design`(结构侧) |
| 3 视觉(+听觉并行) | 情绪板/三层构图/UI 组件/材质滤镜;音景与反馈音映射;**《素材 prompt 档》**+**《角色设定表》** | 视觉 → `game-visual-design`;听觉 → `game-audio-design` |
| 3b 灰盒排演 + 纵切片 | 占位图排全篇;1 幕成品级(启动/重开/失败恢复/存档/音频全通道) | 本技能(`references/production-gates.md`) |
| 4 AI 资产 + 闸门 | 角色立绘(含情绪符号/表情差分)/场景/4s 待机循环;过质检 | `game-visual-design`(references/ai-materials.md + 项目的素材 prompt 档) |
| 5 合成开发 | 分层叠加、脚本植入、变量挂接、性能预算;**回填后回归纵切片那一幕** | `game-visual-design`(references/blueprint.md 合成节) |
| 6 测试打磨 | 自检 / 节奏实测回填 / 结局覆盖率 / A/B / **儿童试玩** | 叙事(故事与对白 + 分支与节奏)→ `game-story-design`;视觉 → `game-visual-design`;试玩观察法 → 本技能 `references/production-gates.md` |
| 7 发布上线 | 构建、迁移(先升库后升代码,**含存档版本**)、部署、冒烟、打 tag、回滚预案 | 本技能(项目的发布手册/`release` 技能优先) |
| 8 运营连载 | 章节结算页、下回预告钩子、分支数据回灌(埋点先过隐私门) | 本技能 |

## 变更闸门(阶段 0 纪律)

**任何偏离已锚定方案的临时创意 —— 加新角色、改玩法类型、插功能 —— 一律回「阶段 0 重新锚定」再走全流程,禁止中途直接插入开发后期**(否则破叙事/资产一致性)。

### 重锚影响矩阵(改一条 ≠ 只改一处)

重锚后**必须按表重跑下游**,别只改「看得见的那一处」:

| 变更 | 必重跑 | 常见漏项 |
| --- | --- | --- |
| 加 / 换角色 | 角色台账 → 分镜 → 立绘 prompt → 语音表 → 资产 → 文案 | 忘了语音/注册表与**跨域契约**(常不止美术) |
| 改世界规则 | 圣经 → 所有已写分镜 → 伏笔台账 → 显影计划 | 代价漂移:新规则与旧台词价码打架 |
| 改玩法类型 | 阶段 0 → 阶段 2 交互 → 阶段 5 开发 → 阶段 6 覆盖率 | 旧交互数据未清,出现双套逻辑 |
| 插入新功能 | 阶段 0 → 全流程 | 中途插进开发后期 = 破叙事与资产一致性 |

**跨域红线**:若某变更触及项目的角色 union / 语音 / 数据模型 / 测试域,先走**该项目的立项流程**,勿当单域小事。

### 文本可逆线(先定文本,再产音频)

**文本(台词 / UI 串)可改;音频一旦落地即成不可逆资产** —— 改一句 = 重录一次(真人配音还需原班人马)。故顺序恒为**文本冻结 → 再产音频**。
> 例外:运行时合成(如浏览器 TTS/`SpeechSynthesis`)不落资产,此线**不存在**,可随时改文本。但**预生成音频 / 真人配音 / 本地化**必须等文本冻结之后 —— 提前产 = 白产。

### 回退矩阵(发现问题的回头路)

变更闸门只管**向前**(加需求 → 回阶段 0)。下游发现问题的回头路按下表,**回退成本随阶段递增**:

| 症状 | 回退到 | 已产资产处置 |
| --- | --- | --- |
| 玩法不好玩 / 核心循环不成立 | 阶段 0(重锚类型) | 灰盒弃;成品素材尚未产 = 无损失 |
| 主题漂移 / 戏不成立 | 阶段 1(故事层) | 改分镜;**角色锚点未变则立绘/场景保留** |
| 分支殊途同归 / 死胡同 | 阶段 1b–2(结构) | 改数据与选项,素材不动 |
| 交互节奏拖沓 | 阶段 3b(重跑灰盒) | 只改节奏与转场数据 |
| **角色外貌 / 画风漂移** | 阶段 3(改锚点)→ 阶段 4 重产 | ⚠ **该角色全部素材作废重跑** —— 最贵的回退 |
| 上线后 bug | 阶段 7(`release` 技能) | 回滚到上一 tag;迁移只增不改 |

> 推论:**改锚点是全流程最贵的动作**(一个角色一批素材报废)→ 锚点定稿优先、冻结优先,别拿「先跑几张看看」当探索手段。

## 验收清单(三张表在 `references/checklists.md`)

| 要查 | 内容 |
| --- | --- |
| **六准则硬约束** | 视觉流向 / 出血安全区 / 色彩无障碍 / 文本密度 / AI 一致性 / 性能预算 的数值**上限**(权威细则 = `game-visual-design` 的 `references/blueprint.md` 与 `references/ai-materials.md`) |
| **风险预案** | 12 条常见风险 → 触发 / 缓解 / 归属技能 |
| **里程碑验收** | M0–M6(含 M3.5)的交付物与验收标准 |

> 数值是**上限**不是目标;项目可**加严**(儿童向 → 单句 ≤20 字),加严须写进**项目文档**并由测试守卫。项目声称"已落地"却低于本表 = 违规。

## 落到具体项目

全流程本身无代码绑定。各领域落某个项目舞台 / 数据 / 音频系统时的**接缝、红线、素材回填点** → 归**该项目设计文档**(本仓库 = `docs/design/` 下的四档,入口见 `docs/design/game-visual.md` 指针节),勿写死通用技能内。

- **前置 →** 动工前先读该域技能 + 项目现状;项目 `PLAN` 未立项的改动先回阶段 0(变更闸门)。
- 项目文档与技能冲突时,**项目现状以代码与该项目文档为准**,技能侧只留方法论。
