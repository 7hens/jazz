# 叙事结构模板与校验(填表即产出)

配套 `game-story-design` 主技能**结构侧**。创作侧(世界观/角色/对白/伏笔/命名)见 `script-and-craft.md`。

> **结构模板 ≠ 填空处**:台词、选项文本、题量**一律不抄进这里**。分镜脚本的交付格式(含结构侧增补列) = `script-and-craft.md` §四;本文件只给**结构列**的骨架。
> **线性项目(无分支)** 只走 §一·§二;§三·§四·§六 标「不适用」并写明理由,**禁虚构分支或结局凑格式**。

## 一、逐幕演出表骨架(逐幕,设计层)

回答「这一幕**怎么演**」—— 镜头、转场、交互点、反馈、演出钩子。

```text
幕 id | 功能(本幕在结构里干什么) | 舞台/氛围数据 | 玩家交互(点什么、几选、几次机会)
      | 转场(入场/出场承接谁) | 演出钩子(本幕要砸实的一件事)
```

> **逐行 vs 逐幕**:分镜脚本 = 玩家**说什么**(`script-and-craft.md` §四);演出表 = 这一幕**怎么演**。二者都要,别用一份顶两份。
> 演出钩子是下游 `game-visual-design` 排镜头的依据 —— 每幕必须写出「要砸实的一件事」,空栏 = 欠账。

| --- | --- | --- | --- |

## 三、分支树骨架(三幕式)

```text
[起点]
  ├─ 强制节点(必经) ──→ [第一幕末:跨门槛选择]
  ├─ 可选节点(可跳过,不影响主线可达性)
  └─ QTE 节点(时限 / 条件触发)
        ↓
[中点反转]
  ├─ 分支 A ──→ 结局 1(条件:变量 X ≥ 60)
  ├─ 分支 B ──→ 结局 2
  └─ 隐藏分支 ──→ 结局 3(解锁:道具标记 / 前章状态)
```

**线性章(无分支)照此输出**:节点列全填「强制」,差异点列写「无(无兄弟节点)」,末端指向唯一出口;**不为了让表格好看而虚构分支或结局**。

节点列定义(每个节点一行):

| 列 | 填什么 |
| --- | --- |
| 节点 id | 稳定标识;增删改须留 `removedId → replacementId` 映射(见 §七) |
| 类型 | 强制 / 可选 / QTE |
| 入场条件 | 变量阈值、道具标记、前章状态;无条件则写「恒真」 |
| 差异点 | 与兄弟节点**至少一处**不同:文案 / 状态 / 结局。三处全同 = 伪分支 |
| 去向 | 下一节点 id 列表(≥1)。**去向为空 = 死胡同** |

**解锁规则**决定分支露出(例:信任 > 60 才现隐藏选项);条件必须写在节点上,别靠散文描述。

## 四、状态变量表

| 变量 | 类型 | 初始 | 读写点(哪几幕) | 结局落点 | 玩家可感知 |
| --- | --- | --- | --- | --- | --- |
| 信任 Trust | 连续 0–100 | 0 | S3 读 / S7 写 | 结局 1 阈值 60 | 是(角色态度变化) |
| Has_Scroll | 布尔标记 | false | S5 写 / S9 读 | 结局 3 解锁 | 是(道具在库) |
| 连续答对 | 计数 | 0 | 每屏写 | 结局 2 阈值(连对 ≥10) | 是(进度条) |

三类:全局连续量(信任值)、道具标记(布尔)、计数。

变量宁少勿多;**每行必须有读有写、有结局落点**。空列 = 悬空变量,删掉或补戏,别留作装饰。玩家可感知 = 能看见或感觉到(别设「看不见的进度条」)。

> **线性项目(无结局分支)**:「结局落点」列填「**不适用(线性单出口)**」。刻意**不设**信任值 / 道具 / 解锁类全局变量 —— 没有结局消费它们,加了就是悬空变量。

## 五、逻辑校验闸门(进视觉前,逐项打勾)

| # | 检查 | 标准 | 不过 = |
| --- | --- | --- | --- |
| 1 | 不可达死胡同 | 每个分支末端都能到某个结局 | 死路 |
| 2 | 伪分支 | 选 A/B 至少一处差异(文案 / 状态 / 结局) | 有选 = 没选 |
| 3 | 结局多样性 | **≥ 3 条截然不同的结局路径可达** | 单线伪装成多线 |
| 4 | 结局覆盖率 | 每个预设结局均可被实际触发(开发末实测) | 死循环 / 摆设结局 |
| 5 | 变量闭环 | 每个变量有读有写有结局落点 | 悬空变量 |
| 6 | 存档兼容 | 新增节点留 `removedId → replacementId`;`schemaVersion` 已升 | 加一章崩老档 |

> **线性章(无分支)的填法**:第 2、3 项**标「不适用」并写明理由**(本章为线性单出口,不存在兄弟节点可比 / 不预设多结局),**不虚构分支或结局来凑格式**;第 1、4 项按唯一出口核对(全链可达 + 实测可触发);第 5、6 项照常适用 —— 线性章反而更容易做到迁移零风险。
> **结局/分支是被设计出来的,不是被表格要求的**:项目不需要多结局时,老实写线性,比造三个殊途同归的假结局强。
> **伪分支的判据是「有无差异」,不是「是否都回同一处」**:教育性重试(选错 → 给应答 + 引导 → 回原选项)只要**文案或状态有差异**,就不算伪分支;儿童向「答错不惩罚、引回正轨」是有意设计,别当缺陷「修」掉。

## 七、存档与叙事状态的版本兼容

做连载 = 每次加章都在动别人的存档。叙事状态(分支变量、道具标记、解锁进度)一旦落成存档,就与**内容版本**绑死;旧存档遇到新章节必须能升 —— 不能崩,也不能悄悄重置。

- **存档带 `schemaVersion`(整数)**:长期更新的游戏里最重要的一个字段。存的不是"进度",是"**哪一版规则下的进度**"。
- **读取管线恒为四步**:`读版本 → 逐版迁移 → 校验 → 实例化`。迁移**只增不改、不可重排**,每一版一个 `vN → vN+1` 纯函数并配单测(仓库侧对应:数字前缀迁移 + 只增列)。
- **未知 / 未来版本优雅降级**(返回空而非抛错):玩家回退到旧版本时,宁可提示"存档不兼容",不要崩。
- **内容 ID 迁移**:增删节点/场景时留一份 `removedId → replacementId` 映射;未知 ID **降级为占位并保留原 ID**,别静默丢弃玩家做过的事。**场景 id 静态复用、内容只增不改的项目无需虚构映射** —— 只保 `schemaVersion` 与未知版本优雅降级即可。
- **分层存**:稳定的**核心层**(身份、关键剧情节点、成就)与**逐版内容模块**分开;新章解锁**从旧选择推断**,而非重置进度让玩家重走。
- 写入用**原子替换**(临时文件 + rename):崩溃后只可能是旧存档或新存档,不会是半个。

> 一句话:**内容更新与存档兼容是同一问题的两面。** 只排结构不管存档 = 加一章崩一批老玩家。
