# 故事创作模板与技法(填表即产出)

配套 `game-story-design` 主技能。表格是**工作台**,不是交付格式 —— 交付给下游的是能演出的分镜脚本。

## 〇、写之前先答三问(顺序不可倒)

1. **核心体验**:我想让玩家**感受到**什么?(一个词:守护 / 复仇 / 自由 / 绝境里的希望)
2. **主题问题**:故事在**辩论**什么?(如「为了所爱能否牺牲无辜?」)—— 结局不是胜负,是对这个问题的回答。
3. **情感曲线**:从好奇 → 恐惧 → 愤怒 → 希望 → 失落 → 胜利 → 释然,哪几档?何时到谷底?何时回弹?无谷底 = 无高潮。

> 三问答不出 → **别往下填表**。填出来的是设定集,不是故事。
> 主角要什么(want)= 推情节的外部目标;缺什么(need)= 定结局品质的内部缺口 —— 二者必须不是同一个东西。

## 一、世界观圣经四栏

| 栏 | 写什么 | 自查 |
| --- | --- | --- |
| 一句话世界 | 一句话说清此地何以不同寻常 | 能不能当 logline 的一半 |
| 地理 / 时代 | 只记与冲突相关的空间与年代 | 有没有写了却永不登场的条目(删) |
| 力量 / 秩序体系 | 1 条主规则 + 边界;多规则须各自有代价 | 极限使用会破功吗 |
| 代价与禁忌 | 每次使用付什么;碰禁忌的后果 | 有没有为剧情豁免过代价 |
| 历史(3-5 件) | 只记**影响当下**的事件 | 每件都能在某场戏里被引用吗 |

附一栏 **显影计划**:哪条规则在第几幕、靠谁付代价显形。写完不填这一栏 = 圣经只是自嗨。

## 二、角色一页卡

```text
姓名 / 年龄 / 身份:
欲望 want(外部目标,推情节):
需求 need(内在缺失,定结局品质):
伤口(何时发生了什么):
谎言(因此相信了哪句错话):
弧光三态 · 起点信念 → 破防点 → 终点:
声纹(句长 / 口头禅 / 禁用语 + 至少一句例句):
外貌锚(主色 / 形态 / 剪影记忆点 / 状态变体)   ← 视觉与 AI 立绘的接缝
显影计划(哪一场演出这条设定):
跨章状态(本章末 → 下章入口条件):
与主角的关系(压力 or 镜像):
```

> **影子字段**:每栏都要能填出「演它的那一场」。填不出 → 删掉该栏或补一场戏。空栏 = 欠账。
> 反派与镜像角色必须受**同一套世界规则**约束;若反派能破例,规则就废了。
> **外貌锚只存一处**(项目设计文档);若下游还要 prompt,由视觉侧按锚点合成,别在本卡之外再抄一份。

### 关系图(主要角色 ≥3 时画)

```text
        向导 / 见证
       ╱     │      ╲
   施压者   交接身份   观察者
      ↓       ↓        ↓
   A ←── 互为镜像 ──→ B
      ╲              ╱
       ╲__ 缺席却在场 __╱   ← 未登场但被反复提及者
```

三问:谁对谁**施压**?谁与谁**互为镜像**(同困境不同选择)?谁**缺席却在场**?
镜像关系是关系网的核心 —— 反派做主题命题的**反面**,正反两面都受同一命题约束,网才不是摆设。

### 叙述位(若项目设有旁白/叙述者)

- **职责边界**:叙述 / 过场 / 结果陈述;**不承担**角色对白、玩家指令、情绪高潮。
- **人称纪律**:第三人称,无「我 / 我们」;出现第一人称 = 叙述位破功。
- **视觉权重**:叙述框通常是最弱的一档(小字、无角色名、不占站位)→ 把它当**过场字**用,别当麦克风。
- 有的项目注册了叙述位却从未使用 —— 那多半不是"不需要",而是没人定义它的职责。**给它固定职责**(如:承接幕间、交代结果)比让它闲置强。

### 语域切换(声纹什么时候浓、什么时候淡)

| 语域 | 场合 | 声纹 | 遮名测试 |
| --- | --- | --- | --- |
| 剧情场面 | 开场、抉择、冲突、结算 | **浓**(口头禅、语气词、断句) | 必须过 |
| 功能性台词 | 操作指令、与判分/系统对齐的文本 | **中性** | **豁免** |

> 功能性台词中性是**故意的**:它要与系统文案对齐、读音要干净,加口癖伤清晰度。别当同质化缺陷去"修"。

## 三、节拍表(每屏一行,先写人话再写台词)

### 章节契约(每章必填两栏,缺一不交稿)

| 栏 | 填什么 | 不过 = |
| --- | --- | --- |
| **高潮位** | 哪一幕 / 情绪峰值 / 场面有什么**不可逆改变** | 全程平 = 没有高潮 |
| **笑点位** | 哪一幕 / 机制 / 一句演出描述(可多登几处,**至少 1 处**) | 只有紧张 = 孩子喘不过气 |

> 两栏写进**项目章节契约**(项目设计文档的「章节结构契约」节),别只留在稿子里 —— 只在稿子里 = 下一章重新即兴。跨章**禁撞机制**:章章同一个笑点 = 无效。
> 笑点判据见 §十二;填不出任一栏 = 不交稿,不是「先空着」。

| 屏 | 人话一句(这屏发生了什么) | 开场 → 收场状态 | 新信息(≤1) | 情绪温度 |
| --- | --- | --- | --- | --- |

情绪温度写入后直接对接本技能结构侧 `structure-and-validation.md` §二 节奏控制表,以及 `game-visual-design` 的情绪色盘。

## 四、分镜脚本行(交付格式)

```text
[场景头] 地点 · 时间 · 天气/光线
[画面焦点] 此屏玩家该看哪里(与对白落点一致)
[对白]     角色 · 情绪 · 台词(≤30 中字)
[选项]     2-4 个,各自标明差异点(文案 / 状态 / 结局)
[状态变化] want 推进了什么 · 哪个变量被读/被写
```

**本文件是分镜行的唯一权威格式** —— 结构侧 `structure-and-validation.md` 只给列骨架,不另立一份分镜定义。

> **分镜文档不抄台词**:台词 / 选项文本 / 题量的权威永远是**项目的数据文件**;设计文档只写意图。下表「对白」列在数据文件落地前是设计初稿,**落库后必须删台词留意图** —— 否则造出第二事实源。

结构侧按项目需要**再增补三列**(线性项目只填后两列):

| 增补列 | 填什么 |
| --- | --- |
| 分支差异点 | 本行选项与其它选项差在哪(文案 / 状态 / 结局)。无兄弟节点则写「无」 |
| 状态挂钩 | 读哪些变量、写哪些变量(与状态变量表逐行对账) |
| 演出钩子 | 本行要砸实的一件事(下游 `game-visual-design` 据此排镜头) |

## 五、对白技法(示例为主)

- **动作代替情绪陈述**;禁直陈「我爱你 / 我恨你 / 我很害怕」——换成具体行为与物件。
- **强冲突 → 短句;亲密关系 → 偏题**(越亲近越说废话);信息藏进指责、讨价还价、玩笑里交付。
- **口头禅到关键处变形** —— 一句声纹可同时当伏笔回收点。

### 好坏对照

| ✗ 坏 | ✓ 好 |
| --- | --- |
| 「我不会让你走的,因为我答应过你母亲。」(一次交付两个信息 + 直陈立场) | 甲把钥匙放进她口袋。「外面在下雨。」(行为即立场,原因留给观众) |
| 「这条规则是:每画一次就忘一个名字。」(世界观讲解) | 她画完,回头问同伴:「我们……刚才在等谁?」(规则靠代价显形) |
| 「我现在非常愤怒。」 | 他把杯子放回桌上,**很轻**。「继续说。」 |

## 六、伏笔台账

| 伏笔(物件/台词/细节) | 埋(屏) | 收(屏) | 回收方式(反转 / 兑现 / 代价) |
| --- | --- | --- | --- |

规则:**埋了必收,收前必埋**。第一期开写就登记;定稿前扫一遍,凡「收」为空的行,删伏笔或补回收 —— 空头悬念比没有悬念更伤。

## 七、术语表与命名权威(专名只此一份)

| 专名 | 类型(人名/地名/物名/拟声/口癖) | 权威写法 | 读音注意(TTS/朗读) | 首现(屏) | 禁用别名 |
| --- | --- | --- | --- | --- | --- |

自查:

- **先入表再入稿** —— 表里没有的新名,先登记再写进正文。
- **一词一写法** —— 同一物禁两种叫法;口头禅固定字形,不自作变体。
- **禁同音 / 近形** —— 新名与既有角色声母或字形过近 = 听感分不清身份(儿童向靠听认角色)。
- **朗读可辨** —— 多音字、异读专名要么换字要么标读音,别让 TTS 猜。
- 已有项目文档设了「命名权威」节 → **并入,不另起一份**。

> 术语漂移是最贵的错误:一个专名定错,后续已配、已译、已画的资产全部跟着错。

## 八、冰山配额(硬约束)

- 圣经写 10% → 演出只用 1%。
- 开场 3 屏内**零**历史/体系旁白。
- 每场戏最多交付 1 个新设定,且必须由冲突带出。
- 观众记住的是**代价**,不是名词表 —— 专有名词一屏最多 1 个新词。

## 九、交付前对账顺序

1. 核心体验 + 主题命题各能一句说清?角色有无念出来(念了 = 删)?
2. 玩法机制参与表达主题吗?有无机制在拆主题的台(玩法统一)?
3. 冲突三线至少一条在加码?情感曲线有谷底有回弹?
4. 世界规则过自洽三问?代价有无被豁免?
5. 每屏状态有变?主角终局选择是第 1 幕做不到的吗?
6. 遮名测试过?信息配额超没超?
7. 故事挡不挡玩法(可跳过 / 回顾 / 提示齐否)?
8. 伏笔台账全回收?有无巧合解围?
9. 专名全篇一种写法?(逐条对过术语表)
10. 章节契约高潮位 / 笑点位两栏填了吗?笑点过「消解 + 良性 + 服务性」三问、且**没被解释**?

全部通过 → 接本技能结构侧 `structure-and-validation.md` 排演出表 / 分支 / 状态变量 / 节奏,**并登记评审台账**(SKILL.md「评审台账」;入库,禁 `.tmp`);不过 → 回炉,别进视觉阶段。

## 十、宏观结构选型(脚手架,不是铁律)

先选骨架,再填表 —— 骨架决定情感怎么爬。

| 骨架 | 形状 | 适用 |
| --- | --- | --- |
| 三幕剧 | 建置 → 对抗 → 解决 | 主线明确的多数项目;最通用 |
| 英雄之旅 | 启程 → 启蒙 → 回归 | 成长 / 冒险 / 史诗 |
| 故事圈 | 舒适 → 需求 → 出发 → 寻找 → 找到 → 代价 → 回归 → 改变 | 角色弧光强;章节式 |
| 起承转合 | 起 → 承 → 转 → 合 | 章节 / 任务式,东方叙事 |
| 七点式 | 钩子 → 转折 → 中点 → 危机 → 高潮 → 结局 | 强情节、短篇 |

**批判性采纳**:骨架只保证形状对,不保证动人 —— 选型后必须回填 §〇 的核心体验,答不上就换骨架。
**故事服从骨架 = 倒置**:为凑「中点反转」而反转、为走完英雄之旅而硬塞 12 阶段 → **骨架服从故事**;体量不够就砍骨架,别灌水。

## 十一、叙事通道(别只靠对白)

对白是最贵也最易滥用的通道。同一条信息,先想两条非对白通道:

| 通道 | 例 |
| --- | --- |
| 玩法 / 机制 | 规则本身让玩家体会代价(每次使用必付) |
| 关卡 / 空间 | 场景布置、可达与不可达、动线 |
| UI / 系统反馈 | 进度、状态变化、提示文案 |
| 环境碎片 | 遗留物、可读物、反复出现的细节 |
| 视觉 / 听觉 | 交棒 `game-visual-design` / `game-audio-design` |
| 对白 / 旁白 | **兜底**,最后才用 |

> **硬规矩:能用「玩到」的,别用「说到」。** §八「开场 3 屏零旁白」只是这条的极端形式;机制与故事打架(玩家玩到的与听到的相反)是同一个病。

## 十二、笑点配方(「让人笑一下」不算合格)

**合格笑点 = 铺垫 + 意外 + 消解 + 良性 + 节奏 + 服务性。**

| 要素 | 硬要求 | 缺了 = |
| --- | --- | --- |
| 铺垫 | 一句建立预期,**不提前泄露** | 没有预期 = 突然,不是笑 |
| 意外 | 打破预期(语言 / 行为 / 情境 / 逻辑 / 视觉 / **机制**) | 可预料 = 不响 |
| **消解** | 意外之后**能瞬间想通**(在角色或世界逻辑里说得通) | 只有意外无消解 = 困惑,不是笑 |
| 良性 | 受众感到**安全**:违逆但不冒犯、无真实伤害 | 只有冒犯没有良性 = 尴尬 / 伤害 |
| 节奏 | 铺垫短、转折快、**转折后不解释** | 解释笑话 = 笑点当场死亡 |
| **服务性** | 服务角色 / 主题 / 节奏或玩家体验 | 硬塞段子 = 出戏 |

> **服务性最重要**:笑点不是加在故事外面的糖,是**角色或主题的一层**。答不出「这个笑点替谁干活」→ 删。
> **消解是分水岭**:失谐 → 消解两步都有才响;想不通 = 只是怪。这也是「铺垫在情理之中、反转在意料之外」的由来 —— 两个条件缺一不可。
> **消解要「当场可感知」**:受众必须在**笑点那一拍**就想通 —— 靠之后揭晓、靠台词补充、靠字幕说明都不算。前提常是**画面里已看得见**正确物 / 已知信息已给足(戏剧反讽尤其如此:猜错那一刻,正解须对受众可见)。排笑点前先确认这条通道存在。

### 机制库(选一个用透,别硬凑)

| 机制 | 做法 |
| --- | --- |
| 落差 | 架势 / 预期拉满 → 结果为零(夸张预备 + 什么都没发生) |
| 重复变奏(三翻四抖) | 前两拍立模式,第三拍**加码或反转**,不原样重放 |
| 误会 / 戏剧反讽 | 角色理解错、观众知道真相 —— **受众比角色懂**,天然邀请他说出正确答案 |
| 错位 | 严肃 × 荒诞(角色认真对待荒谬事;一套规则撞进不匹配的情境) |
| 夸张 / 轻描淡写 | 小事放大或大事化小;两者对冲最有效 |
| Callback / running gag | 旧笑点换新形式再现;同一梗**禁原样重放三次以上** |
| 角色驱动 | 笑点长在角色的执念 / 盲点 / 认真上 —— **让角色成为笑话,而不是讲笑话**;别为搞笑让配角降智(降智 = 工具人 + 刻薄) |

> 项目可**自选子集**并写明判据(如儿童向常限「误会 / 重复 / 落差」),但须落进项目设计文档 —— 白名单只在脑子里 = 每章重新吵。
> **子集要撑得住连载**:机制数 < 章数时必然重复。连载项目**逐章登记本机制**(跨章禁撞车),子集不够就**扩库或允许机制组合** —— 别让「章章有笑点」在第三、四章就只剩重放。

### 通道与安全线

- **别只靠台词**:视觉动作 / 机制反馈 / 失败动画 / 系统对玩家行为的意外反应 —— **玩法幽默比台词笑点更耐玩**(玩家每次操作都出新变体)。
- **笑处境,不笑人**:优越是廉价来源,慎用(易滑向刻板印象 / 贬低)。笑点不得挂在**角色缺陷、外貌、口音、笨拙**上;一旦目标受众感到被冒犯或真实伤害,良性消失,笑点失效。**可操作判据:翻该角色一页卡的「伤口」栏 —— 笑点落在伤口上 = 笑人**(把配角写成笑柄 = 工具人的变体)。
- **禁为笑点破世界规则**:「随便乱喊也有反应」= 规则作废。笑点必须**在规则内**成立(错名不生效本身就可以是笑点)。
- **与玩法同向**:笑点机制不得拆玩法 / 教学台 —— 教学目标是辨声调的项目,谐音梗等于教「声调可以混」,笑点当场变**反教具**(比「不好笑」更贵)。
- **禁谐音梗与双关**(识字前 / 外语初学受众接不住);元幽默(调侃机制 / 第四面墙)**节制**,用多了破沉浸。
- **不阻塞玩法**:笑点可跳过、不改判分与重试逻辑,不插在答题判分瞬间(会打断「答对立即放行」的学习节奏)。

### 测试迭代(唯一确认手段)

幽默极主观,**创作者自己觉得好笑不算数**:

- 目标受众实测:笑了吗?在哪笑?礼貌笑还是真笑?有没有困惑 / 尴尬 / 反感 / 跳过?
- 删掉**纸面好笑、实测无反应**的笑点;实测中破坏节奏或沉浸的,同样删。

> **自检三问**:①受众凭什么能懂(答不出 → 删);②转折后是否要靠一句解释(要靠 → 删);③它替谁干活(答不出 → 删)。
