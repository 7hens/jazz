# 故事脚本与世界观构建(game-story-writing)

## 定位与原则

故事 = 一个有代价的选择被反复推到极限。本技能管「**怎么写**」(世界观 / 角色 / 场景 / 对白 / 伏笔 / 命名);**结构侧**(分支树、状态变量、节奏表、结局可达性)在 `game-narrative-design`,视觉演出在 `game-visual-design`,听觉在 `game-audio-design`。

## 创作纪律(速查)

| 领域 | 硬规矩 |
| --- | --- |
| 前提与主题 | 一句 logline = 谁 + 要什么 + 阻力 + 代价;主题命题写成「价值 + 因果」,**角色不得直接念出命题**(念出 = 命题未被戏剧化) |
| 世界规则 | 三条足够:如何运作 / **每次必付的代价**(不可豁免)/ 禁忌;规则用来生成冲突,定价后**禁中途改价**;反派受同一套规则约束 —— 能破例则规则作废 |
| 角色弧光 | 起点信念 → 破防点 → 终点;终局选择必须是第 1 幕做不到的那个;无弧光者降为功能位并**明标** |
| 场景 | 一场戏 = 目标 → 冲突 → 转折;**收场局面必须与开场不同**,否则删;先写「每屏一句人话」→ 再排选项 → **最后**才写台词 |
| 冰山配额 | 圣经写 10%、演出只用 1%;开场 3 屏**零**历史/体系旁白;每场最多 1 个新设定,一屏最多 1 个新专名 —— 观众记住的是**代价**,不是名词表 |
| 对白 | 潜台词:说的是愿意说的,不是真想的;情绪越强句子越短越偏;遮名测试(**功能性台词豁免**) |
| 硬线 | 单气泡 **≤ 30 中字**(含标点);**超线 = 砍句**,缩字只是 UI 保底 |

## 跨域约定(不可自行发明)

- **人称即分工**:叙述 / 过场 / 结果陈述 = **第三人称,无「我 / 我们」**;角色对白 = 第一 / 二人称。混用 = 叙述位形同虚设。
- **语域切换**:角色在剧情场面声纹浓,在**功能性台词**(操作指令、与判分/系统对齐的文本)切**中性腔** —— 这是有意设计(保读音干净与指令清晰),下游**不得当缺陷「修」掉**;遮名测试对功能性台词豁免。
- **外貌锚是跨域契约**:故事侧不写外貌 → 视觉侧与 AI 立绘无依据 → 两域必然漂移。锚点定稿后**只存一处**(项目设计文档),技能与其它文档只放指针,**禁引用不存在的位置**。
- **影子字段**:每字段必须能填出「演它的那一场」。填不出 = 删掉该栏或补一场戏;空栏 = 欠账。
- 配角的存在理由 = 给主角压力或作镜像;镜像角色(同困境、不同选择)胜过堆背景故事。

## 两本台账(缺一不可)

- **伏笔台账**:埋了必收,收前必埋;每笔一行登记埋/收/回收方式。**无回收计划的伏笔 = 空头悬念**,删掉或补回收。
- **术语表(命名权威)**:专名跨章、跨文档只能有一份权威写法。**先入表再入稿**、一词一写法、禁同音近形撞车(儿童靠听认角色)、朗读可辨。项目已有「命名权威」节则**并入,不另起一份**。
  > 术语漂移是最贵的错误:一个专名定错,后续已配、已译、已画的资产全部跟着错。

## 故事层质检闸门(定稿前逐项对账)

| 检查 | 不过 = |
| --- | --- |
| 主题命题可一句说清,且无角色直接念出 | 无主题 / 说教 |
| 世界规则过自洽三问(含反派同规则、极限推演) | 规则漂移,后期打脸 |
| 每场戏开场与收场状态不同 | 注水戏,删 |
| 主角终局选择 = 第 1 幕做不到的选择 | 无弧光 |
| 遮名测试通过(功能性台词豁免) | 对白无区分度 |
| 伏笔台账全部有回收 | 空头悬念 |
| 专名/术语全篇一种写法(对过命名权威表) | 跨章漂移,越往后越贵 |
| 无巧合解围、无天降救兵 | 廉价结局 |

> 完整对账顺序(含信息配额、脚本行格式)见 `references/script-and-craft.md` §九;逐项过了才交 `game-narrative-design` 排分支。

## 反模式(高危,写完自查)

1. **设定倾泻**:开场旁白讲体系/历史 → 让主角为规则付一次代价。
2. **代价漂移**:同一规则前后价码不同(为省剧情放水)。
3. **对白踩点**:「我现在很生气」「因为我们是朋友」 → 换行为 + 潜台词。
4. **工具人配角**:只递道具不挣扎 → 给镜像困境,或并入主角。
5. **漂亮台词优先**:先写台词后想情节 → 顺序倒过来。
6. **巧合解围**:巧合可以**制造**麻烦,不能**解决**麻烦。
7. **把圣经当交付物**:交付物永远是**能演出的脚本**,不是给人读的设定集。
8. **指令与高潮交给叙述位**:叙述框通常视觉最弱(小字/虚线/无角色名)→ **立刻照做的指令**与**情绪高潮**一律留在角色泡,叙述位只承载过场与铺垫。
9. **闭合枚举陷阱**:模板写死几栏 → 填完就以为完成,把**没列出来**的(外貌锚、显影计划、跨章状态)全挡在门外。**模板越整齐干净,漏得越多** —— 用影子字段原则逼每栏都有演出落点;某栏长期没人填 = 删栏或补戏,别留作装饰。
10. **专名即兴**:写到手边随手造名、或同一物换着叫 → 跨章漂移,改名成本随章数/配音/翻译/立绘次第翻倍。先入表再入稿。

## 落到具体项目

本技能只含**通用创作方法**。故事要落进某项目的场景 / 章节数据字段,或接续该项目既有世界观时,**接缝、命名、既有角色与红线以该项目设计文档为准**;勿在技能里写死某项目现状。

- **交棒 →** `game-narrative-design`:创作定稿后,分支树 / 状态变量 / 节奏表归结构侧。
- **交棒 →** `game-visual-design`:外貌锚定稿后**只存一处**(项目设计文档),视觉侧按锚点合成 prompt,勿再抄一份。
- 本仓库(词库学习岛·千字谷):世界观圣经 / 角色台账 / 伏笔台账 → `docs/design/game-story-bible.md`;故事层分幕落点 → `docs/design/game-direction.md`。
- 也勿在一个项目里虚构与其设定冲突的新体系;新体系先入该项目 `PLAN` 想法池立项。
