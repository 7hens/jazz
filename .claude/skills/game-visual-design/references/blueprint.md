# 视觉设计蓝图(设计流程 + UI 组件规范)

来源:全屏漫画式网页游戏视觉设计工作指南(会话贴入)。本文件 = 设计方法论参考;仓库落地映射与红线见主 SKILL.md「仓库接缝映射」。

## 一、设计理念与目标

- 核心定位:无传统分格(无格线束缚)、全屏沉浸的漫画交互游戏;本质 = 「动态画册 / 交互式电影」的视觉传达。
- 设计原则:
  1. **材质感**:模拟纸张、印刷网点、胶片等物理质感,消除纯数字化生硬感。
  2. **叙事层级**:靠布局、色彩、景深建立清晰视觉阅读动线,引导视线。
  3. **动静对比**:静态画面嵌入微动效设计蓝图,让静止的漫画「呼吸」。
- 协作定位:AI = 首席画师(角色立绘/场景/动态片段);设计师专注视觉统合、构图框定、UI 质感打磨。

## 二、视觉设计流程(6 阶段)

Figma/PS 人工流程;Claude 出蓝图稿/规范给设计参照。

### 阶段一:概念确立与情绪板
- 提 3-4 个核心视觉感受关键词(例:赛博朋克+潮湿+高反差+旧漫画网点)。
- **色彩系统(情感色盘)**:定义「情绪 → 色彩」映射。例:平和对话→青蓝;战斗爆发→橙红。⚠ 抽象色盘是设计意图,**落地须转译**成目标项目现成的情绪载体(token / 边框色 / 氛围渐变 / 场景数据字段),勿照搬直译或绕过既有 token 引入孤例色。
- **情感色边界**:红/橙系只表战斗/危险/愤怒;蓝/青灰系只表回忆/对话/平静;**温情对话禁高饱和刺眼荧光绿/荧光底**(生理性抗拒)。情绪色上氛围/边框/点缀,勿铺满背景压字。
- **文字对比(WCAG AA)**:对白 vs 背景(含气泡)对比 **≥ 4.5:1**,设计稿用 Stark 类工具实测、勿肉眼估。氛围/网点若压字,先降背景再叠字,白字才有保底清晰。
- **UI 材质规范**:明确交互元件设计语言(硬边光效 / 手绘铅笔 / 仿旧纸纹)。

### 阶段二:静态画布构图(布局蓝图)
三层固定图层:
- **背景层(100% 面积)**:AI 场景填充区;边缘叠暗角渐变遮罩防过亮抢镜。文字/按钮落点区背景**明度 < 40%**;AI 背景过亮 → 叠半透明黑遮罩,保白字百分百清晰。
- **角色层(居中/偏侧)**:AI 角色活动安全区(Safe Zone),不遮文字。
- **前景交互层(底部/两侧)**:对话框、选项按钮、进度提示。
- **视线流向(Z/F 型)**:无分格 → 玩家视线须 **0.5s 内**自然流向 角色→对话→选项。角色视线须指向对白落点(对话框在右下 → 角色看右),隐型对角线一断即视觉流断裂。
- **出血/安全区铁律**:屏幕**自底向上 25%** 与**两侧内缩 10%** 为不可侵犯区 —— 永不放角色关键部位(吻部/武器尖)与交互按钮(适配手机/PC/Pad)。仅 **拟声词 SFX 与角色尾/发** 可破格出血,且溢出段不得含关键信息;其余区域留白当视觉休息。

### 阶段三:核心 UI 组件精细化
- **对话框(3 变体)**:普通对白=圆形柔边气泡;内心独白=虚线锯齿边框;怒吼/旁白=尖锐多边形气泡。规范气泡尾(Tail)指向规则(须指向屏幕左/右 1/3 处)。
- **对白密度(二八定律)**:画面是主角非小说;单气泡 ≤ **30 中字**(英 10-12 词),超 = 挡角色 + 阅读快过画面切换(赶鸭子疲劳)。字数接近上限时 UI 层可触发**字体自动缩 ~2pt(shrink-to-fit)作保底** —— 仅保底,不豁免硬线(超线 = 砍句,不是缩字)。
- **字体层级(Type Ramp,6 级)**:H1 拟声词主字 → H2 角色名 → Body 对白 → Caption 旁白 → Button 选项 → Label 小提示;明确每级字体/字号/字距/颜色。H1 拟声词须**图形化素材**(禁系统字体),单图面积 ≤ 画面 **15%**(防「大字报」)。
- **选项按钮(3 状态)**:默认 Dormant / 悬停聚焦 Active(毛玻璃/发光描边)/ 点击 Pressed(内阴影)。**hover 时长 ≤ 0.2s 且须快于角色待机动效** —— UI 动效不得抢角色戏。

### 阶段四:AI 生成介入的「构图适配」设计
- **留白蒙版(Masking Guide)**:画布上叠半透明红色区域,标注 AI 背景图此区须保持纯色或模糊,保证文字叠加清晰。
- **角色站位卡(Pose Template)**:3-4 种固定构图模板(左侧特写/右侧中景/中央全身),AI 严格按比例生成,保证 UI 框线对齐角色视线方向。
- **九宫格安全锚点**:标《角色九宫格安全锚点》—— 以**肚脐为纵向中心、鼻尖为横向基准** → 所有 AI 图/分镜统一对齐(配站位卡用),防换图/换情绪时角色飘移。

### 阶段五:材质覆盖与特效蓝图
- **顶层滤镜**:全屏 3%-5% 透明 Ben-Day Dots 网点纸纹理 + 轻微 Grain 噪点,统一素材质感为「印刷漫画」。
- **转场动态分镜设计**:关键帧蓝图(如白色「擦除线」擦过),标注运动方向/耗时,作动画设计依据。

### 阶段六:设计规范与资产包整理
- UI 组件全部转 Figma/PS 可复用 Master Component。
- 3 页高保真验证稿(开场/平静对话/高潮战斗),查文字可读性与画面层次。
- 标出血线(Bleed)与安全边距(Padding):屏幕边缘向内 20px 不放置交互按钮。

## 三、AI 素材合成落地工作流(配图)

1. **取景框蒙版**:UI 稿角色层拉参考线,拖 AI 绿幕图,自动抠图去绿幕。
2. **缩放与位置校准**:等比缩放,**脚底**恰好落在 UI 底部文字框上方,**头顶**不超过顶部进度条装饰。提示词预留的绿幕边距当缩放调节手柄。
3. **视频非破坏叠加**:绿幕溢色 → AE/PS 去饱和度+色相偏移压绿缘;视频层上叠 3% 透明噪点/网点纹理,把 AI 视频「塑料感」转「老动画/漫画动态质感」。
4. **性能与交付预算**:首屏总包 ≤ **3MB**(流式视频不计);AI 视频 **H.265 压缩 + 渐进式加载**(先显首帧静态图再播流),勿整片拖包。目标项目包体/引擎红线 → 该项目文档为准。

## 四、落到具体项目

蓝图是通用方法论;把它映射到某项目的舞台/角色/UI 组件接缝,是**项目文档的职责**(随代码演进独立维护),勿写死在通用技能里。落地前:对账该项目现状(勿重建已落地物)→ 按项目立项/设计流程走 → 只动视觉壳与数据可选字段,勿碰引擎/语音/判分边界。本仓库(千字谷)的现状接缝表与红线 → 项目技能指向的 `docs/design/game-visual.md`。
